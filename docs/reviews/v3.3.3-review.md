**판정: APPROVE_WITH_CONDITIONS**

**다만 P1 이슈 2건이 발견**:
1. `settings.ts:105` — `dg:interests:changed` listener가 설정 탭 재진입마다 `document`에 누적됨 (listener leak + 이전 `container` DOM 참조 유지).

## 3. P1 (이번 사이클 또는 직후 hotfix)

### P1-1. `dg:interests:changed` 리스너 누수 (메모리/기능 양측 영향)

**파일**: `src/ui/tabs/settings.ts:103-107`
```ts
function bindInterestsHandlers(container: HTMLElement): void {
  // ...
  document.addEventListener('dg:interests:changed', () => {
    renderCurrentInterests(container);
  });
  // ...
}
```

**현상**:
`renderSettings()`는 **비-idempotent** (`src/ui/nav.ts:41-46` — `switchTab()`이 매번 `app.replaceChildren()` 후 재렌더). 따라서 사용자가 설정 탭을 N번 드나들면 `document`에 같은 이벤트명으로 익명 listener가 N개 누적. 각 listener는 **이전 렌더의 `container` DOM 참조**를 클로저로 붙들고 있어 가비지 컬렉션도 막힘.

**영향**:
1. **기능**: 관심분야 모달 저장 시 `renderCurrentInterests(oldContainer)`가 먼저 호출됨 — `oldContainer`는 이미 `app.replaceChildren()`으로 분리되어 `querySelector('#currentInterests')`가 여전히 **분리된 옛 노드**를 반환하므로 동작은 이루어지지만 **화면에 반영되지 않음**. 현재 렌더 container에 대한 listener도 존재하므로 결과적으로 chip 갱신은 보이지만, 매번 분리된 DOM에 쓸모없는 작업이 추가됨 (N 번 설정 방문 시 N 번 dead-work).
2. **메모리**: 분리된 `container` + 그 자손 DOM (input 필드 값 포함 가능) 전체가 GC 대상에서 제외 → 장시간 세션에서 누적.
3. **테스트 사각**: `tests/unit/settings-interests-section.spec.ts:50-66`은 1회 렌더만 검증 → 현재 상태에선 통과하지만 리스너 누수를 감지 못함.

**권장 수정**:
module-level에 단일 registration으로 이동 + 현재 마운트된 container만 살아있는지 조회하도록 변경.

```ts
// settings.ts (module-level)
let currentSettingsContainer: HTMLElement | null = null;

// 모듈 로드 1회만 등록
document.addEventListener('dg:interests:changed', () => {
  if (currentSettingsContainer && document.body.contains(currentSettingsContainer)) {
    renderCurrentInterests(currentSettingsContainer);
  }
});

// renderSettings 안에서
export function renderSettings(container: HTMLElement): void {
  currentSettingsContainer = container;
  // ... 기존 로직
}
```

또는 `bindInterestsHandlers` 안에서 `AbortController`를 썬 unmount 훅을 노출 (v3.3.3 규모 고려하면 첫 방법이 저비용).

**P1 분류 사유**: P0로 보지 않은 이유 = 현재 시나리오(사용자가 관심분야 모달 저장 후 설정 탭에서 즉시 확인)에서 UI는 의도대로 동작. 메모리 누수도 모바일 SPA에서 탭 10회 왕복 정도면 무시 가능. 다만 **장시간 데스크톱 세션 + 자주 재진입**에서 악화. v3.3.4 최초 커밋으로 수정 권장.

### P1-2. `memo.ts` / `interests.ts` 모달 body의 인라인 `style=` 남용

**파일**: `src/ui/modals/memo.ts:28-35`, `src/ui/modals/interests.ts:55-75`

`bodyHtml`로 넘기는 템플릿에 `style="width:100%;padding:10px;border:..."`, `style="display:flex;gap:8px;..."` 식 인라인 속성이 8~10 지점. 이유는 `.dg-modal-body` 내부에 전용 유틸 class가 없어 빠른 구현으로 들어간 것으로 보임.

**영향**:
1. **CSP 하드닝 경로 차단**: `firebase.json:11`에 `style-src-attr 'unsafe-inline'`이 남아있는 이유 중 하나가 이런 인라인 스타일. v3.4+에서 `style-src-attr 'none'`으로 갈 수 없음.
2. **유지보수**: 토큰(`--radius-sm`, `--border`, `--bg-input`) 일관성은 지켰지만, 다크모드 변수가 바뀌면 두 파일을 동시에 수정해야 함.
3. **스펙 §4.1.5 "메모 UI = 모달 전환" 서술과 별개** — 스펙에는 인라인 style 허용 여부가 명시되지 않음. 디자인상 이탈은 아니나 프로젝트 스타일(CSS 레이어에 들어가는 컴포넌트 클래스)과 이질적.

**권장 수정**:
`src/styles/components/shared.css`에 모달 공통 유틸 클래스를 추가 (이미 `.dg-modal-body`가 있음 — 그 아래에).

```css
.dg-modal-input-textarea { width: 100%; padding: 10px; border: 1px solid var(--border); ... }
.dg-modal-footer { display: flex; gap: 8px; justify-content: flex-end; margin-top: 12px; }
.dg-modal-grid-2col { display: grid; grid-template-columns: 1fr 1fr; gap: 8px; }
.dg-modal-checkbox-card { display: flex; align-items: center; gap: 8px; ... }
```

그리고 `memo.ts` / `interests.ts`의 `bodyHtml`에서 `style="..."`을 클래스 참조로 교체.

**P1 분류 사유**: XSS 측면에서는 caller-hardcoded 템플릿이고 사용자 입력을 `escapeHtml()`로 통과시키므로 안전. 다만 스타일 컨벤션 및 CSP roadmap의 P1. 즉시 수정 없이도 배포 가능.

## 4. P2 (백로그 — v3.3.4 후보)

### P2-1. `briefings.ts`의 `imageUrl` 타입 런타임 검증 부재
**파일**: `src/state/briefings.ts:11` + `loadBriefings()`
`JSON.parse(... ?? '[]') as Briefing[]` — localStorage가 과거 버전에서 쓴 값에 `imageUrl`이 `null` 또는 문자열 외 타입으로 저장됐다면 `data-tier="1"` 분기가 `b.imageUrl ? '1' : '2'` (truthy)로 처리되어 큰 문제는 없음. 다만 정책상 localStorage schema 변경 시 `schemaVersion` 필드를 도입해 적극 검증하는 편이 깨끗. (이는 프로젝트 전반의 pattern이므로 v3.3.4 이상에서 일괄 정리 권장.)

### P2-2. `openMemoModal` / `openInterestsModal`의 버튼 셀렉터가 `document.getElementById(...)`로 글로벌 조회
**파일**: `memo.ts:38-40`, `interests.ts:78-80`
`openModal()` 후 `#saveMemoBtn` id로 조회. 메모/관심분야 모달이 동시에 열릴 일은 현재 없지만(openModal은 단일 active), 추후 다이얼로그 chain을 허용하면 id 충돌 가능. `wrap.querySelector()`를 반환하는 API로 리팩토링하면 안전.

### P2-3. `tests/smoke/cardnews.spec.ts:100-116` tier3 fallback test가 `page.route` abort에만 의존
네트워크 abort 대신 실 외부 호스트 응답 실패(4xx/5xx)가 `error` 이벤트를 trigger하는지까지는 검증 X. 현재 구현상 브라우저는 abort/4xx/5xx/DNS fail 모두 `error` 이벤트를 발생시키므로 behavioral coverage는 OK. 다만 스펙 §7.3 "tier 3 graceful degradation"을 실 조건과 더 유사하게 추가 검증할 여지 있음.

### P2-4. `interests.ts`의 `saveBtn.disabled = !anyChecked`가 초기 렌더 시 `save-disabled` 상태를 시각적으로 반영하지 않음
save 버튼 CSS에 `:disabled` 스타일이 없어 비활성화돼도 UI상 같은 primary 스타일. 기능은 동작하지만 접근성/UX 관점 P2.

### P2-5. `home.ts:202` `initialLetter = (b.sourceTitle?.[0] ?? '?').toUpperCase()`
`sourceTitle = '테크크런치'`이면 한글 문자가 grapheme cluster 문제 없이 `.toUpperCase()` pass-through (한글은 대소문자 없음). 다만 이모지 접두사 sourceTitle (e.g. `'📱 Toss'`)이 들어오면 `🏗️` 같은 복합 이모지에서 `.[0]`이 surrogate 쪼갬. 현재 `rss.ts` 응답의 `feed.title`은 단순 문자열이라 문제 없지만, 향후 사용자 커스텀 피드 도입 시 대비 필요.

### P2-6. `shared.ts:37`에 `Date.now()` 기반 titleId 생성
같은 모달이 Date.now() 해상도(1ms) 내에 chain open되면 id 충돌 가능. `Math.random().toString(36).slice(2, 6)` suffix가 더해져 실 충돌 확률은 극히 낮지만, 크립토 난수(`crypto.randomUUID()`)로 교체 시 완전 결정론적. v3.3.4+에서 `crypto.randomUUID`가 모바일 Safari 15.4+까지 지원되므로 교체 가능.

### P2-7. `closeModal({ skipFocusRestore: true })` 호출 경로가 chain-open 외에 노출되지 않음
현재 `interests.ts:94` 등에서는 일반 `closeModal()`만 호출. 올바르지만, 외부 호출자가 chain open 외 상황에서 실수로 `{ skipFocusRestore: true }`를 지정하는 오용 가능성 있음. 타입 레벨로는 보호되지 않음. (JSDoc에 "internal use only" 추가 권장.)

## 6. Security Self-Diagnosis (OWASP A03 / A05 중심)

### A03 — Injection (XSS)

| 벡터 | 방어 | 검증 |
|---|---|---|
| RSS 이미지 URL | `sanitizeHttpsUrl()` — `new URL()` 파싱 + `protocol === 'https:'` gate | `tests/unit/rss-image.spec.ts:59-88` — `javascript:`/`http:`/`data:`/malformed 모두 거부 |
| RSS description `<img>` src | `DOMParser.parseFromString(..., 'text/html').querySelector('img')?.getAttribute('src')` + sanitizeHttpsUrl | DOMParser는 script 미실행 보장. sanitize 통과 |
| 브리핑 카드 title/summary/source | 전부 `.textContent = ...` | `tests/unit/render-briefing.spec.ts:106-114` — `<script>alert(1)</script>` 문자열로 남고 script element 미생성 |
| chat bubble text/action label | `.textContent`, `createElement('button')` + `.textContent` | `tests/unit/chat-bubble.spec.ts:40-54` — 동일 방어 검증 |
| memo 모달 textarea 초기값 | `escapeHtml(existing)` → textarea 내부 문자열 (textarea 내용은 innerHTML로 들어가도 DOM이 plain text로 처리) | `tests/unit/modals-memo.spec.ts:71-86` — `<script>` 문자열 그대로 value에 들어가고 실행 안됨 |
| interests 체크박스 value/label | `escapeHtml(c.id)`, `escapeHtml(c.label)` | (하드코딩 INTERESTS이지만 escape 방어 유지 — 나쁘지 않음) |
| archive modal bodyHtml | pre-existing — `escapeHtml()` + `.replace(/\n/g, '<br>')` + 모든 interpolation escape 통과 |

**결론**: A03 관점 **통과**. `innerHTML` 사용 지점은 모두 caller-hardcoded 템플릿 + escape된 변수만 삽입. user input이 들어가는 곳은 `escapeHtml()` 또는 `textContent`.

### A05 — Security Misconfiguration

| 체크 | 결과 |
|---|---|
| CSP `img-src 'self' data: https:` 확장이 `firebase.json`과 `index.html` 양쪽 동기 | `tests/unit/csp.spec.ts:20-31` — 두 파일의 `img-src` 문자열 매칭 assertion |
| `http:` 이미지 차단 | https-only sanitize로 sanitize 단에서 이미 제거. 브라우저 mixed-content도 백업 |
| CSP `script-src 'self'` 유지 (인라인 onerror 없음) | `home.ts:212` `img.addEventListener('error', ...)` — DOM API 바인딩 |
| `script-src-attr 'unsafe-inline'` 없음 | firebase.json 확인됨. 인라인 핸들러 전무. |
| `referrerpolicy="no-referrer"` | `home.ts:211` — 외부 호스트에 Referer 누출 최소화 |
| `target="_blank" rel="noopener noreferrer"` | `home.ts:198-199` — reverse tabnabbing 방어 유지 |
| `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'` | CSP에 남아있음. clickjacking + form redirect 방어 유지 |
| API 키 노출 | `localStorage` 저장 (기존 디자인, 변경 없음). SPA 특성상 XSS가 없다는 전제 하에 허용 가능. 본 릴리스에서 confidentiality 변화 없음 |

**결론**: A05 관점 **통과**. CSP 확장은 기능상 필요 최소 범위(`img-src`에만 `https:` 추가)이고, 3중 방어(CSP + sanitize + referrerpolicy)가 구성되었음.

### 추가 CSP 여지 (P1-2와 연동)

`style-src-attr 'unsafe-inline'`이 여전히 CSP에 존재. v3.3.3이 이를 적극 도입하지는 않았지만 P1-2의 인라인 style 사용으로 **의존을 계속 유지**하는 형국. v3.3.4에서 인라인 style을 컴포넌트 클래스로 이관하면 `style-src-attr 'none'`으로 tightening 가능.

### OWASP 기타 (A01/A02/A04/A06~A10)

스펙 §8에서 셀프 체크가 이뤄졌고, 본 리뷰도 추가 우려 없음:
- **A01 Broken Access Control**: SPA / 권한 계층 없음
- **A02 Cryptographic Failures**: 암호화 대상 없음
- **A04 Insecure Design**: 카드 액션 원문 링크 중복 제거, tier fallback 설계 자체는 견고
- **A06 Vulnerable Components**: `package.json` 변경 없음 (의존성 영향 0)
