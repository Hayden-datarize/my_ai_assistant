## 5. P2 (Backlog — 배포 차단 아님)

### P2-1 — 읽기/쓰기 URL 검증 정책 비대칭
- **위치**: [src/state/briefings.ts:16-18](src/state/briefings.ts#L16) vs [src/services/rss.ts:24-33](src/services/rss.ts#L24)
- **내용**: 쓰기 측 `sanitizeHttpsUrl`은 `new URL()` 기반 strict parser — 공백/탭/잘못된 authority 모두 reject. 읽기 측 `isValidImageUrl`은 regex `/^https:\/\//i` — `"https:///no-host"`, `"https://user@attacker.example"` 같은 엣지 케이스 통과 가능
- **실 공격면**: CSP `img-src 'self' data: https:` (index.html:7) + `referrerpolicy="no-referrer"` 로 제한됨 → tampered imageUrl은 임의 https 리소스 로드 가능하나 JS 실행 불가
- **권고**: 공유 `isHttpsUrl()` 헬퍼 추출 or 읽기 측도 `new URL()` 기반으로 통일. **v3.5 또는 다음 hotfix 후보**

## 6. Strengths (리뷰어 지적)

1. **Spec fidelity 매우 높음** — 모든 export 이름 (`getInitialLetter`), 타입 predicate (`isValidImageUrl`), 토큰 이름 (`--bg-disabled`), UUID regex 모두 plan과 정확 일치. 범위 0 drift.
2. **Test behavior 기반** — `tier-downgrade`는 real localStorage seed + real `page.route` + real `img.onerror` 이벤트 검증. Mock handler 아님. `feedback_test_coverage_cors_csp.md` lesson 준수.
3. **Defensive narrow, paranoid 아님** — `loadBriefings`는 malformed `imageUrl`만 drop, briefing 자체는 보존. 기록 손실 방지 + scope 유지 균형.
4. **WCAG 대비 분석 in-spec** — §4.3 대비표(라이트 ~3.9:1, 다크 ~3.3:1)가 spec에 명시. disabled state AA 기준 충족 (3:1 non-text contrast).
5. **`@internal` JSDoc 정확성** — grep 확인: `skipFocusRestore`는 shared.ts:29 한 곳만 caller. memo/interests/archive 모두 `closeModal()` no-arg 호출.
6. **`crypto.randomUUID()` 안전성** — 테스트 regex `/^dg-modal-title-[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/`가 UUID v4 형상 검증 + jsdom/vitest 런타임 지원 증명.
7. **disabled-button 듀얼 테마** — 라이트 + 다크 각각 별도 test. 테마-토큰 회귀 감지.
8. **`opacity: 1` override 주석** — `buttons.css:24`에 cascade 결정 self-documenting 주석. 다음 maintainer가 헷갈리지 않음.
