### T1 (R1) — 토큰 base 업데이트 (color / shadow / radius / motion)

**경계**: `src/styles/tokens.css` `:root` 블록 (light + theme-invariant).

**목적**: "올드함"의 토큰 단 3대 원인(얕은 shadow / 보통 채도 / 작은 radius)을 일괄 해결 + M3 accent 시각 어휘(spring motion / gradient) 도입.

**수정 (구체값)**:

```css
/* Color */
--primary-vivid: #6366F1;       /* 신규: hover/active */
--primary-gradient: linear-gradient(135deg, #6366F1 0%, #818CF8 100%);
--accent-gradient: linear-gradient(135deg, #F59E0B 0%, #FBBF24 100%);

/* Shadow — soft 3D depth (3-tier 재정의) */
--shadow-sm: 0 1px 2px rgba(15,23,42,0.06), 0 1px 1px rgba(15,23,42,0.04);
--shadow-md: 0 4px 12px rgba(15,23,42,0.08), 0 2px 4px rgba(15,23,42,0.04);
--shadow-lg: 0 12px 32px rgba(15,23,42,0.12), 0 4px 8px rgba(15,23,42,0.06);
--shadow-glow: 0 0 0 4px rgba(99,102,241,0.15);

/* Radius — 한 단계 ↑ */
--radius-2xl: 24px;             /* 신규: hero 카드용 */

/* Motion — spring easing */
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
--ease-out-soft: cubic-bezier(0.22, 1, 0.36, 1);
```

**위험**: 토큰 변경 → archive/settings/missions까지 자동 propagate. 기존 vitest jsdom getComputedStyle 사용처 한정 update. 사전 review에서 cross-screen invariant 강화 권고.

**테스트**: 신규 vitest — `tests/styles/tokens.spec.ts` (토큰 export 값 회귀 가드, +6 it 추정).

### T2 (R2) — 다크 모드 warm charcoal

**경계**: `src/styles/tokens.css` `[data-theme="dark"]` 블록.

**목적**: 현 dark `--bg: #0F172A`(차가운 slate-900) → 따뜻한 charcoal로 야간 사용감 부드럽게.

**수정**:
- `--bg`: `#0F172A` → `#161823`
- `--bg-card`: `#1E293B` → `#22242F`
- `--bg-input` / `--border`: `#334155` → `#363846`
- `--heatmap-l0`: `#0F172A` → `#161823` 동기화

**위험**: WCAG AA 4.5:1 컨트라스트 재검증 필요 (`text-primary #F1F5F9` vs `--bg #161823`). 수동 1회 dark mode cycle.

**테스트**: dark theme 적용 후 home/stats/archive/settings 수동 1회 시각 확인 + 신규 unit 1 (`--bg` value assertion, T1 spec에 합산).

### T3 (R3) — home 카드뉴스 + 오늘의 질문 hero polish

**경계**: `src/styles/components/cards.css` (briefing 영역 — 정확한 class 이름 plan T0 grep으로 pin) + `src/styles/pages/home.css` (daily-task hero).

**목적**: home 첫 진입 시각 비중 80% 영역. 평평한 카드 + 얕은 shadow → depth + hover lift + 둥근 라운드로 modernize.

**수정**:
- briefing card root: `border-radius: var(--radius-2xl)`, `box-shadow: var(--shadow-md)`.
- `@media (hover: hover) { briefing-card:hover { transform: translateY(-2px); box-shadow: var(--shadow-lg); transition: transform var(--duration-base) var(--ease-spring), box-shadow var(--duration-base) var(--ease-out-soft); } }`.
- briefing card `:active`: `transform: translateY(0)` (탭 피드백).
- 오늘의 질문 hero(daily-task 영역): `box-shadow: var(--shadow-lg)` + subtle gradient `background: linear-gradient(180deg, var(--bg-card) 0%, color-mix(in srgb, var(--primary-ultra-light) 30%, var(--bg-card)) 100%)`.

**위험**: hover transform이 mobile touch에서 stick → `@media (hover: hover)` 가드 필수. grid layout reflow 없도록 transform만 사용 (margin/width 변경 금지).

**테스트**: 신규 vitest 2 — briefing card class 적용 + hero gradient 적용 assertion (jsdom 한정 inline-style 검증 가능 범위).

### T4 (R4) — stats 히트맵 polish

**경계**: `src/styles/components/heatmap.css`.

**목적**: 히트맵 cell 단조로움 + hover 피드백 부재 → M3 accent로 색·모션.

**수정**:
- `.heatmap-cell`: `border-radius: 4px → 6px`, `transition: transform var(--duration-fast), background-color var(--duration-base)`.
- `@media (hover: hover) { .heatmap-cell:hover { transform: scale(1.15); box-shadow: var(--shadow-glow); z-index: 1; } }`.
- 라벨 `color: var(--text-tertiary)` → `var(--text-secondary)` (가독성 ↑).
- ramp(`--heatmap-l1~l3`)는 v3.3.3 ramp B 그대로 유지.

**위험**: `transform: scale(1.15)` 인접 cell overflow → grid gap(2~4px) 충분한지 확인 + `z-index: 1` raise.

**테스트**: 기존 stats heatmap render spec PASS + 신규 vitest 1 — hover transform class assertion.

### T5 (R5) — stats 정원 polish

**경계**: `src/styles/components/garden.css`. (`.garden-grid`, `.garden-card`, 빈자리 placeholder class 이름은 plan T0 grep으로 정확 pin.)

**목적**: 정원 grid의 식물 카드 ↔ 빈자리 시각 분리감 없음 → ambient 배경 + 식물 카드 depth + dotted 빈자리.

**수정**:
- `.garden-grid`: `background: linear-gradient(180deg, transparent 0%, color-mix(in srgb, var(--primary) 3%, transparent) 100%)` (ambient 톤).
- `.garden-card`: `border-radius: var(--radius-xl)`, `box-shadow: var(--shadow-md)`, `transition: transform var(--duration-base) var(--ease-spring), box-shadow var(--duration-base)`.
- `@media (hover: hover) { .garden-card:hover { transform: translateY(-1px) scale(1.02); box-shadow: var(--shadow-lg); } }`.
- 빈자리 placeholder: `border: 1.5px dashed var(--border)`, `border-radius: var(--radius-lg)`, `background: var(--bg-input)`.

**위험**: hover 시 grid jump 없도록 transform-only. v3.15 garden id 중복은 v3.16에서 fix됨 — 단일 selector OK.

**테스트**: 기존 garden render spec PASS + 신규 vitest 2 — 빈자리 class 구조 + garden-card hover class.

### T6 (C2 carry) — scroll-margin CSS UX

**경계**: `src/styles/base.css` 또는 `src/styles/layout.css` (전역 `:where()` selector — plan T0에서 적합 위치 결정).

**목적**: v3.16 T6 mobile submit fixed-nav overlap의 본질 해법. JS scrollIntoView fix는 유지 + CSS layer 보강.

**수정**:

```css
:where(input, textarea, [data-scroll-target]) {
  scroll-margin-top: calc(var(--nav-height) + 16px);
  scroll-margin-bottom: var(--content-bottom-pad);
}
```

**위험**: trivial — `:where` specificity 0이라 기존 override 가능. CSS-only, JS path 무변경.

**테스트**: 기존 layout smoke PASS + v3.16 T6 mobile submit smoke 자연 cover.

### T7 (C4 carry) — modal listener audit

**경계**: `src/ui/modals/*.ts` (welcome-gamification, interests-modal, answer-detail, settings-interests, image-bigview, archive-select 등 — plan T0에서 grep `addEventListener.*keydown|click.*close` 결과로 정확 list 확정).

**목적**: v3.16 C3 welcome-garden AbortController fix의 cross-modal audit. 동일 risk 일괄 적용.

**수정 (각 모달 동일 패턴)**:

```ts
// open
const ctrl = new AbortController();
document.addEventListener('keydown', escHandler, { signal: ctrl.signal });
// close (버튼/backdrop/ESC 모든 path)
```

**위험**: 모달별 lifecycle 다양 (module-level / class / dynamic) → grep 후 site별 확인 필수. 이미 cleanup 잘 된 모달은 fix skip.

**테스트**: 신규 vitest — 각 모달 spec에 "open → close → ESC press → handler 미호출" 1 it. v3.16 C3 패턴 재사용 (~+6 it 추정, 모달 6개 가정).

- **T1~T9 모두 PASS**.

- **번들 측정**: `gzip -c dist/assets/index-*.js | wc -c` canonical.
  - 목표: **net +1.0 ~ +2.0 kB** (절대값 기준 34887 → 35887~36887 B).
  - T9 trim −300~−500 B 회수 후 측정.
  - hard cap **+2.5 kB over 시 fail** → in-cycle 추가 trim 또는 hero polish scope 축소.
- **사전 + 최종 review 모두 P0=0** (P1 in-cycle 반영, P2 → v3.18 backlog).
- **다크 모드 수동 1회 cycle** — home/stats/archive/settings 시각 + WCAG 4.5:1 컨트라스트 자체 검증.
