## §1. Scope & Goals

### 1.1 배경

v3.19 retro에서 **carry-forward 8 그룹 ~14건**이 v3.20 backlog seed로 명시됨. 핵심 줄기:

1. **Backend 정정 (시급)** — Functions runtime/deps deprecation 임박. Node 20 deprecated 2026-04-30 / decommission 2026-10-30 → 6개월 시한. firebase-functions ^5 outdated. artifact registry cleanup policy 미설정 (빌드 캐시 비용 누적 risk).
2. **RSS observability** — v3.18.1 H2에서 도입한 retry 로직(429/503 max 2회 exp backoff)이 production에서 실제 어느 빈도로 발동하는지 가시성 부재. v3.18.1 N3/N4 carry.
3. **P2 backlog 누적** — v3.19 최종 review에서 4건 + v3.18.1 P2 9건 + v3.18 in-cycle 발견 P2 7건 (일부 v3.19에서 자연 흡수). 신규 기능 사이클 진입 전에 청산.

v3.20은 이 3 줄기를 일괄 소진하여, v3.21 신규 기능 사이클(식물 detail modal / Streak Freeze / 게임화 M3·M4)을 깨끗한 상태에서 진입한다.

### 1.2 목표

- **Backend deprecation 시한 해소** — Node 22 + firebase-functions latest + artifact registry cleanup policy + cors 명시.
- **RSS retry 가시성 확보** — telemetry 추가 + 보수적 시드(jitter/backoff 조정)로 외부 API 부담 ↓.
- **P2 backlog 청산** — bundle trim + rel 통일 + CSP dead allowance + helper P2 4건 + functions vitest spec 보강.
- **smoke baseline 정상화** — N=10 cold-fork 검증으로 v3.19 carry된 flake 가능성 closure.
- **신규 기능 0 / Schema 변경 0** — hygiene 정체성 유지.

### 1.3 비목표 (out-of-scope)

- **신규 기능** — 식물 detail modal / Streak Freeze / max stage ambient / M3 missions·뱃지 grid / M4 glassmorphism welcome 모달. **모두 v3.21+**.
- **in-memory rate limit → Firestore 마이그레이션** — 단독 사이클이 더 안전 (cold-start reset 차단은 별도 설계 + persistence 비용 검토 필요). v3.21+ 또는 별도 사이클.
- **Schema 변경** — user v4 / mission v3 그대로.
- **Slack DM 기능 변경** — v3.19 backend 그대로 유지. cors flag 명시는 정합성 reaffirm일 뿐 동작 변경 없음.
- **CSP 새 호스트 추가** — wildcard 좁히기만 (dead allowance 제거).
- **신규 dependency** 없음 (firebase-functions latest는 upgrade일 뿐).

### 1.4 정책 (REJECT / 신규 기능 / P0 회귀)

- **신규 기능 금지** — hygiene 전용. 모달 추가, 새 화면 모두 v3.21+.
- **Schema 변경 금지**.
- **리뷰 final REJECT 시 in-cycle hotfix만 허용** (v3.15 T16.1 / v3.13 T10 / v3.18 정책 일관). 신규 기능 추가 금지.
- **P0 회귀 발견 시 신규 task 추가 가능** (1 task budget 권고).
- **A6 console.info sunset** — 본 사이클 막판 production 모니터링 결과 의존 → **별도 안건**, v3.20 task 외 hotfix 또는 v3.20.x로 처리. spec §2 미포함.

### 1.5 가설 fix duo 모니터링 (별도 안건)

v3.19 T7~T9에서 도입한 파란 화면 #3 가설 fix(SW image 검증 + await race 차단 + console.info 진단)는 **production 1주 모니터링** 후 결정:

## §2. Carry-forward 13건 매핑 (5 그룹)

### 2.1 그룹 A — Backend 정정 (4건)

- **A1** Node 20 → **22** runtime upgrade. `functions/package.json` `"engines": { "node": "22" }` + firebase.json runtime 명시 시 sync.
  - 시한: Node 20 deprecated 2026-04-30, decommission 2026-10-30 (6개월).
- **A2** `firebase-functions` ^5 → latest (보안/호환성). `firebase-admin` ^12 → latest 동반 검토.
- **A3** artifact registry cleanup policy 설정. Firebase CLI: `firebase functions:artifacts:setpolicy`. Default 30일 retention.
- **A4** Function `cors: false` 명시 — `sendAnswerDm` `onRequest({ cors: false, ... })`. same-origin rewrite와 정합성 reaffirm (현재 동작 OK, 명시성 ↑).

### 2.2 그룹 B — RSS observability (2건)

- **B1** RSS retry telemetry — 현재 `src/services/rss.ts` retry 로직(429/503 max 2회 exp backoff [200, 800])이 발동 시 가시성 0. 옵션:
  - **B1-α**: localStorage rolling counter (`dg.rss.retry_count_24h`) — UI 노출 없음, T13 retro에서 production 1주 관측.
  - **B1-β**: console.warn level (T7 console.info 패턴) — `import.meta.env.DEV` 가드.
  - **결정 보류**: T0 사전 review에서 reviewer 의견 반영. 1차 권고는 **β + α 둘 다** (DEV log + 24h counter).
- **B2** RSS 보수적 시드 — backoff `[200, 800]` → `[500, 1500]` + jitter ±20% (외부 API 부담 ↓, 429 회복력 ↑). `MAX_RETRIES`는 2 유지 (timeout 5s 내 잔여 시간 고려).

### 2.3 그룹 C — 코드 cleanup (5건)

- **C1** Bundle trim — 현재 35143 B (v3.19 baseline). target net **−200~−400 B** (35143 → 34743~34943). 후보:
  - 미사용 export 제거.
  - dead branch (예: removed-feature 잔존 if).
  - escapeHtml 호출 dedup.
  - **확정 후보는 plan 단계에서 grep 기반 식별**.
- **C2** `src/ui/handlers/archive.ts:472` `rel="noopener"` → `rel="noopener noreferrer"` 통일 (settings.ts:52 패턴 정합).
- **C3** CSP `connect-src` dead allowance 정리 — 현재 `'self' generativelanguage.googleapis.com api.rss2json.com *.firebaseio.com *.googleapis.com *.sentry.io`.
  - **검토**: `*.firebaseio.com` (Realtime Database SDK 미사용 → 후보 dead) / `*.googleapis.com` wildcard (generativelanguage 이미 명시 → 중복) / `*.sentry.io` (SDK 미사용 → 후보 dead).

  - **plan 단계 1차 grep 검증** + lint vitest assertion 추가.
- **C4** `settings.help` unused class 정리 (v3.19 T6 P2). `index.html` + main.css cross-grep.
- **C5** `await peek.json` fire-and-forget 명시 (v3.19 T8 P2) + `chat.postMessage` error log 보강 (v3.19 T4 P2). functions/src 영역 — 묶음 처리.

- **분류**: P0/P1/P2 → **P0/P1 in-cycle 반영**, P2는 plan 항목으로 추가 또는 v3.21+ backlog.
