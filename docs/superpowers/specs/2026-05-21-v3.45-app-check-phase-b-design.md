## §2. T1 — C1 Backend `enforceAppCheck:true` + 응답 Contract

### 2.1 변경 범위

**`functions/src/sendAnswerDm.ts`** (T1 자체는 frontend 영향 0, hosting bundle Δ 0 — settings UX copy는 T2 별도):

**Pre-check (implementer 의무)**: `functions/package.json` firebase-functions version 확인. `enforceAppCheck` 옵션은 firebase-functions v2 onRequest에서 v3.14+ 지원. 현재 v3.x 또는 v7.x 확인 후, 미지원이면 minor bump 또는 옵션 unavailable 명시.

```ts
export const sendAnswerDm = onRequest(
  {
    secrets: [SLACK_BOT_TOKEN],
    maxInstances: 1,
    cors: CORS_ORIGINS,
    region: 'us-central1',
    enforceAppCheck: true,  // ⬅ Phase B: 인증 실패 시 firebase-functions 자동 401
  },
  async (req, res) => {
    // ... validation 그대로 ...
    try {
      // ... buildAnswerBlocks + sendDmAsBot ...
      res.status(200).json({ ok: true });
    } catch (e) {
      const msg = e instanceof Error ? e.message : 'unknown';
      // ⬇ generic 202 변환 (3 error)
      if (msg === 'user_not_found' || msg === 'lookup_failed' || msg === 'dm_open_failed') {
        res.status(202).json({ ok: true });  // Slack 멤버 enumeration 차단
      } else if (msg === 'post_message_failed') {
        res.status(502).json({ error: 'post_message_failed' });  // 실제 send 시도 후 실패
      } else if (msg.startsWith('http_5')) {
        res.status(502).json({ error: 'slack_upstream' });
      } else {
        res.status(500).json({ error: 'internal' });
      }
    }
  },
);
```

### 2.2 응답 Contract 표 (변경/유지)

| Error | Before | After | 변경 사유 |
|---|---|---|---|
| `user_not_found` | 404 | **202 `{ok:true}`** | Slack 멤버 enumeration 차단 |
| `lookup_failed` | 502 | **202 `{ok:true}`** | user 미존재 vs Slack 시스템 에러 구분 가능 → 누출 |
| `dm_open_failed` | 502 | **202 `{ok:true}`** | 동일 enumeration risk |
| `post_message_failed` | 502 | 502 유지 | 실제 send 시도 후 실패, enumeration 불가 |
| `slack_upstream` | 502 | 502 유지 | 시스템 에러 |
| `invalid_email/answer/question` | 400 | 400 유지 | request malformed, client 검증 피드백 필요 |
| `rate_limited` | 429 | 429 유지 | 의도된 응답 |
| App Check 인증 실패 | (없음, monitor) | **401** (firebase-functions 자동) | `enforceAppCheck:true` native |
| `method_not_allowed` | 405 | 405 유지 | — |

### 2.3 Frontend Ripple — `src/services/slack.ts`

**현재 (v3.42 T3, slack.ts:46-49)**:
```ts
if (!res.ok) {
  const body = await res.json().catch(() => ({} as { error?: string }));
  const errCode = body.error ?? res.status;
  throw new Error(`slack_${errCode}`);
}
```

**Phase B 후 분기 (202는 `res.ok === true`이므로 자동 success path)**:
- `user_not_found`/`lookup_failed`/`dm_open_failed` → 202 → `res.ok=true` → toast "DM 전송 완료" 표시 → **silent failure 위험**.

**정합 design (CLAUDE.md 정석)**: toast 일관적으로 generic "DM 시도 완료" + settings UX copy로 안내 유도.
- `slack.ts`는 변경 0줄 (이미 generic — Error code 그대로 throw, 202 자동 success).
- `autoSendAnswer`는 이미 silent (`console.warn` swallow) — 변경 불요.
- caller (home.ts 등)의 `try/catch` toast wording은 generic 유지 — 변경 검토 의무.

**T1 implementer 의무**: `rg "sendAnswerDm|autoSendAnswer" src/` 전수 grep + toast wording 검토. 만약 caller가 `slack_user_not_found`/`slack_lookup_failed`/`slack_dm_open_failed` 별도 분기 toast를 띄우는 코드가 있다면 → 해당 분기 제거 (어차피 호출 안 됨).
