## §1 Background

v3.7 도입한 `MSG.SAVE_QUOTA_EXCEEDED` 토스트는 응급 가이드("설정에서 번역 캐시를 초기화해 주세요")만 제공. 본질 해결책 부재 — 사용자가 누적된 archive 답변 자체를 정리할 수단 없음.

또한 사용자가 archive에서 답변을 보다가 "이거 마음 바뀌었다 / 실수로 답한 답변" 등 단건 수정 권한이 없음. 자기 데이터 통제권 부족 → UX 신뢰도 손상 잠재.

본 사이클은:

- **타깃 삭제** — archive 카드별 ✕ 버튼, 마찰 최소화 (Undo 토스트 5초 단일 안전망)
- **벌크 삭제** — archive 모달 선택 모드 → 다중 선택 + 일괄 삭제, 위험 ↑로 confirm + Undo 이중 안전망
- **핵 옵션** — settings "데이터 삭제" 섹션에 "전체 답변 초기화", confirm + Undo
- **보존 정책** — XP / Streak / level / heatmap activity 마커 그대로 (스코어링 정책은 v3.9+ 옵션 A 영역)

> **plan 단계 발견** — 본 사이클의 "번역 캐시 동반 정리"는 **무효(N/A)**. v3.4 번역 캐시는 briefings(뉴스)에만 적용(`'briefings'` 키, per-briefing `titleKo`/`summaryKo`/`detectedLang`)이고, answers(`'dg.answers'` 키)는 번역 캐시와 매핑이 없음. 따라서 답변 삭제 시 정리할 캐시 entry 부재. briefings 캐시 정리는 settings 기존 버튼(`#clearTranslationCacheBtn`)으로 그대로 유지.

## §2 Goals & Non-goals

### Goals

- archive 답변을 **타깃 / 벌크 / 전체** 3 단위로 삭제 가능하게 함
- 모든 삭제 액션에 **5초 in-memory Undo** 안전망 제공
- 위험 등급별 confirm 차별화 — 타깃은 마찰 0, 벌크/핵은 confirm 다이얼로그 1단
- XP / Streak / level / heatmap activity 마커 **보존** (행동 변경 0)
- 삭제 도중 storage 실패 시 v3.7 `getSaveErrorMessage` 패턴 재사용 → 분기 토스트
- 회귀 0 — 기존 archive 모달 / settings 흐름 / 빈 상태 UX 그대로

### Non-goals

- **XP / Streak / level 차감 정책** — 삭제 시 스코어 환원 없음. 옵션 A (XP/Streak wiring) 사이클 영역. 본 사이클은 "본문만 삭제, 활동 흔적 보존" 단순 정책
- **soft delete / 휴지통 / 만료 처리** — 별도 storage schema, 만료 cron, 휴지통 UI 모두 YAGNI. 5초 Undo로 즉각 실수만 회복. v3.9+ 실수요 발생 시 별 사이클
- **기간/필터 기반 벌크 정리** — "이전 30일치 삭제" 같은 필터 UX 미포함. 미오픈 서비스 + 사용자 1명 컨텍스트에 과도. 사용자가 선택 모드에서 직접 체크하는 단순 다중 선택만 지원
- **answer ID 기반 영구 삭제 로그** — archive에서 사라지면 흔적 0. "언제 무엇을 지웠는지" 감사 로그 미포함
- **Full i18n** — 신규 카피는 v3.6/v3.7 패턴(`MSG.*` 키)으로 추가하되 다국어 카탈로그는 별 사이클
- **archive 영문 제목 토글** (`swapTitleInDOM` 실 wiring) — 실수요 부재
- **stats 화면 답변 수 재계산** — 보존 정책상 XP/level/streak 그대로 → stats 표시 영향 없음. 단 archive 답변 카운트가 stats에 표시 중이면 자동 반영 (storage read 결과)
