## §2. Architecture

### 2.1 3가지 `as any` 패턴 분류 및 fix 전략

#### 패턴 A — `plantStateByInterest` fixture (10건)

`saveUser(mkUser({ plantStateByInterest: { leadership: { stage: 2, cumulativeActivity: 10 } as any } }))` 형태.

`src/state/plantTypes.ts:3`의 `PlantState` 타입이 source of truth. 실제 fixture는 모든 required field를 가지지만 strict TS에서 inline literal이 `Record<string, PlantState>` 추론 시 너무 narrow하게 잡혀 cast 필요. Fix:

```ts
import type { PlantState } from '../../../src/state/plantTypes';

plantStateByInterest: {
  leadership: { stage: 2, cumulativeActivity: 10 } satisfies Record<string, never> | unknown
}
```

권장 fix는 `satisfies` 또는 explicit type — `Partial<PlantState>` 캐스트가 가장 단순:

```ts
plantStateByInterest: {
  leadership: { stage: 2, cumulativeActivity: 10 } as Partial<PlantState>
}
```

단, `Partial<PlantState>`는 strict하지 않아 placeholder성 — 더 좋은 fix는 `Pick<PlantState, 'stage' | 'cumulativeActivity'>`로 명시. 가장 깔끔하고 단순한 것은 `PlantState`의 optional field만 골라 채우는 케이스가 대부분이므로 **`Partial<PlantState>`** 사용. Inline 시:

```ts
plantStateByInterest: {
  leadership: { stage: 2, cumulativeActivity: 10 } as Partial<PlantState>,
}
```

#### 패턴 B — `saveAnswers([...] as any)` / `saveBriefings([...] as any)` (8건)

`saveAnswers(answers: Answer[])` / `saveBriefings(items: Briefing[])` API 호출 시 inline literal에서 optional field omit이 cast 필요. Fix: explicit type annotation:

```ts
import type { Answer } from '../../src/state/schema';

saveAnswers([
  { id: '1', text: '...', schemaVersion: 1, questionId: 'q1', authorId: 'self', createdAt: '...' },
] satisfies Answer[]);
```

또는 caller-side `as Answer[]`:

```ts
saveAnswers([
  { id: '1', text: '...', schemaVersion: 1, questionId: 'q1', authorId: 'self', createdAt: '...' },
] as Answer[]);
```

`satisfies`가 더 안전 (type narrowing 보존). interestCounts.spec.ts 6건 + migration-v5/v7 2건 모두 `satisfies` 사용.

#### 패턴 C — discriminated union narrow / legacy field 접근 (10건)

두 sub-pattern:

**C-1: discriminated union narrow** (achievements.spec.ts × 4 + events-plant.spec.ts × 1)

```ts
const xp = events.find(e => e.kind === 'xp-gained');
expect((xp as any).amount).toBe(10);
```

Fix — type predicate로 narrow:

```ts
const xp = events.find((e): e is Extract<GameEvent, { kind: 'xp-gained' }> => e.kind === 'xp-gained');
expect(xp).toBeDefined();
expect(xp!.amount).toBe(10);
```

`Extract<GameEvent, { kind: 'xp-gained' }>` 형태가 GameEvent union의 해당 variant를 정확히 narrow.

**C-2: legacy/pre-migration field 접근** (user-migration.spec.ts × 3 + state-user.spec.ts × 1 + validate-interest-id.spec.ts × 1 + migration-v4.spec.ts × 2 + migration-v5.spec.ts × 1 + migration-v7.spec.ts × 1)

```ts
const v2 = migrateUserToV2(v1);
expect((v2 as any).level).toBeUndefined();
```

여기서 `level`은 schema에서 **제거된** 필드. `as any`보다 `as unknown as Record<string, unknown>` 또는 `as Record<string, unknown>` 사용:

```ts
expect((v2 as unknown as Record<string, unknown>).level).toBeUndefined();
```

`Record<string, unknown>`은 lint rule을 통과하면서 의도 (deprecated field 부재 확인)를 정확히 표현.

`makeV6Base(): any` → `function makeV6Base(): Record<string, unknown>` 또는 unknown.

#### 패턴 D — 2 errors (innerHTML = '')

```ts
beforeEach(async () => {
  localStorage.clear();
  sessionStorage.clear();
  document.body.innerHTML = '';   // ← lint error
});
```

Fix — 다른 spec(plant-detail.spec.ts:9)에서 이미 graduated된 패턴 적용:

```ts
beforeEach(async () => {
  localStorage.clear();
  sessionStorage.clear();
  document.body.replaceChildren();
});
```

`replaceChildren()` (인자 없음) = 모든 child node 제거. innerHTML='' 동등.

### 2.2 메타 graduate — CLAUDE.md `§Codex 2-pass Review` 갱신

**현재 (v3.32 graduated)**: 사전 review mandatory dispatch. 최종 review는 deploy gate로 명시, controller fallback (v3.14.5/v3.20/v3.24 선례) 허용.

**v3.33 변경 (soft 명문화)**: 최종 review의 default를 **direct CLI 1차 시도 의무 + 실패 시 controller fallback + 사용자 알림**으로 단계화. 변경 위치 — CLAUDE.md `## Codex 2-pass Review` 섹션:

```markdown
2. **최종 review (deploy gate)** — 모든 main work commit 후, 배포 직전.
   `DEPLOY_APPROVED / APPROVED_WITH_NOTES / REJECT` 분류.
   - 사용자 "배포해줘" 명시 시점에 게이트로 작동.
   - **default dispatch** (v3.33 graduated):
     ```bash
     codex exec --skip-git-repo-check -o /tmp/<cycle>-codex-final.txt "<prompt>"
     ```
   - **fallback 정책**:
     1. direct CLI 1차 시도 의무 — 실패 (한도/권한 등) 명시 캡처
     2. controller `pr-review-toolkit:code-reviewer`로 대체 + **사용자에게 즉시 알림**
     3. retro §verification에 시도 결과 명시 (성공/fallback/실패 사유)
     4. 외부 권한 회복 후 retroactive 시도 권고 (v3.14.2 패턴 보존)
   - **ROI 근거** (v3.32 L2): direct CLI 성공 시 P0/P1/P2 종합 catch.
     controller fallback만으로는 P2 catch 부족 입증.
```

이 변경은 graduate 대신 soft 명문화로, 기존 v3.14.5/v3.20/v3.24 controller fallback 선례를 보존하되 **책임 명시화**가 핵심. fallback 사용 시 retro에 명시하고 사용자 알림 의무 추가.

## §5. Risks / Out-of-scope / Open Questions

### 5.1 Risks

| # | Risk | Mitigation |
|---|---|---|
| R1 | `Partial<PlantState>` 사용이 type-safety 약화 (optional field 누락 가능) | `as Partial<PlantState>`는 fixture에서 의도적 partial. test 의도 명시. 더 strict가 필요하면 `Pick<PlantState, ...>` 대안 사용 (T1 implementation 시 caller별 판단) |
| R2 | discriminated union `Extract<T, { kind: K }>`가 GameEvent union 외 변형에 적용 시 type 오류 | T3 implementation 시 GameEvent variant kind 전체 grep (`src/state/gameTypes.ts`) — `xp-gained`/`level-up`/`streak-milestone`/`badge` 확인 |
| R3 | `Record<string, unknown>` cast가 lint rule 회피 트릭처럼 보일 수 있음 | 의도: deprecated field 부재 확인 (test invariant). `as any`가 검사 자체를 회피하는 것과 달리, `Record<string, unknown>`은 unknown property access 명시 — semantically meaningful |
| R4 | `replaceChildren()` 호환성 (구형 jsdom) | jsdom 16+ 지원. 다른 spec(plant-detail.spec.ts:9)에서 이미 사용 중 — 호환성 검증됨 |
| R5 | T5 CLAUDE.md 변경이 controller 동작 자체에 즉시 영향 없음 (controller가 다음 사이클부터 의식적으로 적용) | retro에서 T6 self-application 명시 — 본 사이클이 첫 적용 사례 |
| R6 | Codex CLI 한도 (v3.32 carry — v3.31 sandbox carry는 v3.32에서 해소) | direct CLI 1차 시도 실패 시 controller fallback + 사용자 알림 (T5 policy 자기-적용) |
