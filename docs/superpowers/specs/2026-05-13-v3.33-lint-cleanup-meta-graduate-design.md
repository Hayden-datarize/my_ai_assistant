## §2. Architecture

### 2.1 3가지 `as any` 패턴 분류 및 fix 전략

#### 패턴 A — `plantStateByInterest` fixture (10건)

`saveUser(mkUser({ plantStateByInterest: { leadership: { stage: 2, cumulativeActivity: 10 } as any } }))` 형태.

`src/state/plantTypes.ts:3`의 `PlantState` 타입:

```ts
export interface PlantState {
  stage: PlantStage;
  cumulativeActivity: number;
  unlockedAt?: string;
  lastEngagedAt?: string;
}
```

→ required field 2개 (`stage`, `cumulativeActivity`)만, optional 2개. 모든 fixture는 required 둘 다 갖춰져 있음.

**v3.33 T0 사전 review P1-1 (Codex)**: `Partial<PlantState>`는 type-safety 약화 — required field 추가 시 못 잡음. **collection-level `satisfies Record<string, PlantState>`** 권장:

```ts
import type { PlantState } from '../../../src/state/plantTypes';

plantStateByInterest: {
  leadership: { stage: 2, cumulativeActivity: 10 },
} satisfies Record<string, PlantState>,
```

이유: `Record<string, PlantState>`는 (1) 미래에 PlantState required field 추가 시 fixture가 컴파일 fail (regression catch), (2) `satisfies`는 narrow 보존 (`Partial`은 narrow 손실), (3) key가 한 곳에서 명시 (string), (4) `as` cast (assertion) 대신 `satisfies` (validation).

**multi-line case** (line 57, 96 — `unlockedAt` / `lastEngagedAt` 포함): 동일 패턴. PlantState optional field 자연 통과.

#### 패턴 B — `saveAnswers([...] as any)` / `saveBriefings([...] as any)` (8건)

`saveAnswers(answers: Answer[])` / `saveBriefings(items: Briefing[])` API 호출 시 inline literal cast.

**v3.33 T0 사전 review P1-2 (Codex)**: `Answer` (`src/state/schema.ts:9`)와 `Briefing` (`src/state/briefings.ts:11`) 모두 `pinned: boolean` **required** (v3.27 T1 → v3.28 T2 graduated). interestCounts.spec.ts fixture에 `pinned` 누락 → 단순 `satisfies` 적용 시 fail. **Fix-A**: fixture에 `pinned: false` 추가 + `satisfies` 유지 (type-safe cleanup 메시지 보존). `as` fallback은 lint만 통과 — 본 사이클 목표 위배.

```ts
import type { Answer } from '../../src/state/schema';
import type { Briefing } from '../../src/state/briefings';

saveAnswers([
  { id: '1', text: '...', schemaVersion: 1, questionId: 'q1', authorId: 'self', createdAt: '...', pinned: false },
] satisfies Answer[]);

saveBriefings([
  { id: 'b1', date: '...', url: '...', title: '...', summary: '...', scrapped: true, read: false, memo: '', pinned: false },
] satisfies Briefing[]);
```

interestCounts.spec.ts 6건 + migration-v7.spec.ts 1건 (`makeV6Base` 반환 타입). migration-v5.spec.ts 1건은 실제로는 패턴 C (legacy access) — T3로 이동.

**migration-v7.spec.ts** `makeV6Base()` 반환 타입 (P2-3 권고):
```ts
function makeV6Base(): Record<string, unknown> & { schemaVersion: 6 | 7; insights: unknown[] } {
  return { ... };
}
```
이유: `Record<string, unknown>` 단독은 broad index — schemaVersion/insights mutation 의도 명시 못 함. 교집합 타입으로 fixture 의도 강화.

#### 패턴 C — discriminated union narrow / legacy field 접근 (10건)

두 sub-pattern:

**C-1a: discriminated union narrow (variant-specific field)** (achievements.spec.ts × 4)

```ts
const xp = events.find(e => e.kind === 'xp-gained');
expect((xp as any).amount).toBe(10);
```

Fix — type predicate로 narrow + optional chain (**v3.33 T0 사전 review P2-1 권고**: `xp!.amount` non-null assertion 대신 `xp?.amount` 단일 expression):

```ts
const xp = events.find((e): e is Extract<GameEvent, { kind: 'xp-gained' }> => e.kind === 'xp-gained');
expect(xp?.amount).toBe(10);
```

`Extract<GameEvent, { kind: 'xp-gained' }>` 형태가 GameEvent union의 해당 variant를 정확히 narrow.

**C-1b: variant-common field (predicate 불필요)** (events-plant.spec.ts × 1)

```ts
const e = events.find(ev => ev.kind === 'plant-stage-up');
expect(typeof (e as any)?.at).toBe('number');
```

**v3.33 T0 사전 review P2-2 권고**: `at: number`는 모든 GameEvent variant 공통 필드 (`src/state/gameTypes.ts:27-32` 전수 확인 — 6 variant 모두 `at: number`). predicate 불필요 — 단순 optional chain:

```ts
const e = events.find(ev => ev.kind === 'plant-stage-up');
expect(typeof e?.at).toBe('number');
```

**C-2: legacy/pre-migration field 접근** (user-migration.spec.ts × 3 + state-user.spec.ts × 1 + validate-interest-id.spec.ts × 1 + migration-v4.spec.ts × 2 + migration-v5.spec.ts × 1 + migration-v7.spec.ts × 1)

```ts
const v2 = migrateUserToV2(v1);
expect((v2 as any).level).toBeUndefined();
```

여기서 `level`은 schema에서 **제거된** 필드. `as any`보다 `as unknown as Record<string, unknown>` 또는 `as Record<string, unknown>` 사용:

```ts
expect((v2 as unknown as Record<string, unknown>).level).toBeUndefined();
```

`Record<string, unknown>`은 lint rule을 통과하면서 의도 (deprecated field 부재 확인)를 정확히 표현.

`makeV6Base(): any` → `function makeV6Base(): Record<string, unknown>` 또는 unknown.

#### 패턴 D — 2 errors (innerHTML = '')

```ts
beforeEach(async () => {
  localStorage.clear();
  sessionStorage.clear();
  document.body.innerHTML = '';   // ← lint error
});
```

Fix — 다른 spec(plant-detail.spec.ts:9)에서 이미 graduated된 패턴 적용:

```ts
beforeEach(async () => {
  localStorage.clear();
  sessionStorage.clear();
  document.body.replaceChildren();
});
```

`replaceChildren()` (인자 없음) = 모든 child node 제거. innerHTML='' 동등.

**v3.33 T0 사전 review P2-5 명시**: 본 사이클 scope은 **lint-triggering 2건만**. 기존 `eslint-disable`된 innerHTML 케이스 (의도된 HTML rendering 검증 등)는 out-of-scope — 정책상 정당한 사용.
