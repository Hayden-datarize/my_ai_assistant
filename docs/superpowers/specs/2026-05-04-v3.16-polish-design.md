## §3. 변경 항목 (단위/경계)

각 항목은 단일 task로 구성. 파일 경로는 spec 단계에서 best-effort, plan 단계 T0/T1에서 grep으로 정확 line 번호 pin.

### C1 (P1-1) — briefings memo→scrap order catch-up

**경계**: `src/state/briefings.ts` memo toggle + scrap toggle path (live).
**정책 (backfill 기준)**: 식물 카운트는 (스크랩된 briefing) + (스크랩된 briefing의 memo) 합계.
즉 memo는 **briefing이 스크랩 상태일 때만** 카운트.
**문제 (Codex final P1-1, 1차 REJECT 기록)**: live memo path는 이미 `if (briefing.scrap)` 가드가 있어 비스크랩 briefing의 memo는 emit 안 함 (정책 일치). 단, **memo 먼저 작성 → 나중에 scrap ON 토글** 케이스에서 scrap 토글 path가 기존 memo 존재를 무시하고 scrap 1건만 emit → memo 1건 **catch-up 누락 (undershoot 1)**.
**수정**: scrap 토글 ON path에서 `if (!prev.scrap && next.scrap && briefing.memo)` 시 `tickPlantActivity('memo')` catch-up 추가 emit. memo toggle path는 변경 없음.
**위험**: low — atomic sweep 영역, v3.15 T16.1 saveOk 패턴 재사용 (memo + scrap 2회 emit이 sweep 1회 saveUser에 묶이도록).
**테스트**: `tests/state/briefings*` 신규 case — (a) 비스크랩 + memo only → 0 (b) **memo 먼저 → scrap ON → memo +1 + scrap +1** (catch-up 검증, 핵심) (c) scrap 먼저 → memo 추가 → memo +1 (기존 동작 유지) (d) scrap OFF 토글 → catch-up 없음 (regression guard).

### C2 (P2-1) — garden-mini DOM id 중복 제거

**경계**: `src/ui/components/garden-grid.ts` 또는 home 마크업 (index.html / home renderer).
**문제**: `id="gardenMini"` outer placeholder + inner row가 동일 id를 가져 HTML invariant 위반. `getElementById` selector 충돌 가능.
**수정**: outer는 class만 (`.dg-garden-mini` 또는 기존 class), inner는 id 유지 (또는 vice versa — grep으로 외부 reference 측 확인). 단일 querySelector 영역.
**위험**: trivial — 단일 selector 영역, 외부 reference grep 필수.
**테스트**: 기존 garden-mini 렌더 spec PASS 유지 + 신규: id 유일성 assertion (DOM `getElementsByTagName` count).

### C3 (P2-2) — welcome-garden Escape listener cleanup

**경계**: `src/ui/modals/welcome-garden.ts` (open/close path).
**문제**: 모달 open 시 `document.addEventListener('keydown', escHandler)` → backdrop click / 버튼 close path에서 `removeEventListener` 누락 → 모달 inactive 상태에서 ESC 무효 listener 잔존.
**수정**: `AbortController` 패턴 (open 시 controller 생성 → close 시 `controller.abort()`) 또는 명시 `removeEventListener(close path 모두에서)`. AbortController 권고 (단일 cleanup 보장).
**위험**: low — modal lifecycle invariant.
**테스트**: 신규 unit — open → close (버튼) → ESC press → handler 미호출 assertion. (반복 open/close 시 listener 1개만 유지 verify.)

### C4 (P2-3) — backfillGarden memo undefined guard

**경계**: `src/state/backfillGarden.ts` memo loop.
**문제**: `b.memo.trim()` 호출 시 `b.memo`가 `undefined` 가능 (loose casting / legacy briefing record).
**수정**: `if (b.memo && b.memo.trim()) { ... }` 또는 optional chaining `b.memo?.trim()` 후 truthy 체크.
**위험**: trivial.
**테스트**: 기존 backfill spec에 memo undefined fixture 1건 추가.

### C5 — bundle trim Standard

**경계**: `src/ui/components/garden-grid.ts` + `src/state/plantCatalog.ts` + `src/utils/*` (미사용 helper).
**목표**: -0.5~-0.7 kB CLI gzip (34.28 → 33.6~33.8 kB).
**수정 후보** (plan T5에서 측정 후 선택):
1. **INTEREST_LABEL 중복 dedup**: garden-grid가 별도 label literal 보유 시 `categories.ts` import.
2. **Plant emoji 인라인 정리**: catalog `🌱🌿🌳🌸🌟` 중복 literal → 단일 const map.
3. **미사용 helper sweep**: `src/utils/*` ts-prune 또는 grep으로 0-reference export 제거.
4. **CSS dead rule** (선택): garden-grid CSS `.placeholder--*` 등 미사용 rule.

**위험**: medium — visual regression 가능. T0 baseline diff + per-task spec compliance reviewer + smoke render 확인 필수.
**테스트**: 기존 garden-grid render spec + smoke PASS, 신규 회귀 spec 1~2건 (label 정확성).

### C6 — layout flake 진단 + bounded fix

**경계**: `tests/smoke/layout.spec.ts` (또는 `desktop-layout.spec.ts`, T6에서 confirm).
**문제**: pre-existing intermittent flake (v3.14.4 cold-start, v3.15 T16/T16.1에서 1회씩).
**작업**:
1. **Repro**: N=10 cold-start (`pnpm exec playwright test tests/smoke/layout.spec.ts --repeat-each=10`).
2. **Diagnose**: frequency 측정 → root cause 가설 (timing race / spec drift / env / fixture).
3. **Fix estimate**:
   - 1 task budget (≤4시간) 내 가능 → in-cycle fix + N=5 5/5 verify.
   - 초과 → **escape valve**: (A) diagnose-only로 격하, root cause 가설 1줄 + repro 명령을 `project_daily_growth_v316.md` 메모리에 기록, v3.17 carry-forward.
**위험**: medium — flake가 timing race면 fix 자체가 unstable 가능.
**테스트**: 진단 결과에 따라 in-cycle 추가 (timing → wait/await 강화, spec drift → fixture sync).
