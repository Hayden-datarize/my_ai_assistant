## §2. T2 — C7 Firebase API Key GCP Referrer 절차

### 2.1 Finding 요약

Firebase Web API key는 client-side public (정상 설계)이지만, GCP Credentials에서 **HTTP referrer 제한 미설정** 상태. 외부 abuser가 key 추출 후 본인 도메인에서 Firebase services 호출 가능 → 할당량 도용, Functions/Hosting 비용 발생.

v3.41 T1 (App Check Phase A) 자가 진단에서 carry-forward로 분류.

### 2.2 결정 — 절차 문서 + 검증 script (코드 변경 0)

사용자는 비개발자 (HR/GA) — GCP Console step-by-step 절차 + 검증 script 둘 다 필요. referrer 잘못 설정 시 production block (blast radius H). 검증 우선 강조 패턴.

**T2 진입 시 선행 실측 (의무)**:

1. **Production endpoint 인벤토리**: Daily Growth가 Firebase Web API key를 실제로 reference하는 endpoint 목록 (예: Functions `httpsCallable`, Firebase Hosting setup, App Check token 발급 등). `src/` grep + `firebaseConfig` import sites 확인.
2. **GCP referrer 제한 적용 범위 검증**: 해당 endpoint들이 GCP API key restrictions의 "Website restrictions"에 영향받는지 확인. Firebase Auth / Firestore 미사용 시 referrer 제한 ROI 재평가.
3. **결과에 따른 spec 조정**:
   - Effective endpoint 있음 → §4 검증 script에 해당 endpoint 사용
   - 적용 범위 없음 → 절차 문서 §1 "Why"를 "App Check 대체가 아닌 안전망" 강조로 조정, ROI 노트 추가
   - 둘 다 미달 시 → T2 abort + v3.44 carry로 강등 (controller 판단)

**신규 디렉토리 + 파일**:
