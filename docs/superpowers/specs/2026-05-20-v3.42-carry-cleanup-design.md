## §2. T2 — C3 polish flake (disabled button pointer-events) (S~M)

### 2.1 Finding

`tests/smoke/polish.spec.ts:77` — `.btn` 첫 element에 `disabled` 속성 설정 후 `getComputedStyle().pointerEvents` 체크. 1차 run fail (`'auto'`), 2차 PASS. CSS rule (`buttons.css:20`)은 정상.

### 2.2 가설

1. `document.querySelector('.btn')` 첫 element가 onboarding 단계 vs main app 단계에 따라 다름 (DOM race)
2. 또는 `btn.setAttribute('disabled', '')` 직후 `:disabled` pseudo-class evaluation 즉시 반영 안 됨 (브라우저 layout flush 미실행)

### 2.3 결정

- selector를 **항상 존재하는 stable element**로 변경 — `body` 안의 첫 onboarding/home `.btn` 대신 **명시적 stable element 사용**. 후보: `seedUser(page)` 후 home에 항상 존재하는 button (예: `'.archive-tab .btn'` 또는 `#archiveBulkDelete` — `<button>` 직접)
- 추가 안전망: `disabled` 속성 set 후 `void btn.offsetHeight` (force reflow) 후 `getComputedStyle` 호출

### 2.4 변경

- `tests/smoke/polish.spec.ts`:
  - selector를 stable한 `button.btn` 또는 명시적 ID로 변경
  - reflow trigger 추가

### 3.3 변경

- `src/services/slack.ts`: top-level import 제거 + 함수 내부 dynamic import

- 기존 vitest mock (`vi.mock(appCheck)`) 정합 확인
