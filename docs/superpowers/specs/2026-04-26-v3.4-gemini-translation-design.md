# v3.4 Gemini Translation — Design Spec

**Date**: 2026-04-26
**Branch**: `feat/v3.4-gemini-translation` (TBD)
**Scope**: 영문 RSS 카드의 한글 자동 노출(제목) + on-demand 요약/직역(본문) + 비용 안전망
**Base commit**: `fade513` (main, v3.3.4.3 merge)
**Target TS**: es2020 (프로젝트 기본값)

---

## 1. 배경

- v3.3 시리즈 + v3.3.4.3 P2 cleanup 완결 (`fade513`). 차기 사이클로 v3.4(Gemini 확장) vs v3.5(폴리시/URL 통일) 중 사용자가 **v3.4 선택**.
- 페인포인트: 영문 RSS 소스(TechCrunch 등)가 한국어 화자에게 인지 부담. 카드뉴스 훑기 흐름이 끊김.
- CLAUDE.md AI API 비용 정책: 1순위 `gemini-3.1-flash-lite-preview` / 2순위 `gemini-2.5-flash` / 3순위 Claude API.
- 기존 인프라: `src/services/gemini.ts` (모델 `gemini-2.5-flash-lite` 하드코딩, `parseJsonText` 헬퍼 보유), API key는 `dg_gemini_key` localStorage에 영구 저장 (onboarding/settings/home 공통).

## 2. 범위 (In-Scope)

- 영문 카드 자동 감지 (제목 + description의 한글 글자 휴리스틱)
- **자동 제목 번역** (RSS fetch 직후 background queue, 비동기 in-place swap)
- **On-demand 본문 요약 또는 직역** (인라인 토글)
- 일일 사용량 캡 + 자동 차단 (기본 100건)
- 캐싱 (`Briefing` 객체에 inline, 기존 briefing 보존 정책 따름)
- 모델 fallback (1순위 → 2순위, rate-limit/network 에러 한정)
- 설정 화면 확장 (한도 슬라이더 + 오늘 사용량 + 캐시 초기화 버튼)

## 3. 범위 외 (Out-of-Scope)

- **한글 → 영문 번역** (반대 방향)
- **일본어/중국어/기타 언어** 처리 → 휴리스틱에서 `'unknown'` 분류, 토글 비노출
- **사용자 override UI** (자동 감지만 시작; v3.5+에서 피드백 보고 추가 검토)
- **재번역 옵션** — 캡 우회 수단이 됨, YAGNI
- **기존 `services/gemini.ts` 모델 align** — 별도 사이클 (사용자 정책: "요청받은 것만 변경")
- **Full article fetch** — CORS 회피, RSS description만 사용
- **Claude API (정책 3순위)** — v3.4에선 안 씀, 1·2순위 fallback만

## 4. 브레인스토밍 결정 사항 요약

| # | 영역 | 결정 |
|---|---|---|
| 1 | 트리거 | 하이브리드 (제목 자동 + 본문 on-demand) |
| 2 | 언어 감지 | 자동 (한글 글자 우선 + ASCII 보조) |
| 3 | 결과물 | 한글 요약 3~4줄 (description ≤80자면 1:1 직역으로 fallback) |
| 4 | 비용 안전망 | 일일 캡 + 자동 차단 (기본 100건, 사용자 30~500 조정) |
| 5 | UI | 카드 내부 인라인 토글 |
| 6 | 모델 | 1순위 → 2순위 자동 fallback (rate-limit/network only) |

## 5. Architecture & Data Flow

### 5.1 새 파일 (4개)

| 파일 | 역할 |
|---|---|
| `src/utils/lang.ts` | `detectLanguage(title, description?): 'en'\|'ko'\|'unknown'` |
| `src/services/translate.ts` | `translateTitle()`, `summarizeOrTranslateBody()`, 모델 fallback 로직 |
| `src/state/usage.ts` | 일일 카운터 — localStorage `dg_translate_usage` |
| `src/ui/components/cardLangToggle.ts` | 인라인 토글 컴포넌트 (DOM 생성 + wiring) |

### 5.2 기존 파일 수정 (3개)

| 파일 | 변경 |
|---|---|
| `src/state/briefings.ts` | `Briefing` 타입에 `detectedLang?`, `titleKo?`, `summaryKo?` 추가. 기존 `mutate()` 패턴 재사용해 atomic write |
| `src/ui/handlers/home.ts` | 카드 렌더 시 한글 우선 표시 + 토글 wiring + background queue trigger (RSS fetch 후) |
| `src/ui/tabs/settings.ts` | 새 섹션 "Gemini 번역" — 슬라이더 + 사용량 + 캐시 초기화 |

### 5.3 Data flow

```
[RSS fetch (services/rss.ts)]
   │
   └─ home.ts: 카드 즉시 렌더 (영문 제목 그대로)
        │
        └─ background queue 시작
             ├─ 영문 카드만 필터 (lang.ts: detectLanguage)
             ├─ in-flight Set<briefingId>로 중복 dispatch 방지
             ├─ 동시 3 호출 + 200ms delay (rate-limit 회피)
             └─ for each:
                  · usage.ts: 캡 미도달 + apiKey 있음 확인
                  · translate.ts: translateTitle()
                  · 1순위(gemini-3.1-flash-lite-preview) 시도
                       ├─ 429/503/network → 2순위(gemini-2.5-flash)
                       └─ 4xx → 즉시 실패 (401이면 세션 차단)
                  · 결과 → briefings.ts: mutate() 패턴으로 titleKo 저장
                  · 카드 DOM 텍스트 in-place 교체 (transition 없음)

[사용자가 "🌐 한글 요약" 토글 클릭]
   │
   └─ cardLangToggle.ts:
        · summaryKo 캐시 있음 → 즉시 swap, 호출 0
        · 없음 → translate.ts: summarizeOrTranslateBody()
             ├─ description ≤ 80자: 1:1 직역
             └─ > 80자: 3~4줄 요약
        · 결과 → mutate() 캐시 → swap
        · e.stopPropagation()으로 카드뉴스 swiper 페이지 변경 방지
```

### 5.4 언어 감지 휴리스틱 (`lang.ts`)

1. `title + ' ' + (description ?? '')` 합쳐 검사
2. 한글 글자(`[가-힣]`) **1자 이상** → `'ko'`
3. 한글 0자 + ASCII letter (`[A-Za-z]`) **50% 이상** → `'en'`
4. 그 외 → `'unknown'` (토글 비노출, 안전 default)

**근거**: 단순 ASCII 비율은 "MIT 입학" 같은 한글 다수 카드를 EN 오판. 한글 글자 우선이 한국 매체 false positive 방지에 효과적.

### 5.5 요약 vs 직역 분기 (`translate.ts`)

```
summarizeOrTranslateBody(description, apiKey):
  if description.length <= 80:
    prompt = "다음 영문을 한국어 해요체로 자연스럽게 번역. JSON: {\"text\":\"...\"}"
  else:
    prompt = "다음 영문 본문의 핵심을 한국어 해요체 3~4줄로 요약. JSON: {\"text\":\"...\"}"
  text = description.slice(0, 1500)  // 입력 토큰 cap (방어적)
  ...
```

**근거**: description이 짧으면 "요약"이 의미 없음. 1:1 직역도 충분히 유용. 단일 함수에서 분기, 호출 측은 동일 인터페이스.

### 5.6 모델 fallback (`translate.ts`)

```
async function callWithFallback(apiKey, prompt):
  for model in ['gemini-3.1-flash-lite-preview', 'gemini-2.5-flash']:
    try:
      return await callGemini(model, apiKey, prompt)
    catch err:
      if err.status in [429, 503] or err.isNetwork:
        continue  // 다음 모델로
      if err.status == 401:
        markSessionBlocked()
        throw err
      throw err  // 400/403 → 즉시 실패
  throw new Error('all models failed')
```

### 5.7 일일 캡 (`usage.ts`)

```ts
interface Usage { date: string; count: number; }
const KEY = 'dg_translate_usage';
const SETTINGS_KEY = 'dg_translate_cap';  // 기본 100, 30~500

function checkAndIncrement(): boolean {
  const today = getDateStr();
  const cap = readCap();
  const u = load() ?? { date: today, count: 0 };
  if (u.date !== today) { u.date = today; u.count = 0; }  // midnight reset
  if (u.count >= cap) return false;
  u.count += 1; save(u);
  return true;
}
```

**호출 단위**: 1 API 호출 = 1 카운트 (제목/본문 동등). 토큰 기반 X (사용자 인지 단순함 우선).

### 5.8 Background queue (`home.ts` 또는 별도 모듈)

**트리거 시점**: `services/rss.ts`의 RSS fetch가 끝나고 `home.ts`에서 카드 DOM이 렌더된 직후 자동 호출. 사용자 명시 액션(refresh 버튼)에서도 동일하게 trigger.

```
class TranslateQueue:
  - inFlight: Set<string>  // briefingId
  - pending: Briefing[]
  - MAX_CONCURRENT = 3
  - DELAY_MS = 200

  enqueue(briefings):
    for b in briefings:
      if b.detectedLang === 'en' && !b.titleKo && !inFlight.has(b.id):
        pending.push(b); inFlight.add(b.id)
    process()

  process():
    while running < MAX_CONCURRENT and pending.length:
      b = pending.shift(); running++
      after DELAY_MS:
        try: titleKo = await translateTitle(b.title, apiKey)
             updateBriefingTitleKo(b.id, titleKo)
             swapDOM(b.id, titleKo)
        catch: silently fail (toast collapse)
        finally: running--; inFlight.delete(b.id); process()
```

### 5.9 캐싱 정책

- `titleKo` / `summaryKo`는 `Briefing` 객체에 inline 저장
- **별도 만료 정책 없음** — `briefings` 자체에 만료/회전 로직이 현재 없음(`src/state/briefings.ts` 확인). 따라서 `*Ko` 필드도 briefing이 살아있는 동안 유지
- 사용자가 "캐시 초기화" 누르면 모든 briefing의 `*Ko` 필드만 삭제 (briefing 자체는 유지)

**근거**: localStorage 한도(5MB)는 카드당 ~500B × 수천 개 = 약 1MB 미만, 위협 안 됨. 만약 향후 briefings 누적이 큰 문제가 되면 별도 사이클에서 briefings 자체에 회전 정책 도입(이번 사이클 범위 외).

### 5.10 마이그레이션 (기존 사용자 호환)

- 기존 `Briefing` 객체에 `detectedLang` 등 신규 필드 없음 → optional 타입
- **별도 batch 마이그레이션 X** — 카드 render 시점에 lazy detection (한 번 렌더되면 캐시)
- 새 RSS refresh 사이클부터 background queue가 자동 채움

## 6. UI/UX

### 6.1 인라인 토글 (`cardLangToggle.ts`)

- 영문 카드 (`detectedLang === 'en'`) 본문 영역 위에 작은 버튼
- 라벨: `🌐 한글로 보기` ↔ `🌐 영문으로 보기` (state에 따라 toggle).
  - "요약"이 아닌 "한글"이라 표현한 이유: description ≤ 80자에선 직역이라 "요약" 표현이 부정확. 일반화된 라벨로 통일.
- `aria-label`도 동기화. 비활성 시 `aria-disabled="true"` + 시각 dim
- 캡 도달 시 비활성 + 툴팁 "오늘 한도 도달"
- API key 미입력(`dg_gemini_key` 빈 값/없음) 시 **비노출**
- 토글 클릭 시 `e.stopPropagation()`로 swiper 페이지 변경 방지 (v3.3.3 카드뉴스 동작 보존)

**구현 단계 deviation 기록 (in-cycle review)**: 본 사이클 구현에서 토글 위치를 카드 본문 영역 위가 아닌 카드 우상단 absolute pill로 채택. 사유: full-bleed 카드뉴스 layout에서 인라인 위치가 본문 흐름을 끊고 swiper page change 충돌 위험. top-right pill은 발견성 + 카드 흐름 보존 + 클릭 영역 명확. CSS는 `.briefing-card .card-lang-toggle { position: absolute; top: 12px; right: 12px; }` 패턴. v3.4.1+에서 사용자 피드백 기반 재검토 가능.

### 6.2 자동 제목 swap

- RSS fetch 끝나면 카드 즉시 렌더 (영문 제목 그대로 노출, 사용자 대기 없음)
- background queue가 영문 카드만 골라 `translateTitle()` 호출
- 결과 도착 시 in-place DOM 텍스트 교체 (transition 없음, 깜빡임 최소)
- 실패한 카드는 영문 제목 유지 (자동 재시도 X)

### 6.3 설정 화면 추가 (`settings.ts`)

- **위치**: 기존 Gemini API key 입력 영역 아래 새 섹션 "Gemini 번역"
- **항목**:
  - 일일 한도 슬라이더: 30~500, 10단위 step, 기본 100, label "일일 번역 한도"
  - 오늘 사용량 텍스트: "오늘 N건 사용 (한도 100)" — 슬라이더 변경 시 즉시 갱신
  - 캐시 초기화 버튼: "번역 캐시 초기화" → confirm 모달 → 모든 `*Ko` 필드 삭제

### 6.4 토스트 메시지 (`role="status"` + aria-live)

| 상황 | 메시지 |
|---|---|
| 캡 도달 | "오늘 번역 한도(N건)에 도달했어요. 내일 자정에 재개됩니다." |
| 401 (key 무효) | "API 키가 유효하지 않아요." + 설정 이동 링크 |
| 429/503/network | "잠시 후 다시 시도해주세요." (세션당 동일 메시지 1회만) |

### 6.5 에러 토스트 collapse

- `lastShownError: string | null` 세션 단위 캐싱
- 같은 메시지 재발 시 토스트 skip (스팸 방지)
- 사용자가 다른 액션(설정 변경 등) 후 reset

## 7. 비용 추정

영문 카드 일일 ~20개 가정:

| 항목 | 호출 | 토큰 (입+출) |
|---|---|---|
| 자동 제목 번역 | ~20 | ~100 each |
| On-demand 본문 요약 | ~5~10 | ~500 each |
| **합계** | ~25~30/일 | |

→ 캡 100건의 약 30% 사용 수준. 캡 도달 가능성 낮음.

**비용 절대치 주의 (할루시네이션 가능성)**: Gemini 1순위 모델(`gemini-3.1-flash-lite-preview`)의 정확한 단가는 preview 단계라 변동 가능. 본 spec에서는 절대 비용 수치를 추정하지 않고 "캡 100건이 일반 사용에 충분"이라는 상대적 판단만 명시. 실측은 v3.4 배포 후 1주일 사용량 카운터로 확인.

## 8. 위험 & 트레이드오프

| 위험 | 완화 |
|---|---|
| Gemini API rate limit (모델·tier별 상이, free tier는 분당 한 자릿수~수십 회로 알려짐 — 정확한 한도는 할루시네이션 가능성 있음) | 동시 호출 3 + 200ms delay로 보수적 처리. 429 응답 시 즉시 2순위 모델 fallback |
| 캡 도달 후 비개발자 혼란 | 명확한 토스트 + 설정 카운터 가시화 |
| description ≤ 80자 임계가 너무 작음 | 1:1 직역도 유용. 임계 조정은 사용자 피드백 기반 v3.5+ |
| Preview 모델(1순위) 불안정 | 자동 fallback to 2순위 |
| localStorage 한도 (5MB) | 카드당 ~500B × 수천 개 ≈ 1MB 미만, 위협 X |
| 한글+영문 혼용 카드 → 한글 우선 분류 → 토글 X | acceptable (한국 사용자 입장에서 자연스러움) |
| 비동기 swap 깜빡임 | transition 없이 in-place DOM 교체 |
| 401 무한 재시도 위험 | 세션 단위 차단 (사용자가 키 수정 시 해제) |

### 9.1 vitest 단위 (+25)

### 9.4 독립 코드 리뷰 (배포 전, 필수)

## 12. 보안 자가 진단

| 항목 | 검토 결과 |
|---|---|
| **XSS (AI 응답 → DOM)** | AI 응답은 `textContent` 또는 `Node.textContent =` 로만 주입. `innerHTML` 절대 사용 금지. 카드 제목/본문 swap 모두 textContent 기반. 구현 시 코드 리뷰에서 재확인. |
| **API key 노출** | Gemini endpoint URL의 `?key=` query param 노출은 기존 `services/gemini.ts:14` 패턴과 동일. HTTPS 전송이므로 transit 안전. localStorage 저장은 사용자 본인 브라우저 — 기존 정책 유지. |
| **prompt injection** | RSS description은 외부 텍스트 → AI prompt에 직접 포함됨. 응답이 JSON 형식 강제이고 결과는 textContent로만 표시되므로, prompt injection으로 사용자 데이터 유출 경로 없음. 단, 응답이 한국어 톤을 벗어나는 정도의 noise는 발생 가능 (UX 영향, 보안 영향 X). |
| **CORS / CSP** | 호출 대상 `generativelanguage.googleapis.com`은 기존 gemini.ts에서 이미 허용. v3.4 추가 호스트 없음. CSP 정책 변경 불필요. |
| **localStorage 무결성** | JSON parse는 try-catch로 감싸 corrupted state에서도 fail-soft (기존 `loadBriefings()` 패턴 따름). |
| **Rate limit 악용 / 비용 폭주** | 일일 캡 + 자동 차단으로 1차 방어. 401 발생 시 세션 차단으로 무한 재시도 방지. |
| **CSRF / SSRF** | client-side만 호출, 서버 X. 해당 없음. |

→ **추가 보안 위험 없음**. 기존 보안 경계와 동일 또는 더 보수적.
