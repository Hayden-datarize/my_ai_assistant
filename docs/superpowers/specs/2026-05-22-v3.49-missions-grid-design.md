# v3.49 — Missions Grid 게임화 (UI 재구성 + game elements)

> 사이클 유형: UI-only(스키마 0). 미션 list → card grid 전환 + 게임화 element 2개(progress ring + 완수 sparkle micro-animation) 의식적 포함. 로직·데이터·schema·이벤트 변경 0.

---

## §1. 배경 / 동기

- v3.18 carry로 누적되어 온 "M3 missions·뱃지 grid 게임화" 항목을 v3.49에서 정리.
- 현재 상태 (탐색 결과):
  - **뱃지(badges)**: stats 탭 안 `badges-grid` (이미 grid, 카테고리별 + detail modal). 26개 catalog, 자동 unlock.
  - **미션(missions)**: 6번째 별도 탭(v3.14 graduate). 기간별 그룹(daily/weekly/monthly) + 수직 `<ul>` **list**. progress는 가로 bar.
- ROI 정합:
  - 뱃지는 이미 grid → 추가 grid 작업 불요.
  - 미션은 list 형태로 visual quest panel 정체성 약함. mobile (≤375px) 한 줄에 `title + bar + count + reward + check`가 답답.
  - v3.14의 missions 탭 분리(stats에서 떼어낸 의도적 graduate)는 유지 — 통합 허브(B안)는 risk 큼.
- → **미션 list → card grid + 게임화 element 2개**. 스코프 최소, 정체성 강화.

## §2. 결정 (선택안)

- **A) 미션을 grid card로 (택)**: list→card grid 전환 + progress ring + 완수 sparkle. schema 0, 로직 0.
- B) 통합 게임화 허브: missions/stats/garden을 한 화면. risk 큼, v3.14 lesson 일부 되돌림 → 기각.
- C) 뱃지 grid 강화: 이미 grid라 ROI 낮음 → 기각.

## §5. UI 변경

### §5.1 마크업 (renderCard / renderGroup)

기간 그룹 헤더는 그대로. 그룹 내부 `<ul>` → grid 컨테이너 `<ul role="list" class="mission-group__grid">`로 변경(클래스만 swap, `<ul>` 의미·a11y 유지).

각 카드:

```html
<li class="mission-card" data-mission-id="..." aria-label="<title>, <progress>/<target>">
  <h3 class="mission-card__title">{escapeHtml(def.text)}</h3>
  <span
    class="mission-card__ring"
    role="img"
    aria-label="진행 {progress}/{target}"
  >
    <svg viewBox="0 0 48 48" width="48" height="48" aria-hidden="true">
      <circle cx="24" cy="24" r="20" class="mission-card__ring-track" />
      <circle
        cx="24" cy="24" r="20"
        class="mission-card__ring-progress"
        stroke-dasharray="{2πr}"
        stroke-dashoffset="{2πr × (1 - p/t)}"
      />
    </svg>
    <span class="mission-card__ring-text">{progress}/{target}</span>
  </span>
  <span class="mission-card__reward">+{rewardXp} XP</span>
  <!-- 완수 시 -->
  <span class="mission-card__check" aria-label="완수">✓</span>
</li>
```

- `escapeHtml` 그대로(현재 적용 중).
- progress=0인 카드는 ring track만(progress circle 0%).
- 완수 카드는 ring 100% 충전 + ✓ overlay (현재 `mission-card--completed` opacity 정책 유지).

### §5.2 정렬

`renderMissionsSection`에서 각 그룹의 missions 배열을 `[...활성, ...완수]` 순으로 sort 후 렌더 (안정 정렬 — index tiebreak). 활성 미션이 first-paint.

### §5.3 Sparkle (게임화 element #2)

- 신규 module `src/ui/missions-sparkle.ts`:
  - `mountMissionsSparkle()` — 1회 호출. `dg:reward:mission-completed` listener.
  - listener payload(`missionDefId`)로 DOM `[data-mission-id="..."]` 카드를 찾아 sparkle emit.
  - **emit-once 가드**: session-scoped `Set<string>` (또는 카드 `data-sparkled="1"` attribute). 이미 sparkle된 미션은 skip — 탭 재진입/리렌더에 재발화 X.
  - `window.matchMedia('(prefers-reduced-motion: reduce)').matches` 시 sparkle 전체 skip.
- CSS:
  - `.mission-card--sparkle` 짧은 scale animation (`1 → 1.05 → 1`, 0.4s `--ease-out-soft`).
  - particle 3개는 단순 `::before`/`::after` + 동적 `<span>` 1개로 처리 — DOM 추가 ≤ 3 element/카드.
  - `@media (prefers-reduced-motion: reduce)`에서 animation `none`.
- `mountMissionsHandlers()` 안에서 `mountMissionsSparkle()` 1회 호출 wiring(idempotent guard 권장 — module-level `wired = true` flag로 중복 listener 방지).
- **sparkle 발화와 grid sort 충돌 회피**: 완수 미션은 emit 직후 정렬에 의해 grid 끝으로 이동하므로, sparkle class를 카드 element가 아니라 **`data-mission-id` 기반으로 재마운트 후에도 일관 유지**할 것. 구현 패턴: (a) sparkle listener는 `missionDefId`를 session-scoped Set에 push, (b) `renderMissionsSection`이 sparkle queue를 소비해 새로 마운트된 카드에 class 부여 후 animation end에 class 제거. emit-once 가드와 자연 정합.

### §5.4 CSS (responsive grid)

```css
.mission-group__grid {
  display: grid;
  grid-template-columns: 1fr;            /* ≤375: 1열 */
  gap: var(--space-2);
  list-style: none;
  margin: var(--space-2) 0 0;
  padding: 0;
}
@media (min-width: 376px) {
  .mission-group__grid {
    grid-template-columns: repeat(2, 1fr);  /* 376–767: 2열 */
  }
}
@media (min-width: 768px) {
  .mission-group__grid {
    grid-template-columns: repeat(auto-fill, minmax(180px, 1fr)); /* ≥768: auto-fill, 미션 적으면 자연 2열 */
  }
}

.mission-card {
  display: grid;
  grid-template-rows: auto 1fr auto;
  justify-items: center;
  gap: var(--space-1);
  padding: var(--space-3);
  border-radius: var(--radius-lg);
  background: var(--surface-1);
  box-shadow: var(--shadow-card);
  position: relative;
}
.mission-card__title  { font-size: var(--font-size-sm); text-align: center; margin: 0; }
.mission-card__ring   { display: inline-flex; position: relative; }
.mission-card__ring-track    { fill: none; stroke: var(--surface-2); stroke-width: 4; }
.mission-card__ring-progress { fill: none; stroke: var(--color-primary-vivid); stroke-width: 4;
                               transform: rotate(-90deg); transform-origin: center;
                               transition: stroke-dashoffset var(--duration-base) var(--ease-out-soft); }
.mission-card__ring-text     { position: absolute; inset: 0; display: grid; place-items: center;
                               font-size: var(--font-size-xs); font-weight: 600; }
.mission-card__reward { font-size: var(--font-size-xs); color: var(--success); font-weight: 600; }
.mission-card__check  { position: absolute; top: var(--space-1); right: var(--space-1);
                        color: var(--success); font-weight: 700; }
.mission-card--completed { opacity: 0.6; }

/* sparkle */
.mission-card--sparkle { animation: mission-sparkle 0.4s var(--ease-out-soft) 1; }
@keyframes mission-sparkle { 0% { transform: scale(1); } 50% { transform: scale(1.05); } 100% { transform: scale(1); } }
@media (prefers-reduced-motion: reduce) {
  .mission-card--sparkle { animation: none; }
  .mission-card__ring-progress { transition: none; }
}
```

(token 이름은 기존 `tokens.css` 확인 후 정합 — 최소 `--surface-1/2`, `--shadow-card`, `--color-primary-vivid`, `--success`, `--ease-out-soft`, `--duration-base`, `--font-size-sm/xs`, `--space-1/2/3`, `--radius-lg`. 부재 시 가까운 토큰 대체.)

기존 list-form CSS(line 230~256)는 grid CSS로 교체. `mission-group / __header / __title / __progress / __chevron`는 유지(헤더는 같은 UX).

## §9. Risk

| Risk | 대응 |
|---|---|
| sparkle이 탭 재진입마다 재발화 | session-scoped Set + `data-sparkled` attribute 이중 가드 |
| ring SVG가 bundle 증가 | inline SVG 1회 + `<use>` 또는 stringified template — 신규 모듈 lazy chunk 흡수 |
| 3열 grid에서 카드 너무 좁음 | ≥768 `auto-fill, minmax(180px, 1fr)` — 미션 적으면 자연 fallback |
| polish 격하 위험 | spec §design intent에 게임화 element 2개 의식 포함 명시(§2 self-critique) |
| reduced-motion 사용자 누락 | sparkle + ring transition 양쪽 `@media` 가드 |
| handlers 호출 인터페이스 변경 | renderMissionsSection 시그니처 유지, caller diff 0 |
| escape 잔여 surface | def.text만 사용자 노출 — 기존 escapeHtml 패턴 유지, def.id는 catalog 정의 ascii |
