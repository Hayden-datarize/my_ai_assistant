## §1. 배경 / 동기

- v3.18 carry로 누적되어 온 "M3 missions·뱃지 grid 게임화" 항목을 v3.49에서 정리.
- 현재 상태 (탐색 결과):
  - **뱃지(badges)**: stats 탭 안 `badges-grid` (이미 grid, 카테고리별 + detail modal). 26개 catalog, 자동 unlock.
  - **미션(missions)**: 6번째 별도 탭(v3.14 graduate). 기간별 그룹(daily/weekly/monthly) + 수직 `<ul>` **list**. progress는 가로 bar.
- ROI 정합:
  - 뱃지는 이미 grid → 추가 grid 작업 불요.
  - 미션은 list 형태로 visual quest panel 정체성 약함. mobile (≤375px) 한 줄에 `title + bar + count + reward + check`가 답답.
  - v3.14의 missions 탭 분리(stats에서 떼어낸 의도적 graduate)는 유지 — 통합 허브(B안)는 risk 큼.
- → **미션 list → card grid + 게임화 element 2개**. 스코프 최소, 정체성 강화.

## §5. UI 변경

### §5.1 마크업 (renderCard / renderGroup)

기간 그룹 헤더는 그대로. 그룹 내부 `<ul>` → grid 컨테이너 `<ul class="mission-group__grid">`로 변경(클래스만 swap, `<ul>`은 HTML5에서 implicit `role=list`이므로 explicit 명시 불요).

> v2 정정 (Codex 사전 review P2-1): plan과의 일치를 위해 `role="list"` explicit 제거. HTML5 `<ul>`은 implicit `role=list`. 단 CSS `list-style: none` 적용 시 일부 브라우저(특히 macOS Safari VoiceOver)에서 implicit role을 제거할 수 있다는 보고가 있으므로 implementer가 필요 시 explicit 부착 결정.

각 카드:

```html
<li class="mission-card" data-mission-id="..." aria-label="<title>, <progress>/<target>">
  <h3 class="mission-card__title">{escapeHtml(def.text)}</h3>
  <span
    class="mission-card__ring"
    role="img"
    aria-label="진행 {progress}/{target}"
  >
    <svg viewBox="0 0 48 48" width="48" height="48" aria-hidden="true">
      <circle cx="24" cy="24" r="20" class="mission-card__ring-track" />
      <circle
        cx="24" cy="24" r="20"
        class="mission-card__ring-progress"
        stroke-dasharray="{2πr}"
        stroke-dashoffset="{2πr × (1 - p/t)}"
      />
    </svg>
    <span class="mission-card__ring-text">{progress}/{target}</span>
  </span>
  <span class="mission-card__reward">+{rewardXp} XP</span>
  <!-- 완수 시 -->
  <span class="mission-card__check" aria-label="완수">✓</span>
</li>
```

- `escapeHtml` 그대로(현재 적용 중).
- progress=0인 카드는 ring track만(progress circle 0%).
- 완수 카드는 ring 100% 충전 + ✓ overlay (현재 `mission-card--completed` opacity 정책 유지).

### §5.2 정렬

`renderMissionsSection`에서 각 그룹의 missions 배열을 `[...활성, ...완수]` 순으로 sort 후 렌더 (안정 정렬 — index tiebreak). 활성 미션이 first-paint.

### §5.3 Sparkle (게임화 element #2) — event-based queue 패턴

> **v3 정정 (Codex 사전 review P1-1)**: repo에 `dg:reward:mission-complete` 이벤트가 이미 존재(`src/ui/events.ts:44~45`, `src/state/achievements.ts:128/189`). false→true 전환 + 새 instance 즉시 완수 모두 emit. **render diff 패턴은 reload 시 persisted completed 미션 sparkle false-positive risk** → event-based queue로 재설계. 이벤트 emit·schema 변경 0, listener 1건 추가.

- 신규 module `src/ui/missions-sparkle.ts`:
  - module-level `sparkleQueue: Set<string>` + `listenerWired: boolean`.
  - export `mountMissionsSparkleListener(): void` — 1회 호출(idempotent). `on('dg:reward:mission-complete', ({ defId }) => sparkleQueue.add(defId))` listener 등록.
  - export `consumeSparkleQueue(): Set<string>` — 현재 queue를 반환하고 new Set으로 교체(소비 1회).
  - export `isReducedMotion(): boolean` — `window.matchMedia('(prefers-reduced-motion: reduce)').matches`.
  - **테스트 hook**: `__resetSparkleState()` (queue 비우기 + listenerWired=false).
- wiring: **`registerMissionsListeners()`**(`src/ui/handlers/missions-listeners.ts`)에서 `mountMissionsSparkleListener()` 1회 호출 — production boot 경로(`main.ts:registerCoreHandlerListeners`). (v3.49 T5 Codex 최종 P1 정정: 초안의 `mountMissionsHandlers()`는 dead code path — production caller 없음.)
- `renderMissionsSection(root, active)` 내부에서:
  1. `consumeSparkleQueue()` 호출 → 새로 완수된 미션 Set 획득.
  2. `[...active].sort((a, b) => Number(a.completed) - Number(b.completed))` 안정 정렬(JS Array.sort ES2019 stable).
  3. renderCard에서 `data-mission-id` 부착. 정렬된 순서로 mount.
  4. mount 직후 `root.querySelectorAll<HTMLElement>('.mission-card[data-mission-id]').forEach(el => { if (sparkleSet.has(el.dataset.missionId!) && !isReducedMotion()) { el.classList.add('mission-card--sparkle'); el.addEventListener('animationend', () => el.classList.remove('mission-card--sparkle'), { once: true }); } })`.
- CSS:
  - `.mission-card--sparkle` 짧은 scale animation (`1 → 1.05 → 1`, 0.4s `--ease-out-soft`).
  - particle은 `::before` + `::after` 2개로 처리 (DOM 추가 0).
  - `@media (prefers-reduced-motion: reduce)`에서 `.mission-card--sparkle { animation: none; }` (방어 — JS 가드 이중 보완).
- **sparkle/sort 충돌 회피 자연 정합**: queue 소비는 정렬보다 먼저, class 부착은 mount 이후. 정렬과 무관 동작.
- **reload 안전성**: 페이지 reload 후 queue 비어있음 → persisted completed 미션은 sparkle 발화 X. event-based의 본질적 정합.
- **carry (v3.50+)**: composite key `${period}:${defId}:${windowStart}` (P2-3 — period rollover edge에서 같은 defId 재완수 시 강건성. 현재 단순 defId로 충분, 비목표).

### §5.4 CSS (responsive grid)

```css
.mission-group__grid {
  display: grid;
  grid-template-columns: 1fr;            /* ≤375: 1열 */
```
