## §1. Scope & Goals

### 1.1 배경
v3.17 retro에서 **carry-forward 13건 4 그룹**을 v3.18 backlog seed로 명시(commit `db71195`).
v3.17이 UI revamp(B2 강도) + carry-forward 4 동시 처리로 사이클 사이즈가 컸고, 13건의 hygiene 잔존분이 누적된 상태. v3.18은 이 13건을 단일 cleanup 사이클로 일괄 소진하여 코드베이스를 hygiene 정체성으로 정리하고, v3.19 신규 기능(식물 detail modal / Streak Freeze 등)을 깨끗한 상태에서 시작할 수 있게 한다.

### 1.2 목표
- **carry-forward 13건 PASS** (4 그룹 모두 in-cycle 처리).
- **신규 기능 0 / Schema 변경 0** — hygiene 정체성에 충실.
- **번들 net negative** (cleanup 사이클이 부수 효과로 자연 회수, v3.15 hard cap +0.43 누적의 점진 회복).
- **smoke 안정성 강화** — T8 layout cold-fork flake 본질 fix.

### 1.3 비목표 (out-of-scope)
- **신규 기능** — 식물 detail modal / Streak Freeze / max stage ambient / 답변 편집 / 새 미션 / 새 뱃지 / 새 식물 catalog. **모두 v3.19+**.
- **새 화면 / 새 모달 / 새 탭** 없음.
- **Schema 변경** — user v4 유지, migration 신규 0줄.
- **게임 catalog 데이터 변경** — 식물 15 ID / 뱃지 18 / 미션 5+2+1 그대로.
- **CSP 정책 변경** 없음.
- **신규 dependency** 없음.

### 1.4 정책 (REJECT / 신규 기능 / P0 회귀)
- **신규 기능 금지** — 본 사이클은 hygiene 전용. UI revamp, 모달 추가, 새 화면 모두 v3.19+.

- **리뷰 final REJECT 시 in-cycle hotfix만 허용** (v3.15 T16.1 / v3.13 T10 패턴) — 신규 기능 추가 금지.

- **G4-3** v3.17 T3 regex tightening (heatmap snapshot regex 너무 broad → 의도 외 fixture 통과 가능성)

**총 13건** (5+3+2+3 = 13).

- **신규 vitest spec N=5 5/5** (T1 token cleanup / T4 today combo / T5 markup-layer focus 중심).
- **Playwright smoke 97/97 유지** — T7 layout flake fix 시 신규 회귀 가드 spec +0~+2 가능, **95 미만 fail**.
- **번들 측정** (`gzip -c dist/assets/index-*.js | wc -c` canonical):
  - **목표 net −300~−500 B** (34894 → 34394~34594).
  - **hard fail**: net +200 B 초과 (cleanup 사이클 정체성 위배).
  - **soft AMBER**: net 0~+200 B (그룹 1 자연 회수 부족 — retro에 원인 기록).
- **사전 + 최종 review 모두 P0=0** (P1 in-cycle, P2 → v3.19 backlog).
- **다크 모드 수동 1회 cycle** — home/stats/archive/settings 시각 + 그룹 2-2 luminance 회복 검증.

## §6. 리뷰 게이트

CLAUDE.md "배포 전 독립 코드 리뷰" 표준 리뷰 정책 (4~10 commits, 기능 추가/수정) 적용. 본 사이클 commit 추정 10~16이지만 cleanup hygiene이고 되돌리기 어려운 작업 없음 → **표준 리뷰 + per-task review 강도**.

### 6.1 사전 review (spec + draft plan 단계)
- **시점**: T0(plan 작성) 직후, T1 진입 전.
- **subagent**: `superpowers:code-reviewer` (Codex CLI 권한 가능 시 병행 fallback).
- **입력**: 본 spec(`docs/superpowers/specs/2026-05-05-v3.18-cleanup-design.md`) + draft plan.
- **분류**: P0/P1/P2 → **P0/P1 in-cycle 반영**, P2는 plan 항목으로 추가 또는 v3.19+ backlog.

### 6.2 최종 review (배포 게이트)
- **시점**: T8 (bundle 측정 + verification) 완료 후, 사용자 "배포해줘" 명시 직전.
- **subagent**: `superpowers:code-reviewer`.
- **입력**: 모든 task commit (T1~T7) + 빌드 결과 + 번들 측정 + smoke N=10 결과.
- **분류**: `DEPLOY_APPROVED` / `APPROVED_WITH_NOTES` / `REJECT`.
- **REJECT 시**: §1.4 정책 — in-cycle hotfix만 허용, 신규 기능 추가 금지 (v3.15 T16.1 패턴).

### 6.3 per-task review
- 각 task commit 직후 `pr-review-toolkit:code-reviewer` 또는 task-by-task subagent dispatch (표준 사이클 패턴).
- **추정 dispatch 횟수**: 7~10회 (task 7 + 발견 시 fix 0~3 in-cycle).
- minor 발견은 in-cycle 흡수 / 격하 / 백로그 (v3.14 graduation 패턴).
