## 1. 배경 / 동기

v3.3 시리즈(완결)와 v3.4(Gemini 번역) 사이클에서 누적된 P2 backlog 12건과 신규 폴리시 후보 4건을 한 사이클에 정리한다 (총 16건). 사이클 이름의 "URL 통일"은 v3.3.4 review의 **B1 (read/write URL validation 비대칭 해소)** 가 핵심이고, "i18n Lite"는 **305개 분산 한국어 문자열 중 highest-frequency 4~5개 메시지를 통합**하는 폴리시 작업이다. Full i18n 시스템 도입은 별도 v3.6 후보로 분리.

내역:
- P2 backlog 12건 = A2/A3/F1(v3.4 잔존 3) + B1/B2/B4/B5(v3.3.4 closing 4) + C1/C2/C3(v3.3.4.3 stats 3) + D1/D2(pre-existing flake 2)
- 신규 폴리시 4건 = F2(loadUser dedup) + F3(isoKey 폐기) + F4(waitForTimeout 제거) + i18n Lite messages.ts

본 사이클은 폴리시 성격이라 risky operation(DB migration, auth boundary, data destruction) 없음. 단 commit 수가 ~12이고 cross-file 변경 多 → 글로벌 CLAUDE.md 규칙에 따라 **독립 심층 리뷰** 1회 적용.

## 2. 스코프 (16건)

### 2.1 URL 통일 (1건) — 본 사이클의 핵심

**B1. `isHttpsUrl` 공유 helper 도입**

현황 (검증 완료):
- `src/state/briefings.ts:20` — `isValidImageUrl(v)` = `typeof v === 'string' && /^https:\/\//i.test(v)` (regex)
- 다른 read-side URL validation 없음
- 이미지 imageUrl 외에도 `link` 필드(브리핑 원문 URL) 등 untrusted localStorage 입력은 검증 없이 통과 중

목표:
- `src/utils/url.ts` 신규 — `isHttpsUrl(value: unknown): value is string` export
- 구현: `new URL()` parser 기반, `protocol === 'https:'` 만 허용, throw 케이스 false 반환
- `briefings.ts`의 기존 `isValidImageUrl`은 **폐기**하고 호출처(`loadBriefings` 내부 line 31)에서 `isHttpsUrl`을 직접 호출 — alias 유지하면 dead-code 잔존하므로 명시 폐기
- 향후 `Briefing.link` validation 도입 가능한 위치 마련 (이번 사이클은 imageUrl까지만 적용 — Lite 원칙)

비기능 요구:
- `javascript:` / `data:` / `http:` / 빈 문자열 / `null` / `undefined` 모두 false
- `https://` (대소문자 무관) 만 허용 — `new URL()` 은 protocol을 자동 lowercase하므로 현행 `/^https:\/\//i` 와 동일 인풋 집합 유지

### 2.3 Pre-existing flake (2건)

**D1. heatmap reduce-motion 셀렉터 누락 (CSS 버그 확정)**

현황 (검증 완료): `src/styles/components/heatmap.css:163-166`
```
@media (prefers-reduced-motion: reduce) {
  .heatmap-cell { transition: none; }
  .heatmap-grid.is-entering .heatmap-cell { animation: none; }
}
```
문제: `.heatmap-grid.is-entering .heatmap-cell` (specificity 0,2,1) 이 `.heatmap-grid.is-entering .heatmap-cell.is-future` (0,3,1)보다 낮아 future cell의 `heatmap-fade-in-future` keyframe override 실패. 테스트 `tests/smoke/heatmap.spec.ts:124` 가 이를 감지.

목표 (CSS 한 줄 추가):
```
@media (prefers-reduced-motion: reduce) {
  .heatmap-cell { transition: none; }
  .heatmap-grid.is-entering .heatmap-cell,
  .heatmap-grid.is-entering .heatmap-cell.is-future { animation: none; }
}
```
대안: `:is()` 또는 `:where()` 사용 — 일관성 위해 **명시 selector 추가**로 결정 (다른 기존 selector도 명시 패턴).

**D2. `layout.spec.ts:38` mobile bottom nav suite-flake**

현황 (메모리에서): 단독 3회 모두 pass, suite 실행 시 flaky.

목표 (조사 cap 1시간):
- 직전 spec/test가 viewport / localStorage / context 잔류 의심
- `beforeEach`에 `await page.setViewportSize` + `localStorage.clear()` 명시 추가
- 1시간 안에 원인 미확인 시 → `test.fixme()` + 별도 backlog (v3.6 issue) — v3.5 핵심 아님
