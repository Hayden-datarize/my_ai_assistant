## §1. 배경 + 목표

식물 detail modal은 이미 본문이 완성돼 있다:

- **v3.21**: Standard 6항목 (단계 배지 / progress / unlockedAt 도달일 / lastEngagedAt 마지막 활동 / wilting 상태 / answer·scrap counts).
- **v3.36**: action layer **옵션 1** = archive 탐색 chip ("📚 이 분야로 archive 탐색", `navigateToInterestArchive`).

v3.21 §8.5는 action layer로 4건을 명시했고 v3.36이 그 중 archive 이동만 청산했다. 본 사이클은 **나머지 잔여**를 reframe하여 청산한다:

| v3.21 §8.5 항목 | v3.47 처리 |
|---|---|
| archive 이동 | ✅ v3.36 완료 |
| "이 분야로 이동" home **filter** trigger | ⛔ 현재 구조 불가 (switchTab 인자 없음 + home 비-필터 설계) → **reframe**: 필터 없는 홈 이동으로 대체 |
| 다시 활성화 (재참여) | ✅ 본 사이클 — 홈 이동 CTA |
| 임박 재입력 | ✅ 본 사이클 — 다음 단계 nudge |

**reframe 결정 근거** (사용자 승인 2026-05-22):

1. **home interest-filter는 1.5h 불가**: `switchTab(id)`는 필터 인자 없음, `renderHome()`은 stateless 통합 피드, interest 필터링은 archive 전용(`currentInterestId` in `archive.ts`). 제대로 하려면 switchTab 시그니처 변경 + 전역 filter state + home 렌더 필터링 = 별도 큰 사이클.
2. **식물 활동의 실제 경로 = 홈**: `cumulativeActivity`는 **홈 브리핑 카드 스크랩/메모**로만 증가한다 (`tickPlantsByBriefingInMemory`, `briefings.ts:129` — 키워드 매칭). 답변(`recordDailyAnswer`)은 식물을 직접 tick하지 않는다. 따라서 시든 식물을 "다시 가꾸는" 실제 행동 = 홈에서 오늘 브리핑을 읽고 해당 분야 카드를 스크랩하기. **필터 없이도** 키워드 매칭이 자동으로 올바른 식물을 tick하므로 본질 충족.

## §3. 기능 설계

### A) 다음 단계 nudge (표시 전용, stage 1~4)

- **위치**: progress 줄(`.plant-detail-progress`) 바로 아래.
- **요소**: `<div class="plant-detail-nudge">` (innerHTML 합성 영역에 포함, 텍스트는 escapeHtml 불요 — 정적 카피 + 숫자만).
- **계산**: `remaining = STAGE_THRESHOLDS[stage-1] - cum`.
  - `cum`은 기존 `Math.floor(plant.cumulativeActivity)` (NaN guard 재사용).
  - **clamp**: `remaining < 1`이면 `1`로 표시 (정상 흐름에선 cum≥threshold면 engine이 이미 stage를 올렸지만, 손상 데이터/경계 방어).
- **카피**:
  - `remaining <= 3` → `🎯 다음 단계까지 딱 {N}번!`
  - 그 외 → `🎯 다음 단계까지 {N}번 더 가꾸면 돼요`
- **stage 5**: nudge 없음 (만개 — progress 줄이 "만개 ✨").

### B) 재참여 CTA → 홈 (행동)

- **요소**: `<button class="plant-action-home-chip">` (base `.plant-action-chip` **미포함** — CSS는 grouping 셀렉터로 공유). 사전 review P0-1: base 클래스를 공유하면 stage<5 식물에서 기존 smoke 테스트의 `.plant-action-chip` 단일 셀렉터가 2-match strict-mode 위반.
- **라벨**: `🌱 홈에서 오늘 브리핑 보기` (단일 라벨 — 시듦 맥락은 위 wilting 줄이 제공).
- **aria-label**: `홈으로 이동해 오늘 브리핑 보기`.
- **표시 조건**: `wilting || plant.stage < 5`. 즉 **`plant.stage === 5 && !wilting`(만개+건강)일 때만 숨김**.
- **onClick**: `closeModal()` → `void switchTab('home').catch(...)` (사전 review P1-3: archive chip과 parity — home chunk load reject 시 unhandled rejection 방지).
  - **단일 callsite** → 전용 helper 만들지 않고 inline 처리 (전역 CLAUDE.md "한 번만 쓰는 유틸 금지"). `navigateToInterestArchive`는 resetArchiveFilters/applyInterestFilter dynamic import가 필요해 helper였지만, 홈 이동은 `closeModal` + `switchTab` 2줄이라 inline이 적합.
  - import 추가: `closeModal` (이미 `shared`에서 openModal import 중 → 같은 모듈), `switchTab` from `../nav`.
- **archive chip과 공존**: archive chip(과거 돌아보기) + home 버튼(새로 가꾸기). DOM 순서: archive chip 먼저, home 버튼 다음 (또는 chip 묶음 컨테이너). 버튼 2개가 나란히 — CSS는 기존 chip 레이아웃 따름.

### DOM 순서 (renderBody 최종)

```
.plant-detail-stage
.plant-detail-progress
.plant-detail-nudge        ← A) 신규 (stage<5)
.plant-detail-unlocked     (조건부)

.plant-detail-wilting       (조건부)
.plant-detail-counts
.plant-action-chip (archive)
.plant-action-chip--home    ← B) 신규 (조건부: stage5+건강 아닐 때)
```

## §7. Risk

| Risk | 대응 |
|---|---|
| nudge가 progress 줄과 정보 중복 | progress=현재 위치, nudge=남은 횟수+격려. 중복 아닌 보완. stage5는 nudge 없음으로 정리 |
| home 버튼이 모든 분야에서 동일 동작(홈 이동) → 분야 무의미 | 의도된 동작 — CTA는 동기 부여용, 목적지는 통합 홈. 스크랩 시 키워드 매칭이 분야 식물 자동 tick |
| `closeModal` import 경로 | `shared`에서 이미 `openModal` import 중 → `closeModal` 같은 모듈에서 추가 import |
| smoke 홈 탭 활성 판정 flake | static element 대신 home dynamic mount 결과 또는 aria-current anchor (COMMON_MISTAKES §5) |
| switchTab은 async (Promise) | onClick에서 `void switchTab('home')` — fire-and-forget, modal은 이미 closeModal로 닫힘 |
