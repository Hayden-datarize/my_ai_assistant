## §1. 배경 + 목표

v3.21이 Streak Freeze를 **자동 전용**으로 출시: 7일마다 ❄️ 1개 regen(cap 2), 결석일 1:1 자동 consume, 홈 배너 `🔥 N일 · ❄️ N`. v3.21 §8.6은 "수동 claim / settings UI / 재충전 timer / 소비 history"를 v3.22+로 deferred.

**"수동 claim" reframe (사용자 결정 2026-05-22)**: freeze가 이미 자동 regen + 자동 consume이라 "수동 claim 버튼"은 자동 시스템과 중복되고 실익이 모호. 대신 §8.6의 실질 가치인 **가시성**(보유량 · 다음 충전 · 활동 내역)을 settings에 추가한다. 수동 claim 버튼은 비목표.

**확정 결정**:
- ① 내역은 **충전(earned) + 사용(consumed) 통합 타임라인** (소비만 기록 시 결석 없는 사용자는 늘 빈 내역).
- ② 다음 충전 표시는 **"예상"** — regen은 답변 시점에만 실행되므로 "약 D일 (답변 시 충전)"으로 정직 표기.

## §3. Schema v9→v10 (xpHistory v8 선례 1:1)

### FreezeHistoryEntry

```ts
interface FreezeHistoryEntry {
  date: string;                    // KST 'YYYY-MM-DD' (getKstDateStr)
  kind: 'earned' | 'consumed';     // 충전 / 사용
  amount: number;                  // >0 정수 (regen grant 또는 consumed days)
}
```

User 타입: `freezeHistory?: FreezeHistoryEntry[];`

### migrateUserToV10 (chain superset)

```ts
export function migrateUserToV10(u: unknown): User {
  const r = u as Record<string, unknown> & { schemaVersion?: number; freezeHistory?: unknown };
  if (r.schemaVersion === 10) return r as unknown as User;   // idempotent / downgrade barrier
  const v9 = migrateUserToV9(u);
  const v9r = v9 as unknown as Record<string, unknown>;
  const freezeHistory = Array.isArray(v9r.freezeHistory) ? v9r.freezeHistory : [];
  return { ...v9, schemaVersion: 10 as const, freezeHistory } as unknown as User;
}
```

### user.ts 4 spot (Explore 실측)

1. **User 타입** `schemaVersion: 9` → `10`.
2. **getCachedUser hydrate**: range `sv0 >= 2 && sv0 <= 9` → `<= 10`; chain에 `user = migrateUserToV10(user);` 추가 (v9 호출 다음).
3. **getCachedUser persist**: `parsed?.schemaVersion !== 9` → `!== 10`.
4. **isValidUserShape**:
   - 기존 `sv >= 4 && sv <= 9` (plant) → `<= 10`; `sv >= 8 && sv <= 9` (xpHistory) → `<= 10` (v10은 v9 superset).
   - 신규 freezeHistory guard:
     ```ts
     // v3.48: v10 신규 freezeHistory 배열 guard (silent NaN 차단, v3.12 lesson).
     if (sv >= 10 && sv <= 10) {
       if (!Array.isArray(r.freezeHistory)) return false;
       for (const h of r.freezeHistory as unknown[]) {
         if (!h || typeof h !== 'object') return false;
         const he = h as Record<string, unknown>;
         if (typeof he.date !== 'string' || he.date.length === 0) return false;
         if (he.kind !== 'earned' && he.kind !== 'consumed') return false;
         if (typeof he.amount !== 'number' || !Number.isFinite(he.amount) || he.amount <= 0) return false;
       }
     }
     ```

**§16 (migrate fast-path normalize) 정합**: v10 fast-path early-return은 `schemaVersion===10`만 — 손상 freezeHistory는 isValidUserShape guard가 read-time에 차단(false → re-migrate). xpHistory와 동일 contract.

## §4. 기록 지점 — recordDailyAnswer (xpHistory push 선례)

regen/consume 자리(user.ts ~line 367~392)에서 earned/consumed 산출 후 push. **freezeEngine 시그니처 무변경** — count before/after 캡처로 earned 산출:

```ts
// v3.48: freeze 활동 내역 기록 (충전 + 사용 통합). engine 시그니처 무변경 — count 차이로 earned 산출.
const freezeBefore = u.streakFreeze.count;
regenerateFreeze(u, now);
const earned = u.streakFreeze.count - freezeBefore;   // regen grant (0~2)

// ... consume (기존) ...
// const result = consumeFreezeForGap(u, gap); freezeConsumed = result.consumed;

if (!Array.isArray(u.freezeHistory)) u.freezeHistory = [];   // optional init guard (xpHistory 선례)
if (earned > 0) u.freezeHistory.push({ date: today, kind: 'earned', amount: earned });
if (freezeConsumed > 0) u.freezeHistory.push({ date: today, kind: 'consumed', amount: freezeConsumed });
```

**순서 주의**: earned는 regen 직후 캡처, consumed는 기존 `consumeFreezeForGap` 결과(`freezeConsumed`) 사용. push는 둘 다 saveUser 이전 같은 atomic write에 포함 (xpHistory T4 핀 패턴 정합).

**브랜드 신규 user**: v5 migration default `{count:2}`는 recordDailyAnswer 이벤트가 아니므로 history entry 없음 — 빈 내역에서 시작, 이후 실제 regen부터 누적. 정상.

## §5. 읽기 헬퍼 — getFreezeHistory (getXpHistory 선례)

```ts
export interface FreezeHistoryView {
  date: string;
  kind: 'earned' | 'consumed';
  amount: number;
}

export function getFreezeHistory(limit = 10): FreezeHistoryView[] {
  const user = getCachedUser();
  const raw = user?.freezeHistory ?? [];
  if (raw.length === 0) return [];
  // 최근 entry desc (배열 끝이 최신 — push 순서). slice 후 reverse.
  return raw.slice(-limit).reverse().map((h) => ({ date: h.date, kind: h.kind, amount: h.amount }));
}
```

### 다음 충전 계산 (순수 helper, schema 무관)

```ts
// count >= cap → null (가득 참). 아니면 lastEarnedAt + 7d - now (ms, 음수 가능 → 0 clamp).
export function getNextFreezeEtaDays(u: { streakFreeze: { count: number; lastEarnedAt: string } }, now = new Date()): number | null {
  if (u.streakFreeze.count >= 2) return null;   // FREEZE_CAP
  const lastMs = Date.parse(`${u.streakFreeze.lastEarnedAt}T00:00:00+09:00`);
  if (!Number.isFinite(lastMs)) return 0;
  const remainingMs = lastMs + 7 * 86400_000 - now.getTime();
  return Math.max(0, Math.ceil(remainingMs / 86400_000));
}
```

(위치: `freezeEngine.ts` — FREEZE_CAP/7d 상수 동일 모듈 재사용. count≥cap이면 timer 무의미하므로 null sentinel.)

```html
<section class="settings-group">

  <div id="freezeStatus" class="settings-freeze-status"><!-- 보유 + 다음충전 read-render --></div>
  <div id="freezeHistory" class="settings-freeze-history"><!-- 활동 내역 list --></div>
  <details><summary>Streak Freeze란?</summary><p>...자동 충전/소비 설명...</p></details>
</section>
```

`bindHandlers`(또는 render 직후)에서 read-render:
- **보유**: `❄️ {count} / 2`.
- **다음 충전**: `getNextFreezeEtaDays(u)` → `null`이면 "보유 가득 (2/2)", 숫자 N이면 "다음 ❄️까지 약 {N}일 (답변 시 충전)" (N=0이면 "곧 충전돼요 (답변 시)").
- **활동 내역**: `getFreezeHistory(10)` → 각 entry `{formatKoreanDate(date)} ❄️ {+amount 충전 | -amount 사용 (연속 유지)}`. 빈 배열이면 "아직 내역이 없어요".
- 모든 텍스트 escapeHtml (date/amount는 안전하나 일관).

신규 claim 버튼 없음. 이벤트 신규 0 (settings 탭 전환마다 재렌더 → read-render로 충분).

CSS: `.settings-freeze-status` / `.settings-freeze-history` 최소 rule (기존 settings 토큰 재사용, list는 줄간격).
