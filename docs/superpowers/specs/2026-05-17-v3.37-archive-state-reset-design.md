# v3.37 Archive State Reset + Focus Carry — Design

> **Status**: Spec drafted 2026-05-17. T0 진입 직전.
> **Cycle range**: parent `fe3282b` (v3.36 deploy) → tip TBD.
> **Type**: Small cleanup (v3.36 Codex 최종 P2-1 + P2-2 carry 일괄 청산).

---

## §1. Motivation

v3.36 T1에서 plant detail modal에 action chip(`📚 이 분야로 archive 탐색`)을 도입했다. chip click 시 `closeModal() → switchTab('archive') → input.value = keyword → handleArchiveSearch()` 시퀀스로 archive에 keyword가 prefill되지만, 아래 두 carry-forward가 남아있다.

### 1.1 Carry-forward 출처

**C1 (v3.36 Codex 최종 P2-1)** — archive module state(`currentFilter` / `currentTokens` / `currentEntity` / `selectedIds` / `selectMode`) reset 없음. 이전 archive 세션에서 entity '스크랩' + filter '메모'를 적용한 상태에서 plant action 진입 시, plant keyword가 stale filter와 AND 결합되어 결과 0건 또는 무관한 chip 활성화 가시 — 사용자 혼란.

**C2 (v3.36 Codex 최종 P2-2)** — `closeModal()` → `switchTab('archive')` 시퀀스에서 `#app` element가 교체되며 closeModal이 복원한 trigger element가 사라져 focus가 body로 fallback. plant action chip의 의도(이 분야 관련 콘텐츠 탐색 시작)와 맞지 않고, keyboard/스크린 리더 사용자가 즉시 검색어 편집/스크롤할 위치를 잃음.

### 1.2 본 사이클 목표

1. archive handler에 `resetArchiveFilters()` export 신설. module state 5종 + DOM chip ARIA + question type row 표시를 default('all')로 동기화.
2. `.other-pin-counter` click handler 내 inline 5줄 reset → 새 함수 호출로 통합 (DRY).
3. plant-detail `navigateToInterestArchive` 시퀀스에 `resetArchiveFilters()` 호출 + `input.focus({ preventScroll: true })` 추가.
4. 기존 v3.36 smoke spec 확장 — 사전 stale filter setup → chip 클릭 → reset + focus 회귀 가드.
5. 외부 라이브러리 0줄. Schema 변경 0. Migration 0. CSP/CORS 0.

### 1.3 사용자 가치

- Plant action chip 진입 시 새 컨텍스트가 깨끗하게 열려 stale filter로 인한 결과 0건 회피.
- `#archiveSearch` focus 자동 부여 → keyboard 사용자가 즉시 키워드 보정/추가 입력 가능.
- counter-click(다른 entity 핀 보기)도 같은 reset 경로 공유 → 향후 유사 entry point 추가 시 단일 함수 재사용.

### 2.2 `resetArchiveFilters()` 시맨틱

```ts
/**
 * v3.37 T1: archive module state + DOM chip ARIA 일괄 default 복귀.
 * 진입점:
 *   - .other-pin-counter click handler (v3.27 T4 inline reset 통합)
 *   - plant-detail navigateToInterestArchive (v3.36 carry C1)
 *
 * Reset 대상:
 *   - currentFilter: 'all'
 *   - currentTokens: []
 *   - currentEntity: 'all'
 *   - selectedIds.clear() + selectMode = false (선택 모드 진입 중에도 안전하게 해제)
 *
 * DOM 동기화:
 *   - .archive-entity-chip → entity 'all'만 active + aria-checked='true'
 *   - .filter-chip → filter 'all'만 active
 *   - #archiveFilters (question type row) → display=''  (entity 'scrap'/'insight'로 숨김 상태였을 경우 복구)
 *   - 선택 모드 UI 클래스/배지 (있다면) → 해제
 */
export function resetArchiveFilters(): void { /* ... */ }
```

**중요 invariant**:

- `currentTokens` reset은 `handleArchiveSearch()`가 직후 input value로 덮어쓰므로 동작상 redundant이지만, **함수 시맨틱 완결성**을 위해 명시 (다른 caller가 search input 비어있는 채로 호출 가능).
- DOM 동기화는 `archive-entity-chip` / `filter-chip` element가 mount되지 않은 시점(다른 탭에 있을 때)에도 silent no-op이어야 함 — `querySelectorAll`가 empty NodeList 반환.
- `rerenderList()`는 호출하지 않음. caller(plant-action)가 keyword 세팅 후 `handleArchiveSearch()`를 직접 호출하므로 중복 render 회피. counter-click handler에서는 새 함수 호출 후 `rerenderList()` 명시 호출 유지 (현행 동작 보존).

### 2.3 plant-detail 시퀀스

**현재** (`plant-detail.ts:98-112`):

```ts
async function navigateToInterestArchive(interestId: string): Promise<void> {
  const keyword = pickSearchKeyword(interestId);
  if (!keyword) return;

  closeModal();
  await switchTab('archive');

  const input = document.querySelector<HTMLInputElement>('#archiveSearch');
  if (!input) return;
  input.value = keyword;

  const { handleArchiveSearch } = await import('../handlers/archive');
  handleArchiveSearch();
}
```

**변경 후**:

```ts
async function navigateToInterestArchive(interestId: string): Promise<void> {
  const keyword = pickSearchKeyword(interestId);
  if (!keyword) return;

  closeModal();
  const { resetArchiveFilters, handleArchiveSearch } = await import('../handlers/archive');
  resetArchiveFilters();
  await switchTab('archive');

  const input = document.querySelector<HTMLInputElement>('#archiveSearch');
  if (!input) return;
  input.value = keyword;
  handleArchiveSearch();
  input.focus({ preventScroll: true });
}
```

**호출 순서 근거**:

1. `closeModal()` 먼저 — 모달 dispose가 archive DOM 노출보다 선행해야 사용자 시각 noise 최소.
2. `resetArchiveFilters()`를 `switchTab` 전에 호출 — archive DOM이 hydrate되기 전 module state는 reset됨. switchTab 후 hydrateArchive()가 reset된 state 기반으로 render.
3. `await switchTab('archive')`까지 끝나야 `#archiveSearch` element가 DOM에 존재. 이후 `input.value` / `handleArchiveSearch` / `focus` 모두 안전.
4. `focus({ preventScroll: true })` — 모바일 Safari에서 `focus()` 시 화면 점프 회피. archive header가 viewport 상단에 보장되어야 하므로 scroll 점프 차단.

### 2.4 counter-click 통합

**현재** (`archive.ts:461-479`, 약 19줄):

```ts
document.addEventListener('click', (e) => {
  if (!(e.target as HTMLElement).closest('.other-pin-counter')) return;
  currentEntity = 'all';
  currentFilter = 'all';
  document.querySelectorAll<HTMLButtonElement>('.archive-entity-chip').forEach((b) => {
    const active = b.dataset['entity'] === 'all';
    b.classList.toggle('active', active);
    b.setAttribute('aria-checked', active ? 'true' : 'false');
  });
  document.querySelectorAll<HTMLButtonElement>('.filter-chip').forEach((btn) => {
    btn.classList.toggle('active', btn.dataset['filter'] === 'all');
  });
  const q = document.getElementById('archiveFilters');
  if (q) q.style.display = '';
  rerenderList();
});
```

**변경 후** (4줄):

```ts
document.addEventListener('click', (e) => {
  if (!(e.target as HTMLElement).closest('.other-pin-counter')) return;
  resetArchiveFilters();
  rerenderList();
});
```

> `resetArchiveFilters`는 `rerenderList`를 부르지 않음 — counter-click은 명시적 render 호출 유지 (현행 행동 보존). plant-action은 직후 `handleArchiveSearch()`가 `rerenderList`를 호출하므로 중복 render 회피.

## §4. Risk / Open Questions

### 4.1 Risk 매트릭스

| Risk | 영향 | 대응 |
|---|---|---|
| `resetArchiveFilters` 호출 시 `__archiveMounted` 가드와 충돌 — guard reset 누락 | mount 가드 재진입 fail | `__archiveMounted`는 reset 대상 아님 (mount는 1회성). 본 함수는 state + DOM만 다룸. spec에 명시 |
| counter-click 통합 후 `rerenderList()` 중복 호출 — 본 함수 내부에서도 부르면 counter-click이 2번 render | 사소한 성능 손실 | 본 함수는 `rerenderList` 호출 안 함. caller가 명시 호출. spec §2.2 invariant 명시 |
| `input.focus({ preventScroll: true })` iOS Safari 14+ 미지원 fallback | mobile 일부 환경에서 scroll 점프 가능 | 옵션 자체는 polyfill 없이 안전 (지원 안 하는 브라우저는 옵션 무시하고 일반 focus). DoD에 명시 |
| `selectMode === true` 상태에서 plant action chip 클릭 → 선택 모드 자동 해제가 사용자 의도와 어긋남 | UX 미세 차이 | "새 컨텍스트 진입 = 이전 모드 해제"는 자연스러운 메타. spec §1 사용자 가치 명시. smoke에서 selectMode 사전 setup case는 plan에서 검토 |
| 양쪽 TZ vitest count drift — 신규 spec이 TZ-dependent 시드 사용 시 fail mask | retro 보고 drift | TZ-agnostic 시드 (`T09:00:00Z` 패턴 또는 spy 기반 — 시간 무관) 사용 |
| dynamic import 추가 — `resetArchiveFilters`도 archive chunk이라 plant-detail은 이미 archive handler를 lazy import 중. 추가 import cost 0 | 영향 없음 | 동일 chunk 내 named export 1개 추가 |

### 4.2 deferred (의식적)

- `selectMode === true` 상태 plant action smoke case — plan 단계에서 cost/value 검토 후 추가 여부 결정. T0 Codex 사전 review 의견 반영.
- mobile iOS focus 동작 실측 검증 (자동화 어려움) — 사용자 manual QA로 위임. retro에 명시.
- counter-click 통합과 plant-action 호출 외 **다른 entry point** 도입 (예: stats 탭 카드 클릭) — v3.38+ carry.
