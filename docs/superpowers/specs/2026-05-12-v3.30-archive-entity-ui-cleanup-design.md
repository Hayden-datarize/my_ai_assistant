#### T2 — Count wiring

`archive-entity-chip.ts`:

```typescript
export function renderEntityChipRow(
  active: EntityFilter = 'all',
  counts: Record<EntityFilter, number> | null = null,
): string {
  const chips = ENTITY_ORDER.map((id) => {
    const checked = id === active ? 'true' : 'false';
    const activeClass = id === active ? ' active' : '';
    const countSpan = counts !== null
      ? `<span class="archive-entity-count" data-entity-count="${id}">${counts[id]}</span>`
      : '';
    return `<button type="button" role="radio" class="archive-entity-chip${activeClass}" data-entity="${id}" aria-checked="${checked}">${ENTITY_LABELS[id]}${countSpan}</button>`;
  }).join('');
  return `<div id="archiveEntityFilters" role="radiogroup" aria-label="아카이브 카테고리" class="archive-entity-row">${chips}</div>`;
}
```

`src/ui/handlers/archive.ts`에서:

- 단일 helper `getEntityCounts()` 신설 (closure 내부) — `all` = total / `answer` = 답변만 / `scrap` = 스크랩 / `insight` = 인사이트.
- DOM 갱신 helper `refreshEntityCounts()` 신설 — `document.querySelectorAll('[data-entity-count]').forEach((el) => { const id = el.getAttribute('data-entity-count'); el.textContent = String(counts[id]); })`.
- **호출 시점**:
  1. 첫 `renderArchive()` 시점에 counts=null로 chip row 렌더 → 데이터 load 직후 `refreshEntityCounts()` 1회 (R1 race).
  2. 답변/스크랩/인사이트 **추가/삭제 후** — 실재 이벤트 `dg:archive:updated` (단일, [archive.ts:74](src/ui/handlers/archive.ts#L74) `dispatchEvent(new CustomEvent('dg:archive:updated', { detail: { entity, id } }))`) 1개에 hook. `refreshEntityCounts()` 재호출 (chip row 재생성 X, textContent만).
- chip row 자체는 재생성 X — text 노드만 update (DOM 노드 재사용 + ARIA state 보존).

**실측 정정 (controller self-review, 2026-05-12)**:

`src/main.ts:28-37` 현재 코드:

```typescript
// v3.29 T3 (Codex 사전 P1-3): handler mount lazy — boot 시점에 listener 등록을
// 보존하기 위해 Promise.all 병렬 await. 향후 truly first-mount eager-only로
// 줄이려면 handler가 dg:* listener 등록을 tab-changed 시점으로 미루도록 리팩토링 필요.
const [home, archive, stats, missions] = await Promise.all([
  import('./ui/handlers/home'),
  import('./ui/handlers/archive'),
  import('./ui/handlers/stats'),
  import('./ui/handlers/missions'),
]);
home.mountHomeHandlers();
archive.mountArchiveHandlers();
stats.mountStatsHandlers();
missions.mountMissionsHandlers();
```

v3.29 T3 코멘트에 명시: **truly lazy mount는 listener 등록 분리 (`registerListeners` vs `mountHandlers`) 리팩토링 동반 필요**. 단순 `mount*` 호출만 nav.ts switchTab 시점으로 옮기면 cross-tab listener (예: home의 답변 save → archive 카운트 update 이벤트 hook) 누락.

**본 사이클 T4 scope 격하**: import만 직렬화/병렬 미세 polish 또는 listener 분리 사전 작업. truly lazy mount는 **v3.31+ carry**로 이연 (R4 명시).

선택지 (T4 plan v1 시점 controller 결정):

- **옵션 A (안전)**: T4를 **v3.31+ carry-forward**로 이연. 본 사이클 T4 = 0 task. 사이클 task 수 T0~T8 → T0~T7 (8개).
- **옵션 B (사전 작업)**: T4에서 listener 등록을 `register*Listeners()` 함수로 분리만 수행 (mount 분리 X). v3.31에서 mount-lazy 시점에 자연 reuse. trim 효과 ~0.
