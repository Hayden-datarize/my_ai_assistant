## §2. Architecture

### 2.1 C2 — questionText highlight scope 확장

**현재** (`src/ui/handlers/archive.ts:570-579`):

```ts
const q = document.createElement('p');
if (a.questionText) {
  q.className = 'archive-card-question';
  q.textContent = `❓ ${a.questionText}`;  // textContent — highlight 불가
} else {
  q.className = 'archive-card-question archive-card-question--missing';
  q.textContent = '질문 정보 없음 (이전 버전 답변)';
}
card.append(q);
```

**변경 후**:

```ts
const q = document.createElement('p');
if (a.questionText) {
  q.className = 'archive-card-question';
  if (currentTokens.length > 0) {
    // eslint-disable-next-line no-restricted-syntax -- highlightHtml escapeHtml + escapeRegex 적용, <mark> only inject
    q.innerHTML = `❓ ${highlightHtml(a.questionText, currentTokens)}`;
  } else {
    q.textContent = `❓ ${a.questionText}`;
  }
} else {
  q.className = 'archive-card-question archive-card-question--missing';
  q.textContent = '질문 정보 없음 (이전 버전 답변)';
}
card.append(q);
```

**XSS 안전성**:
- `❓` 이모지는 코드 리터럴, escape 불필요.
- `highlightHtml(a.questionText, currentTokens)`는 `escapeHtml` + `escapeForRegExp` 내부 적용 후 `<mark>`만 inject — 이미 `body` highlight에서 검증된 pattern (archive.ts:587-588).
- `archive-card-question--missing` 분기는 사용자 입력 0 (코드 리터럴 only) — `textContent` 유지.

### 2.3 C5 — ranking.ts NFC normalize 1회

**현재** (`src/utils/ranking.ts:17-22`):

```ts
const normalized = fields.map((f) => ({
  weight: f.weight,
  body: f.text.normalize('NFC').toLowerCase(),
  initials: getInitialConsonants(f.text.normalize('NFC').toLowerCase()),  // 2회 호출
}));
```

**변경 후**:

```ts
const normalized = fields.map((f) => {
  const text = f.text.normalize('NFC').toLowerCase();
  return {
    weight: f.weight,
    body: text,
    initials: getInitialConsonants(text),
  };
});
```

**의미 보존**: NFC + toLowerCase는 idempotent한 string transform — `getInitialConsonants(x)` 결과 동일. 기존 9 spec 그대로 통과.

### 2.4 C6 — ranking.spec.ts cross-product case 1건

**현재** (`tests/unit/ranking.spec.ts`): 9 case — 단일 field × 다중 token, 다중 field × 단일 token 분리. (Codex 사전 P1-2 경로 정정.)

**추가** (1 case):

```ts
it('다중 field × 다중 token cross-product max', () => {
  const fields = [
    { text: 'TypeScript best practices', weight: 2 },  // field 1
    { text: 'React hooks rules', weight: 1 },           // field 2
  ];
  const tokens = ['typescript', 'react'];
  // typescript: field 1 hit (weight 2) — max 2
  // react: field 2 hit (weight 1) — max 1
  // total: 2 + 1 = 3
  expect(scoreEntry(fields, tokens)).toBe(3);
});
```

**의도**: 토큰별 max(field weight) 알고리즘이 cross-product에서도 invariant 유지 확인. v3.34 T3 DOM-level spec이 이 invariant를 간접 cover하지만 unit-level 명시 추가.

| C2 `q.innerHTML = `❓ ${highlightHtml(...)}`` — `❓` 이모지 + 결합 시 escape 누락 우려 | XSS 가능성 (낮음 — 이모지는 코드 리터럴) | highlightHtml 내부에서 questionText만 escape, ❓는 안전한 코드 리터럴. ESLint `no-restricted-syntax` disable 명시. |
| C2 archive-card-question CSS line-clamp/overflow와 `<mark>` interaction | visual cue 약화 가능 | T2 DOM-level spec에서 mark element 존재 검증 + 사이클 끝 smoke 100/100 확인. **실측 (Codex P2 흡수)**: question preview는 line-clamp 아니라 `nowrap + overflow hidden + ellipsis` (archive.css:173). `<mark>`는 inline이라 구조 충돌 가능성 낮음 — DOM spec + smoke로 충분, final self-review에 명시. |
| C2 highlight scope — substring token만 mark, **초성-only 토큰은 mark 없음** (highlight.ts:10 graduated 정책) | 초성 검색 시 visual cue 부재 | Spec 문구에 "substring token 한정" 명시 (Codex 사전 P2-4 흡수). 본 사이클 변경 X (기존 정책 유지). |
