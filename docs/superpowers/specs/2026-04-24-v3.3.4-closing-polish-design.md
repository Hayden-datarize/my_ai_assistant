## 2. Problem Statement

### 2.1 Item 1 — `imageUrl` 런타임 타입 검증 누락
- **증상**: `loadBriefings()`가 `JSON.parse` + `as Briefing[]` 타입 단언만 수행. localStorage가 손상되거나 legacy v3.3.2 cache (imageUrl 없음) 혼재 시 런타임 에러 가능성. 특히 `img.src = <non-string>` 시 TypeError
- **관련 코드**:
  - [src/state/briefings.ts:11](src/state/briefings.ts#L11) — `imageUrl?: string` 필드 정의
  - [src/state/briefings.ts:17](src/state/briefings.ts#L17) — `loadBriefings()` 검증 없음
  - [src/ui/handlers/home.ts:204-207](src/ui/handlers/home.ts#L204) — `img.src = b.imageUrl` 직접 할당
  - [src/services/rss.ts:24-33](src/services/rss.ts#L24) — 쓰기 측 `sanitizeHttpsUrl()`는 이미 안전

### 2.2 Item 3 — tier3 fallback 네트워크 실패 시나리오 E2E 미커버
- **증상**: v3.3.3에서 tier 1→2 전환 로직은 구현됨 ([home.ts:212-216](src/ui/handlers/home.ts#L212)) 하지만 **실 이미지 URL이 4xx/5xx 리턴할 때 letter fallback으로 정상 전환되는지** Playwright smoke 없음
- **관련 코드**:
  - [src/ui/handlers/home.ts:212-216](src/ui/handlers/home.ts#L212) — `img.addEventListener('error', ...)` 핸들러
  - [e2e/](e2e/) — tier downgrade 시나리오 테스트 없음

### 2.3 Item 4 — `saveBtn:disabled` 시각 피드백 약함
- **증상**: `.btn:disabled`는 `opacity: 0.5` + `cursor: not-allowed` + `pointer-events: none` 만 적용. `.btn-primary:disabled`는 primary indigo 색 유지한 채 dim — **"로딩 중"으로 오인 가능**. "못 누름" 신호가 약함
- **관련 코드**:
  - [src/styles/components/buttons.css:20](src/styles/components/buttons.css#L20) — 현재 disabled 룰
  - [src/ui/modals/interests.ts:84](src/ui/modals/interests.ts#L84) — 체크 0개 시 `saveBtn.disabled = true` (대표 사례)
  - [src/styles/tokens.css](src/styles/tokens.css) — `--bg-disabled` 토큰 부재

### 2.4 Item 5 — surrogate pair 미대응 → letter fallback 깨짐
- **증상**: `const initialLetter = (b.sourceTitle?.[0] ?? '?').toUpperCase();` — `sourceTitle`이 이모지 prefix로 시작하는 피드(예: `'🚀 TechCrunch'`)면 `[0]`이 lone surrogate `'\uD83D'` 반환 → 렌더링 깨짐 (`�`)
- **관련 코드**:
  - [src/ui/handlers/home.ts:202](src/ui/handlers/home.ts#L202)

### 2.5 Item 6 — titleId 충돌 가능성 (이론적)
- **증상**: `Date.now()` + `Math.random().slice(2,6)` 조합 — 동일 틱 + 4자 랜덤으로 충돌 확률 존재 (1/36^4 ≈ 1/1.6M). `aria-labelledby` 참조 꼬임 가능성 낮지만 현대 브라우저에 `crypto.randomUUID()` 있음
- **관련 코드**:
  - [src/ui/modals/shared.ts:37](src/ui/modals/shared.ts#L37)

### 2.6 Item 7 — `closeModal({skipFocusRestore})` 의도 문서 부재
- **증상**: `skipFocusRestore` 플래그는 `openModal` 내부에서 체인 제거 시에만 사용해야 함. 외부 호출 시 포커스가 body로 튐. JSDoc 없어 외부 호출자가 오용할 여지
- **관련 코드**:
  - [src/ui/modals/shared.ts:74](src/ui/modals/shared.ts#L74) — `closeModal(opts?: CloseOpts)` 시그니처

## 4. Design

### 4.1 Item 1 — `imageUrl` narrow validation

**변경 위치**: `src/state/briefings.ts` — `loadBriefings()` 에 inline sanitize

**로직**:
```ts
function isValidImageUrl(v: unknown): v is string {
  return typeof v === 'string' && /^https:\/\//i.test(v);
}

export function loadBriefings(): Briefing[] {
  try {
    const raw = JSON.parse(localStorage.getItem(KEY) ?? '[]') as unknown;
    if (!Array.isArray(raw)) return [];
    return raw.map((b) => {
      const briefing = b as Briefing;
      // Drop imageUrl only if present-but-invalid; leave undefined alone
      if (briefing.imageUrl !== undefined && !isValidImageUrl(briefing.imageUrl)) {
        const normalized: Briefing = { ...briefing };
        delete normalized.imageUrl;
        return normalized;
      }
      return briefing;
    });
  } catch {
    return [];
  }
}
```

**설계 근거**:
- `isValidImageUrl`은 `briefings.ts` 파일 내부 private helper — 재사용 수요 없음 (user instruction: "한 번만 쓰는 로직의 유틸리티 함수 만들지 않는다")
- `https://` 접두만 검증 (쓰기 측 `sanitizeHttpsUrl`와 정책 일치)
- briefing 자체는 삭제하지 않고 `imageUrl` 필드만 drop — 기록 손실 방지

### 4.2 Item 3 — tier downgrade smoke

**신규 파일**: `e2e/tier-downgrade.spec.ts` (또는 기존 briefing 관련 spec에 추가)

**시나리오 2건**:
1. Image URL 404 응답 → `.briefing-card[data-tier="2"]` + `.card-thumb` 제거
2. Image URL 500 응답 → 동일 결과

**구현 개요**:
```ts
test('tier1 → tier2 on image 404', async ({ page }) => {
  // Seed localStorage with a briefing carrying imageUrl BEFORE first paint
  await page.addInitScript(() => {
    localStorage.setItem('briefings', JSON.stringify([{
      id: 'test-1', date: '2026-04-24', url: 'https://example.com/article',
      title: 'T', summary: 'S', scrapped: false, read: false, memo: '',
      sourceTitle: 'Example', imageUrl: 'https://example.com/img.jpg'
    }]));
  });
  await page.route('https://example.com/img.jpg', (route) => route.fulfill({ status: 404 }));
  await page.goto('/');
  const card = page.locator('.briefing-card').first();
  await expect(card).toHaveAttribute('data-tier', '2');
  await expect(card.locator('.card-thumb')).toHaveCount(0);
});
```

**Note**: `.card-initial` DOM element는 tier=1/2 공통 append됨 ([home.ts:220-224](src/ui/handlers/home.ts#L220)). visibility는 CSS layer에 의존하므로 `data-tier="2"` + `.card-thumb` 부재를 assertion 기준으로 삼음 (DOM-level 검증이 더 견고).

**설계 근거**: 이미 구현된 `img.onerror` 로직의 회귀 방지. 실 트래픽 변화(사이트 이미지 CDN 장애) 대응 검증

### 4.3 Item 4 — `.btn-primary:disabled` muted style

**토큰 추가**: `src/styles/tokens.css`

```css
:root {
  /* ... 기존 토큰 ... */
  --bg-disabled: #CBD5E1;  /* slate-300 */
}

[data-theme="dark"] {
  /* ... 기존 토큰 ... */
  --bg-disabled: #475569;  /* slate-600 */
}
```

**스타일 추가**: `src/styles/components/buttons.css`

```css
.btn-primary:disabled {
  background: var(--bg-disabled);
  color: var(--text-secondary);
  opacity: 1;  /* override .btn:disabled opacity */
}
```

**설계 근거**:
- `--bg-disabled` 신규 토큰 1개만 추가 (최소 확장)
- `--text-secondary` 재사용 (tertiary는 대비 부족 — 라이트에서 slate-400 on slate-300 = 2.3:1로 WCAG 3:1 미달)
- `opacity: 1` 명시적 override로 .btn:disabled 계단식 결과 제거
- 최종 대비: 라이트 ~3.9:1, 다크 ~3.3:1 — disabled 기준 충분

**색 검증 표** (Q2 해소):

| Mode | bg | text | 대비 |
|------|-----|------|------|
| Light | `--bg-disabled` #CBD5E1 | `--text-secondary` #64748B | ~3.9:1 |
| Dark | `--bg-disabled` #475569 | `--text-secondary` #94A3B8 | ~3.3:1 |
| 참고: `--border` #E2E8F0 (light) | — | — | bg-disabled보다 밝음 → 구분 OK |

**검증**: Playwright `toHaveCSS('background-color', ...)` 으로 light/dark 각각 assertion

### 4.4 Item 5 — surrogate pair-safe initialLetter

**변경 위치**: `src/ui/handlers/home.ts:202`

```ts
// Before
const initialLetter = (b.sourceTitle?.[0] ?? '?').toUpperCase();

// After
const initialLetter = ([...(b.sourceTitle ?? '?')][0] ?? '?').toUpperCase();
```

**설계 근거**: String spread는 grapheme-safe 이터레이션. ZWJ combo (👨‍👩‍👧) 까지 완벽 처리는 아니지만 lone surrogate (😀🚀 등 basic emoji) 는 해결. Intl.Segmenter는 polyfill 비용 고려 시 과함.

**Tests** (unit, `src/ui/handlers/__tests__/home.test.ts` 또는 신규):
- `'🚀TechCrunch'` → `'🚀'`
- `'가나다'` → `'가'`
- `'A'` → `'A'`
- `''` → `'?'`
- `undefined` → `'?'`

### 4.5 Item 6 — `crypto.randomUUID()` titleId

**변경 위치**: `src/ui/modals/shared.ts:37`

```ts
// Before
const titleId = `dg-modal-title-${Date.now()}-${Math.random().toString(36).slice(2, 6)}`;

// After
const titleId = `dg-modal-title-${crypto.randomUUID()}`;
```

**설계 근거**:
- `crypto.randomUUID()`는 secure context에서 사용 가능. Firebase Hosting HTTPS 강제 → 프로덕션 OK
- 개발: `vite` dev server는 localhost를 secure context로 취급 → OK
- UUID에 포함된 하이픈은 HTML id 유효 문자 → `aria-labelledby` 안전
- 충돌 확률: 실질적 0 (128-bit)

**브라우저 지원**: Chrome 92+, Firefox 95+, Safari 15.4+ — 2023년 이후 모든 주류 브라우저. `target: 'es2022'` vite config과 일치

v3.3.3 spec의 Q1/Q4/Q5/Q6 패턴 계승. 구현 phase 진입 시 아래 항목을 먼저 실 검증.
