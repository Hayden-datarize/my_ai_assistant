## §1 Background

### 1.1 발견된 production 버그

`src/state/user.ts`는 두 개의 도메인 함수를 export 한다:

- `recordActivity(xpDelta)` — XP/level 누적 + lastActiveDate 갱신 + saveUser
- `checkAndUpdateStreak()` — 어제 활동 여부로 streak 증감 + saveUser

**그러나 production 코드 어디서도 호출하지 않는다.** `git grep`/`find_symbol` 양방향 확인 결과 호출처는 0건. `tests/unit/state-user.spec.ts`의 4 it-block(recordActivity x1 + checkAndUpdateStreak x3)만이 사용한다 → 테스트는 green이지만 실제로는 데드 코드.

대신 `src/ui/handlers/home.ts:72` `applyAnswerActivity`가 inline으로 동일 로직 일부(XP + level + lastActiveDate)만 복제 — **streak 갱신은 누락**:

```ts
export function applyAnswerActivity(user: LegacyUser): void {
  user.xp += 10;
  user.level = 1 + Math.floor(user.xp / 100);
  user.lastActiveDate = getDateStr();
  try { saveUser(user); } catch (e) { showToast(getSaveErrorMessage(e)); }
}
```

귀결:

- 홈 탭 `🔥 ${user.streak}일 연속 성장 중!` (handlers/home.ts:314) 은 영구 0
- stats 탭 `user.streak >= 7` 주간 스트릭 뱃지 (handlers/stats.ts:253) 영원히 표시 안 됨
- 사용자(본인 1인 사용)에게 핵심 게임화 피드백 루프 끊김

### 1.2 v3.7 P2-3 (rollback xp on save fail) 잔존

v3.7은 `saveUser` 실패 시 토스트는 띄웠지만, in-memory `user.xp`는 이미 `+= 10`된 상태. 페이지 새로고침 전까지 unsaved 변경이 UI에 잔존 → 새로고침 시 사라져 일관성 깨짐. v3.7 P2-3는 "rollback xp on save fail"을 별 사이클로 deferred.

### 1.3 사이클 결정

본 사이클에서 두 사안을 한번에 정리한다:

- **데드 코드 제거** + **streak 실 wiring** + **단일 atomic API로 통합** (saveUser 1회 호출 → partial-state 부정합 자체 제거)
- **v3.7 P2-3 자연 해소** — atomic single-write이므로 별도 rollback 로직 없이 "fail = 무변경" 보장

## §2 Goals & Non-goals

### Goals

- `user.streak`가 답변 제출 시 의도한 시멘틱(연속 답변 일수)으로 갱신된다
- 같은 날 두 번째 답변은 streak idempotent (xp는 +10 누적)
- `recordActivity` + `checkAndUpdateStreak` 데드 코드 제거. 단일 atomic primitive `recordDailyAnswer(xpDelta)`로 통합
- `applyAnswerActivity`(handlers/home.ts)는 얇은 UI wrapper로 축소 (try/catch + toast)
- saveUser 실패 시 in-memory user 객체 + persisted state 모두 변경 없음 (atomic single-write 보장)
- 회귀 0 — XP/level 계산식 (10 per answer, level=1+floor(xp/100)), 토스트 카피, UI 마크업 모두 동일
- streak 전이 4 시나리오 (Day1 / 연속 / 끊김 / 같은날 재제출) 통합 vitest

### Non-goals

- **streak milestone 토스트 / 레벨업 토스트 / 축하 애니메이션** — 게임화 확장은 별 사이클 (사용자 신호 발생 시)
- **XP 양/공식 변경** — 답변당 +10, level=1+floor(xp/100) 그대로
- **과거 답변 기반 streak backfill** — 본 사이클은 "오늘부터 정상 카운트". 기존 `streak: 0` 사용자는 다음 답변에 streak=1로 시작 (의도된 단순 시작)
- **streak/level UI 마크업 변경** — 홈 탭 streakBanner / xpBadge, stats 탭 levelCard 모두 그대로. 데이터만 정상화
- **앱 부팅 시점 streak 갱신 호출** — Goal 1의 시멘틱은 "답변 제출 = 활동". 부팅만으로는 streak 안 바뀜 (사용자와 합의)
- **v3.9 P2 6건 / per-task P2 9건 closeout** — 별 사이클 (옵션 A "P2 closeout")
- **v3.7~v3.9 잔존 부채(Full i18n / USER_STORAGE dedup / `applyAnswerActivity` state→ui 의존 / module boundary 정비)** — 별 사이클
- **`applyAnswerActivity` 시그니처 변경의 외부 호출처 추적** — 본 사이클 검증으로 호출처는 `submitAnswer` (1곳) + 자체 테스트 (1곳)뿐. 외부 모듈 영향 없음

## §6 Design

### 6.1 `recordDailyAnswer(xpDelta)` API

**Location**: `src/state/user.ts` (`recordActivity` + `checkAndUpdateStreak` 위치 대체)

**Signature**:

```ts
/**
 * 답변 제출 1회의 사용자 활동을 atomic single-write로 기록한다.
 * - streak: 어제 활동했으면 +1, 아니면 1로 리셋. 같은 날 재제출은 idempotent.
 * - xp: xpDelta 누적. level = 1 + floor(xp / 100).
 * - lastActiveDate: 오늘로 갱신.
 *
 * 사용자 데이터가 없으면(`getCachedUser()` null) silent return.
 *
 * @throws {DOMException} saveUser quota/security 에러 (caller에서 try/catch 처리)
 */
export function recordDailyAnswer(xpDelta: number): void {
  const u = loadUserData();
  if (!u) return;
  const today = getDateStr();

  // streak 전이 (같은 날 재제출이면 skip — idempotent)
  if (u.lastActiveDate !== today) {
    const y = new Date(today);
    y.setDate(y.getDate() - 1);
    const yesterday = getDateStr(y);
    u.streak = u.lastActiveDate === yesterday ? u.streak + 1 : 1;
  }

  // xp/level
  u.xp += xpDelta;
  u.level = 1 + Math.floor(u.xp / 100);
  u.lastActiveDate = today;

  saveUser(u);
}
```

**불변량**:

- 호출 후 `lastActiveDate === getDateStr()` 항상 참 (정상 종료 시)
- 호출 후 `level === 1 + Math.floor(xp / 100)` 항상 참
- 같은 날 N번 호출 시 streak 동일, xp는 N*xpDelta 누적
- saveUser throw 시 localStorage 무변경 (브라우저 setItem atomicity), `u`는 함수 지역 변수라 caller에 영향 없음
