## §2 Goals & Non-goals

### 2.1 Goals

- **G1 (A)**: archive 탭의 답변/스크랩 카드를 풍부한 list preview로 재설계. 스크랩 카드는 홈 briefing 카드와 시각적으로 통일. 답변 카드는 질문 미리보기 + 유형 칩 + 답변 본문 3줄 클램프
- **G2 (B)**: 홈 briefing 카드 + archive 스크랩 카드 모두 첫 N장(N=3) `loading="eager"` 적용으로 첫 진입 시 image paint 지연 제거
- **G3 (C-dedup)**: `localStorage['seenBriefings']` 신설. URL 키 + `firstSeenAt` epoch ms. 30일 retention + 500개 LRU cap. fetch 직후 unseen만 사용자에게 노출
- **G4 (C-소스)**: `interestToFeed` (1:1) → `interestToFeeds` (1:N). 6개 unique → **15개 unique** (KR 8 + EN 7). 모든 후보는 rss2json API 통과 사전 검증 완료
- **G5**: 답변 schema에 optional `questionText?: string` 추가 + submitAnswer 저장. 기존 답변(필드 없음)은 archive에서 graceful degrade
- **G6**: 모든 변경 회귀 검증 — vitest +25 it-block, Playwright +1~2 smoke. 번들 +1.5 kB gzip 이내

### 2.2 Non-goals (v3.11 범위 밖)

- **카드뉴스 모드 토글** (archive에서 list ↔ swipe 전환) — 사용자 실 사용 패턴 본 후 v3.12+에서 결정 (YAGNI)
- **사용자가 추가 RSS 소스 등록 UI** — 15개 curated list로 충분, 등록 UI는 별 사이클
- **답변 detail modal에서 인사이트 편집/재평가** — read-only 표시만, 편집은 별 사이클
- **seenBriefings 영구 보존** — 30일 retention 결정 (§4.3 근거)
- **v3.10 P2-1/P2-2** (`updateStreakBanner` 데드 export, `LegacyUser` 별칭 정리) — v3.12+ 별 사이클

### 2.3 Success criteria

- archive 탭 진입 시 답변 카드에 질문 미리보기 + 유형 칩 + 답변 3줄 가시. 스크랩 카드는 홈 briefing과 시각 동일(이미지 + 소스 뱃지 + 제목/summary 오버레이)
- 홈 첫 진입 시 첫 3장 카드의 background image가 카드 paint와 동시 또는 직후에 표시 (이니셜 letter 단계가 사용자 인지 시점에 보이지 않음)
- 같은 사용자가 새로고침을 5회 연속 눌러도 5번 모두 새 기사로 채워짐 (단, 풀이 충분할 때)
- 풀 부족 시(unseen < 5) 30일 이상 된 seen 항목을 fallback으로 허용해 빈 화면이 발생하지 않음
- 15개 feed 중 1~2개가 일시 다운되어도 나머지 feed에서 5장 채울 수 있음

### 3.2 데이터 흐름 — refreshBriefings 신규

```
사용자 click 🔄
   ↓

   ↓ interestToFeeds (1:N) + Set dedup → 최대 8개 feed url cap
   ↓

   ↓ 결과: FeedResult[] (각 feed의 items는 RSS 표준에 의해 pubDate desc)
   ↓ 각 FeedResult.items 안에서 isSeen(url) 항목 제거 (in-place 또는 새 객체)
   ↓
filtered FeedResult[] (= unseen-only)
   ↓
pickBriefings(filtered, 5) → round-robin이라 feed별 최신 1번부터 진행 = "최신 자료만"
   ↓

   ├ yes → 그대로 진행
   └ no  → fallback: 원본 FeedResult[]로 pickBriefings(원본, 5)
              (즉 30d expired seen은 자연 허용 — isSeen이 false 반환하므로)
   ↓
chosen 5장
   ↓

   ↓
hydrateBriefings()
```

### 4.2 seenBriefings 모듈 (신규)

`src/state/seen.ts`:

```ts
const KEY = 'seenBriefings';
const MAX = 500;
const TTL_MS = 30 * 24 * 60 * 60 * 1000; // 30 days

interface SeenRecord { url: string; firstSeenAt: number; }

function loadSeen(): SeenRecord[] {
  try {
    const raw = JSON.parse(localStorage.getItem(KEY) ?? '[]') as unknown;
    if (!Array.isArray(raw)) return [];
    return raw.filter(
      (r): r is SeenRecord =>
        typeof r === 'object' && r !== null
        && typeof (r as SeenRecord).url === 'string'
        && typeof (r as SeenRecord).firstSeenAt === 'number',
    );
  } catch { return []; }
}

function saveSeen(list: SeenRecord[]): void {
  localStorage.setItem(KEY, JSON.stringify(list));
}

/** url이 30일 retention 안에 있으면 true (= 노출 차단) */
export function isSeen(url: string, now: number = Date.now()): boolean {
  const rec = loadSeen().find((r) => r.url === url);
  return !!rec && rec.firstSeenAt + TTL_MS > now;
}

/** chosen url 목록을 seen에 기록. LRU cap = 500. */
export function recordSeen(urls: string[], now: number = Date.now()): void {
  if (urls.length === 0) return;
  const existing = loadSeen();
  const existingMap = new Map(existing.map((r) => [r.url, r]));
  for (const url of urls) {
    if (!existingMap.has(url)) existingMap.set(url, { url, firstSeenAt: now });
  }
  // LRU: firstSeenAt desc 정렬 후 앞에서 MAX개만 유지
  const next = Array.from(existingMap.values())
    .sort((a, b) => b.firstSeenAt - a.firstSeenAt)
    .slice(0, MAX);
  saveSeen(next);
}

/** retention 만료된 항목 제거 (옵셔널 housekeeping; 호출 시점은 refreshBriefings 진입 시) */
export function purgeExpiredSeen(now: number = Date.now()): void {
  const list = loadSeen();
  const next = list.filter((r) => r.firstSeenAt + TTL_MS > now);
  if (next.length !== list.length) saveSeen(next);
}
```

**테스트** (`tests/unit/seen.spec.ts`, ~6 it-block):

- empty/malformed JSON → []
- recordSeen new urls → all stored with same now
- recordSeen with existing url → idempotent (firstSeenAt 변경 안 됨)
- recordSeen 501개 → MAX=500 cap 적용, 가장 오래된 1개 drop
- isSeen 29일 → true / 31일 → false
- purgeExpiredSeen → expired만 drop

### 4.3 dedup retention 30일 근거

| 시나리오 | 영구 | 30일 ← 채택 | 90일 |
|---|---|---|---|
| 본 기사를 한 달 후 우연히 다시 보는 빈도 | 0 | 낮음(사용자가 거의 잊음) | 매우 낮음 |
| 풀 고갈 위험 (interest 1개당 활성 feed 2~3개, 각 feed top 20 가정) | 매우 높음 | 낮음 | 중간 |
| localStorage 양 (URL ~150B 가정) | 무제한 → 장기적 폭주 | ~75 KB(500개 cap) | ~225 KB(500개 cap 동일) |
| 풀 빈약 시 fallback 없음/약함 | 영구 → 결국 empty | 30일 expired 항목 재사용 가능 | 90일도 재사용 가능 |

500 LRU cap은 모든 옵션 공통. 30일이면 사용자 인지 측면 + 풀 신선도 측면 절충.

### 4.6 archive 답변 카드 — `renderAnswerCard`

신규 함수 (handlers/archive.ts 또는 별 모듈):

```ts
function renderAnswerCard(a: Answer): HTMLElement {
  const card = document.createElement('article');
  card.className = 'archive-card archive-card--answer';
  card.dataset['answerId'] = a.id;

  // 헤더: 유형 칩 + 날짜
  const header = document.createElement('div');
  header.className = 'archive-card-header';
  if (a.type) {
    const chip = document.createElement('span');
    chip.className = 'archive-type-chip';
    chip.textContent = toKoType(a.type);  // "🔍 분석형" 등
    header.append(chip);
  }
  const date = document.createElement('time');
  date.className = 'archive-date';
  date.textContent = a.date ?? (a.createdAt ? new Date(a.createdAt).toLocaleDateString('ko-KR') : '');
  header.append(date);

  // ✕ 버튼 (헤더 우측)
  const deleteBtn = document.createElement('button');
  deleteBtn.className = 'archive-card-delete';
  deleteBtn.type = 'button';
  deleteBtn.setAttribute('aria-label', '답변 삭제');
  deleteBtn.textContent = '×';
  header.append(deleteBtn);

  card.append(header);

  // 질문 미리보기 (있으면 1줄, 없으면 muted "질문 정보 없음")
  if (a.questionText) {
    const q = document.createElement('p');
    q.className = 'archive-card-question';
    q.textContent = `❓ ${a.questionText}`;
    card.append(q);
  } else {
    const q = document.createElement('p');
    q.className = 'archive-card-question archive-card-question--missing';
    q.textContent = '질문 정보 없음 (이전 버전 답변)';
    card.append(q);
  }

  // 답변 본문 3줄 클램프 (CSS -webkit-line-clamp: 3)
  const body = document.createElement('p');
  body.className = 'archive-card-body';
  body.textContent = a.text;  // CSS로 클램프, JS에서 truncate 안 함
  card.append(body);

  return card;
}
```

기존 위임 핸들러(`handleCardClick`, line 166~)는 `data-briefing-id` 기반이라 그대로 작동. ✕ 버튼 클릭은 기존 `archive-card-delete` 위임 분기와 호환.

**인터랙티브 핸들러 분리 (T5 review fix)**: `renderBriefingCard`은 home 컨텍스트에서
`setRead(idx)` / `toggleScrap(idx)` / `openMemoModal(idx)`을 closure로 등록한다. archive에서
`idx`는 scrap-filtered subset의 인덱스라서 home full list와 mismatch → 잘못된 briefing이
mutate될 수 있다. 따라서 archive 스크랩 컨텍스트에서는 `.card-actions`(♥/✎) 전체 제거 + `.card-main`
link를 cloneNode으로 교체해 closure 핸들러를 drop한다. 사용자 unscrap action은 ✕ 버튼
(`archive-card-delete` + aria-label `스크랩 해제`)으로 일원화.

## §8 Risks & known limitations

- **R1 (P2)**: 15개 feed 중 일부가 image src에 hotlink-protected CDN 사용 → CSP `img-src` 추가 필요. plan 단계에서 1차 sampling으로 식별, 누락 시 hotfix
- **R2 (P2)**: rss2json API 무료 tier rate limit. 사용자 한 번 refresh당 8개 cap 동시 fetch가 한도에 가까울 수 있음. 5s timeout으로 일부 실패는 graceful, 다만 사용자가 짧은 시간 안에 refresh 반복 시 빈 결과 가능. 별 사이클에서 클라이언트 캐싱 검토(v3.12+)
- **R3 (P2)**: 영어 소스가 늘어 v3.4 번역 큐 부하 ↑. 일일 캡(v3.4 design §X)은 그대로 유지 → 캡 초과분은 미번역 노출. 사용자가 토글로 본문 번역 가능
- **R4 (P2)**: archive 답변 카드의 본문 3줄 클램프 — CSS `-webkit-line-clamp` 사용. 사파리/크롬 호환 OK, 일부 구형 브라우저(IE 등) 미지원 — 대상 사용자(본인 1인) 환경에서 무관
- **R5 (P2)**: 기존 답변(`questionText` undefined)은 archive에서 "질문 정보 없음" 표시. 1회성 backfill 가능하지만 questionId만으로는 풀 질문 텍스트 복원 불가(today_question_<date> 캐시는 당일만 유효) → backfill 비용 vs UX 가치 trade-off 후 별 사이클 고려

## §10 Lessons learned 누적 (반영)

- **Atomic single-write idiom (v3.9, v3.10)**: seen 기록은 chosen list 확정 후 1회 호출(`recordSeen(urls)`). 카드별 호출 안 함
- **Plan/spec drafting fact triangulation (v3.10)**: spec self-review 단계에서 §3.1/§4.4 unique feed 카운트가 14/15로 어긋난 것을 발견 → 일괄 15(KR 8 + EN 7)로 동기화. 마무리 단계 grep 자체점검 강화
- **표준 리뷰 깊이 (v3.10)**: 사이클이 reversible/no-data-destruction이지만 외부 호스트 신규 6개 + 번들 크기 변동 큼 → 표준 리뷰 + verification 한 단계 강화
- **Direct deploy 패턴 유지 (v3.4~v3.10)**: origin remote 미등록. main no-ff merge → build → firebase deploy
