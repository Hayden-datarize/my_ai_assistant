## §1. 목표 · 범위 · Non-goals

### 1.1 목표 (Goals)

1. v3.10에 깔린 XP / streak / level 데이터를 **시각·UX에서 활성화** — 현재 데이터는 있으나 변화에 대한 즉시 피드백/진척감 부재
2. 답변 제출 = 작은 도파민, 레벨업 / streak 마일스톤 = 의미 있는 순간으로 느껴지게
3. 뱃지 컬렉션이 **채워지는 진척감** 제공 (silhouette → unlocked 시각 변화)
4. 게임화 후속 사이클(v3.13 미션, v3.14 캐릭터)이 얹힐 수 있는 **단일 이벤트 진입점** 마련 (`detectEvents` sweep)

### 1.2 In-scope

#### A. 즉시 보상감 (Q3에서 (b) Balanced 강도 채택)

- 답변 제출 → **+10 XP** (현재 `recordDailyAnswer(10)` fixed value, 본 사이클 변경 안 함) floating 숫자 (chat bubble → 우측 `#xpBadge` 방향 1.2초 motion, 도착 시 badge scale pulse + 숫자 increment)
- 레벨업 → **토스트** (`.toast--levelup`) + **CSS-only confetti** burst 1초
- Streak 마일스톤 (3 / 7 / 30 / 100 / 365일) → **토스트** + sessionStorage flag → 다음 stats 진입 시 `#statStreak` 카드 fire 펄스 1회
- 뱃지 unlock → **토스트** (탭 시 상세 modal)

#### B. 뱃지 시스템 (Q2에서 (b) 풍성+silhouette 채택)

- **18 뱃지 catalog** (5 카테고리: Streak 5 / Volume 4 / Tier 3 / Diversity 3 / Engagement 3)
- Silhouette grid — 미획득 = 회색 (`filter: grayscale opacity 0.4`) + 🔒 mini overlay + tap tooltip ("달성 조건: ...")
- Centralized `detectEvents(prev, curr)` sweep (단일 진입점)
- 뱃지 unlock 시각 + ISO date 영구 저장 (`user.earnedBadges` Record)

#### C. 부산물 정리 (touching this code anyway)

- **Tier 시스템 단일화**: 현재 `user.level = 1+floor(xp/100)` ↔ stats `levels[]` thresholds 불일치 → 단일 source `getCurrentTier(xp)` 헬퍼로 통합
- `levels[]` catalog 별도 모듈 (`src/state/leveling.ts`) export
- `user.level` 필드 **제거** (schema v2 마이그레이션)
- 기존 하드코딩 6 뱃지 (`hydrateBadges` 인라인) → catalog 시스템으로 흡수

### 1.3 Non-goals (v3.13+ 또는 영구 보류)

- ❌ 미션 / 주간 챌린지 / 일일 미션 → **v3.13 Game Goals**
- ❌ 캐릭터 진화 / 정원 풀 시각화 → **v3.14 Game World**
- ❌ Streak Freeze 아이템 → v3.13 (미션 도메인)
- ❌ **사운드** — 직장 데스크 환경 고려 (사용자 요청 시 v3.15+)
- ❌ 친구 / 리더보드 / 공유 — 본 앱 개인용 (현재 fit 아님)
- ❌ Push notification → SW 추가 작업 필요 (별도 사이클)

### 1.4 사이클 사이즈 (예상)

- **15 tasks**, 15~17 commits (per-task review fix 1~2 포함)
- 7~10일 (이전 사이클 v3.11 = 10 commits 7일 패턴 기준)

## §2. Tier 시스템 단일화 + 이벤트 Sweep 아키텍처

### 2.1 현재 문제

1. `user.level = 1 + Math.floor(u.xp / 100)` — 무한 단계, 수학적
2. stats `levels[]` (handlers/stats.ts:74-81): 새싹(0)/새잎(100)/나무(300)/숲(600)/산(1000)/하늘(2000) — 6 tiers, MAX 있음
3. `hydrateBadges()`에서 `user.level >= 3` (xp ≥ 200) 체크 시 unlock되지만 표시 tier는 여전히 "새잎" (xp 300 미만) — **불일치**

### 2.3 단일 이벤트 sweep — `src/state/achievements.ts` (신규)

**모듈 의존 방향** (순환 회피):

```
gameTypes.ts (Snapshot, GameEvent 타입 정의만, 순수 type)
    ↑                    ↑
achievements.ts    badgeCatalog.ts
    ↑                    ↑
    └─── achievements.ts re-imports BADGE_CATALOG from badgeCatalog ───┘
```

`Snapshot` / `GameEvent` 인터페이스를 `src/state/gameTypes.ts` 별도 파일로 분리 → `achievements.ts`와 `badgeCatalog.ts` 모두 여기서 import (단방향).

#### gameTypes (`src/state/gameTypes.ts` 신규) — 순수 타입 정의

```ts
// 모든 사이클 공통 — 순환 회피 위해 타입만 분리

  streak: number;

  uniqueScrapCategories: number;

export type GameEvent =
  | { kind: 'xp-gained'; amount: number; at: number }

```

#### achievements (`src/state/achievements.ts` 신규) — 로직 + 진입점

```ts
import type { Snapshot, GameEvent } from './gameTypes';
import { BADGE_CATALOG } from './badgeCatalog';

export function takeSnapshot(userOverride?: User): Snapshot;
export function detectEvents(prev: Snapshot, curr: Snapshot): GameEvent[];
```

`takeSnapshot`은 read-only (`loadUserData`/`loadAnswers`/`loadBriefings` 호출).

`detectEvents` 로직:

`detectEvents` 로직:
- `xp-gained`: `prev.xp < curr.xp` → amount = curr.xp - prev.xp
- `level-up`: `didLevelUp(prev.xp, curr.xp)` non-null
- `streak-milestone`: `[3, 7, 30, 100, 365].some(m => prev.streak < m && curr.streak >= m)`
- `badge`: `BADGE_CATALOG`에서 `!prev.earnedBadgeIds.has(b.id) && !curr.earnedBadgeIds.has(b.id) && b.predicate(curr)`

#### 후속 처리 (test 격리 위해 분리)

```ts
export function persistUnlocks(events: GameEvent[]): void;  // user.earnedBadges 갱신
export function emitEvents(events: GameEvent[]): void;      // CustomEvent dispatch
export function runSweep(prev: Snapshot, curr: Snapshot): void {
  const events = detectEvents(prev, curr);
  if (events.length === 0) return;
  persistUnlocks(events);
  emitEvents(events);
}
```

### 2.4 진입점 (3곳)

**중요**: saveUser가 throw(QuotaExceeded 등)하면 sweep을 **실행하지 않음**. in-memory `u`는 mutate되어 있어도 persist 안 된 상태이므로 이벤트 emit이 false-fire가 됨. try/catch로 보호.

```ts
// src/state/user.ts — recordDailyAnswer
export function recordDailyAnswer(xpDelta: number): void {
  const u = loadUserData();
  if (!u) return;
  const prev = takeSnapshot(u);
  // ... existing mutation (streak / xp / lastActiveDate) ...
  try {
    saveUser(u);
  } catch (e) {
    // Quota 등 — sweep 안 함, 호출자가 에러 UX 표시 (v3.7 정책)
    throw e;
  }
  const curr = takeSnapshot(u);
  runSweep(prev, curr);
}

// src/state/briefings.ts — toggleScrap (스크랩 unlock 검출)
//   동일 패턴: prev → mutate → save → curr → runSweep, save 실패 시 sweep 생략
// memo save — 정확한 위치는 plan 작성 시 grep으로 확정
//   (현재 가설: src/state/briefings.ts mutate(index, b => b.memo = ...) 또는
//    src/ui/modals/memo.ts save 핸들러). T4 plan에서 확정.
```

**Test 추가 (T4 DoD)**: `saveUser` mock이 throw 시 `emitEvents` 호출 안 됨 검증.

## §4. 데이터 모델 · Persistence · Migration

### 4.1 User 스키마 v1 → v2

**v1 (현재)**:
```ts
interface User {
  name, interests, onboardedAt, streak, lastActiveDate, xp, level
}
```

**v2 (이번 사이클)**:
```ts
interface User {
  name, interests, onboardedAt, streak, lastActiveDate, xp,
  // ❌ removed: level (compute from getCurrentTier(xp))
  // ✅ added:
  earnedBadges: Record<string, number>; // badgeId → unlockedAt epoch ms
  gamificationMigrated: boolean;        // 환영 모달 1회 보장 flag
  schemaVersion: 2;                     // 신규 필드 (이후 마이그레이션 식별 용이)
}
```

### 4.2 Lazy Migration

`loadUserData()` 호출 시 inline 검사. `schemaVersion`이 없거나 `< 2` → v2로 변환 후 saveUser 1회.

```ts
function migrateUserToV2(raw: any): User {
  const v2 = { ...raw, schemaVersion: 2 };
  delete v2.level;
  v2.earnedBadges = v2.earnedBadges ?? {};
  v2.gamificationMigrated = false;  // backfill + 환영 모달은 T13에서 처리
  return v2 as User;
}
```

**중요**: backfill (이미 자격 있는 뱃지 unlock)은 T13 (환영 모달)에서 처리. T2 마이그레이션은 schema bump + 빈 객체만.

### 4.3 첫 진입 환영 모달 (T13)

**Trigger 시점**: 매 home 탭 활성화 시 (initial app mount 포함, `switchTab('home')` effect). `gamificationMigrated` flag로 idempotent — 한 번 fire 후 영구 skip.

**Trigger 조건**: `!user.gamificationMigrated && answers.length >= 1`

순서:

1. backfill: BADGE_CATALOG 순회 → predicate 만족하는 뱃지 모두 `earnedBadges[id] = now` (try/catch — backfill 실패해도 schema는 보존, 빈 컬렉션으로 시작)
2. 환영 modal 표시 (unlocked mini-grid + "stats에서 보기" 버튼)
3. 모달 닫기 시 `user.gamificationMigrated = true` saveUser

신규 user (answers = 0): 환영 모달 안 띄움. 첫 답변 제출 후 자연 unlock.

### 4.4 unlock 이벤트 로그 — 보관 안 함

토스트는 transient. `earnedBadges[id]` (timestamp)만 영구 저장.
"최근 획득한 뱃지" 표시는 unlockedAt desc 정렬로 derive.

### 4.5 localStorage 키 변경 0건

- `'user'` 키 그대로, 내부 schema만 v1→v2
- 답변/브리핑/슬랙 등 다른 키 변경 없음
- 신규 키 추가 없음

### 4.6 저장 비용

- 18 badges fully unlocked: ~600 bytes
- 추가 필드 (earnedBadges + gamificationMigrated + schemaVersion): 무시 가능
- localStorage 5MB 한도 대비 0.01% — 무관

## §5. UX · Animation 명세

### 5.1 이벤트 → UI 매핑 (단일 진입점)

`src/ui/rewards.ts` (신규)가 4 CustomEvent listen + 큐잉/렌더링.

| Event kind | CustomEvent name | UI 효과 |
|---|---|---|
| `xp-gained` | `dg:reward:xp-float` | floating 숫자 (chat bubble → `#xpBadge`) + xpBadge ping |
| `level-up` | `dg:reward:level-up` | 토스트 (`.toast--levelup`) + CSS-only confetti 1초 |
| `streak-milestone` | `dg:reward:streak-milestone` | 토스트 (`.toast--streak`) + sessionStorage flag |
| `badge` | `dg:reward:badge-unlock` | 토스트 (`.toast--badge`, "자세히" 버튼) → 탭 시 modal |

### 5.2 +XP Floating Motion

- 시작점: chat bubble 우측 가장자리 `getBoundingClientRect()`
- 끝점: `#xpBadge` 중앙 `getBoundingClientRect()`
  - **Fallback**: `xpBadge.checkVisibility()` 또는 width === 0 → 화면 우측 상단 absolute 좌표 (sidebar 닫힘 / 다른 탭 진입 시)
- Duration: 1.2s
  - 0~1.0s: translateXY 시작→끝, ease-out
  - 1.0~1.2s: opacity 1→0
- 도착 시 `#xpBadge` `.badge-pulse` add 300ms (scale 1→1.15→1, textContent 갱신)
- 요소: `<span class="xp-float">+10 XP</span>` 동적 생성

### 5.3 Level-up

- 토스트 `.toast--levelup` (4초, 일반 토스트보다 김 — 의미 부여)
  - 내용: "🌳 **나무** 레벨 달성!"
- **CSS-only confetti** (~30줄 CSS + ~15줄 JS):
  - viewport 중앙에서 30개 `<span class="confetti-particle">` 생성
  - inline style로 `--angle`, `--color`, `--delay` CSS variable 주입
  - keyframes 1개: 1초 fall + spin + opacity 1→0
  - canvas-confetti library **미도입** → bundle +1.5kB 절약
- 구현: `src/ui/rewards.ts` `playConfetti()` 함수

### 5.4 Streak Milestone

- 토스트 `.toast--streak` (3초): "🔥 **7일** 스트릭!"
- 동시에 `sessionStorage.setItem('dg:streakPulsePending', String(days))`
- **stats 탭 진입 시 hydrate**:
  ```ts
  const pending = sessionStorage.getItem('dg:streakPulsePending');
  if (pending) {
    document.getElementById('statStreak')?.classList.add('fire-pulse');
    sessionStorage.removeItem('dg:streakPulsePending');
  ```

- sessionStorage 영구 안 함 — 토스트가 primary, fire 펄스는 보너스

### 5.5 Badge Unlock

## §7. 위험 · 미해소 항목

### 7.1 Risks

| Risk | Mitigation |
|---|---|
| Migration backfill 시 `loadAnswers()` corrupt → user 진입 막힘 | T13 backfill try/catch graceful — 빈 컬렉션으로 시작, schema bump은 보존 |
| 토스트 4+개 동시 unlock 시 사용자 피로 | max 3 cap, 4번째부터 silent persist (다음 stats 방문 시 발견) |
| confetti CSS-only 30 particles 성능 | low-end mobile에서도 CSS transform 30개는 무리 없음 (검증: T8 후 실제 device test) |
| sessionStorage flag 새로고침 시 lost | fire 펄스는 보너스 — 토스트가 primary, 사용자는 정보를 이미 받음 |
| `engagedInterests` derive — 답변엔 카테고리 매핑 없음 | 단순화: 스크랩 카테고리만 사용 (만물박사 predicate가 답변 조건 제거) |
| `xpBadge` non-home tab 시 위치 측정 실패 | `checkVisibility()` 또는 width 0 시 화면 우상단 fallback 좌표 |
