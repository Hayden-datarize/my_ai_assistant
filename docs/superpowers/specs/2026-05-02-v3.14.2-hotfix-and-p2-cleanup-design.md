**v3.14.2**는 두 가지를 한 사이클에 묶는다:

### 1.1 사이클을 한 번에 묶는 이유

- P0와 P2를 분리하면 main 배포가 두 번 발생 → 사용자 부담 증가.

### 1.2 명시 제외 항목

- **v3.14 잔존 IntersectionObserver 변형** — design 변경 동반, 사용자 결정 대기.
- **v3.14 잔존 6탭 mobile 375px 라벨 wrap (P3)** — 측정값 부재, 다음 사이클에서 측정+결정 묶음.

- **v3.7+v3.13.1 silent-fail 정책** — 이미 통일 완료, 재처리 불필요. (P2-NEW-4는 손상 v2 silent path만 추가)

## 9. 사이클 lesson 사전 anchor (Plan controller용)

v3.14·v3.14.1 메모리에서 정착된 controller lesson을 Plan 작성 시 체크리스트화:

1. **Plan fixture는 codebase 실제 schema와 사전 grep** — Briefing/Mission/User type, LocalStorage KEY, function signature.
2. **Per-task review의 spec+quality 2단계** 유지 — quality에서 잡히는 P2가 spec review로는 안 잡힘.
3. **Codex 2-pass default** — substantial cleanup cycle.
4. **State→ui 역방향 의존 회피는 사이클 시작 시점에 결정** — T1 prerequisite로 분리.
5. **JSDoc invariant ≠ enforcement** — invariant 추가 시 실제 callers에 적용 verify 필수, test도 paired-call 형태가 베스트.
6. **Pre-existing 정책 violation 처리** — 같은 도메인 cleanup 시 묶어서 처리 (scope creep ≠ policy uniformity).
7. **Plan accounting per-file count 합산 검증** — v3.14.1 lesson #1 재발 방지.
