## §1. T1 — Slack DM Relay App Check Enforcement (P0 F1)

### 1.1 Finding 요약 (Codex)

- **File**: `functions/src/sendAnswerDm.ts:28`
- **Symptom**: 누구나 `curl -X POST https://us-central1-my-ai-assistant-904f3.cloudfunctions.net/sendAnswerDm` 로 body 조작 → `@datarize.ai` 도메인 이메일 대상 Slack DM 발송 시도. `user_not_found` vs success 응답 차이로 직원 enumeration 가능.
- **Root cause**: CORS는 브라우저 제약만, server-side 호출은 통과. App Check/Auth/HMAC/timestamp replay guard 부재.

### 1.2 결정

**Minimal App Check only** (user-level Firebase Auth는 v3.42+ deferred):

1. Firebase Console: App Check site key 발급 (**[v2 — Codex P1-1] reCAPTCHA v3 default** — 무료. Enterprise는 GCP billing 활성 시만)
2. Frontend (신규 `src/services/appCheck.ts`): `initializeAppCheck` + `getToken()` → `X-Firebase-AppCheck` header
3. Backend (`functions/src/sendAnswerDm.ts`): `onRequest` config에 `enforceAppCheck: true` 추가
4. **[v2 — Codex P1-8] Error response generic화 + UX copy reconcile**:
   - `user_not_found` → `202 Accepted` + `{ok: true, accepted: true}` (enumeration 차단)
   - `src/ui/tabs/settings.ts` 테스트 버튼 success copy 수정: "전송 요청을 접수했어요. DM이 오지 않으면 봇 설치/이메일을 확인해주세요"
   - `@gmail.com` 같은 domain invalid는 400 유지 (기존 동작)
5. Regression test 추가: App Check token 부재 시 401, `nonexistent@datarize.ai`는 202 generic (enumeration 차단 확인), 정상 → 200
6. **[v2 — Codex P1-1] 2-phase rollout (production race 차단)**:
   - **Phase A** (T1 deploy): site key 등록 (Console enforce OFF/monitor), frontend `getAppCheckToken()` deploy, DevTools에서 `X-Firebase-AppCheck` header 발급 확인, 최소 24시간 monitor (token 발급률 ≥ 99%)
   - **Phase B** (T8 deploy 후 별도): backend `enforceAppCheck: true` deploy + Console enforce ON
   - Phase A/B 사이 frontend monitor 결과는 retro §9.4에 기록

### 1.3 변경 범위

**신규 파일**:
- `src/services/appCheck.ts` — Firebase App Check init + token getter

**수정 대상**:
- `src/services/slack.ts` — `fetch('/api/sendAnswerDm', ...)` header에 App Check token 추가
- `src/ui/tabs/settings.ts` — **[v2 — Codex P1-8]** 테스트 버튼 success copy 갱신 (`user_not_found` 202 generic 대응)
- `functions/src/sendAnswerDm.ts` — **Phase B에서** `enforceAppCheck: true` + error response generic화 + `user_not_found` 202 처리
- `functions/src/__tests__/sendAnswerDm.spec.ts` (신설) — App Check + enumeration 차단 regression
- `package.json` — `firebase` (v10+) frontend dep 추가 (이미 있으면 skip)
- `index.html` — App Check debug token meta (개발 환경 only)
- `firebase.json` — App Check 활성화 확인

- App Check site key 발급은 Firebase Console (외부) 작업 → 사용자 1회 필요 (실행 가능한 콘솔 권한 확인)

## §2. T2 — AI Evaluation Score Guard (P1 F2)

### 2.1 Finding 요약 (Codex)

- **File**: `src/ui/handlers/archive.ts:1162`, `src/ui/handlers/stats.ts:450`, `src/services/gemini.ts:88`
- **Symptom**: Gemini가 `score`를 string으로 반환하거나 localStorage 손상 시 archive/stats modal `bodyHtml` raw interpolation → XSS 가능.
- **Root cause**: `parseJsonText<{ score: number; feedback: string }>(text)` 은 generic type assertion만 — runtime check 없음. `answer-detail.ts`는 type guard 있는데 archive/stats path 누락.

### 2.2 결정 — Single Fix Point (v3.31 L5)

`src/services/gemini.ts`에 **`parseEvaluationResponse(text): { score: 1|2|3|4|5; feedback: string }`** 신설:

1. **[v2 — Codex P1-3] `parseJsonText` throw 흡수 의무**: 내부에서 try/catch — malformed/plain text/garbage JSON 시 `{score:3, feedback:''}` + `console.warn('[parseEvaluationResponse] parse failed', err)` 확정. caller에 throw 전파 X.
2. `score`: `Number(raw.score)` → `Number.isInteger` + clamp 1~5 → 미충족 시 `3` fallback + `console.warn`
3. `feedback`: `typeof === 'string'` + length ≤ 500 → 미충족 시 empty string

또한 **[v2 — Codex P2-1]** `src/state/migration.ts`의 `migrateAnswer`는 **read-time normalize only (write-back 없음)** — `loadAnswers` 매 호출 시 normalize 적용, idempotent. 기존 legacy key 1회 write-back과 분리.

렌더링 path는 `escapeHtml(String(score))` + `escapeHtml(feedback)` 적용 (이미 feedback은 escape됨, score만 추가).

### 2.3 변경 범위

- `src/services/gemini.ts` — `parseEvaluationResponse` export
- `src/state/migration.ts` — `migrateAnswer` evaluation normalize 추가
- `src/ui/handlers/archive.ts:1162` — score 렌더 `escapeHtml(String(...))` 적용
- `src/ui/handlers/stats.ts:450` — 동일
- `tests/unit/gemini-parse.spec.ts` — `parseEvaluationResponse` table-driven **[v2 — Codex P1-3] 케이스 11**: (1) valid `{score:3, feedback:"good"}` (2) string score `"5"` coerce (3) out-of-range `6` fallback (4) negative `-1` fallback (5) non-integer `2.5` fallback (6) missing `feedback: null` (7) **fenced ` ```json {...}``` ` (Gemini 흔한 응답)** (8) **garbage prefix + valid JSON** (9) **malformed JSON throw → fallback `{3, ''}`** (10) **plain text "score 5점"** → fallback (11) empty `{}` → fallback
- `tests/unit/migration.spec.ts` — evaluation normalize 회귀

### 2.4 Risk

- Gemini 응답 schema change 시 fallback `3`이 silent corruption처럼 보일 수 있음 → console.warn 출력 (v3.40 L1 silent fail 회피)
- **[v2 — Codex P2-1]** Migration normalize timing — **read-time normalize only, write-back 없음**. `loadAnswers` 매 호출마다 적용. idempotent 보장.

### 3.2 결정

1. `CACHE_NAME = 'daily-growth-v10'` (bump)
2. `fetch` handler 진입에서 `event.request.method !== 'GET'` → `return` (cache 우회)
3. `/api/`로 시작하는 path도 `return` (functions 호출 우회)
4. Navigation request (`event.request.mode === 'navigate'`) → **network-first** with cached `/index.html` fallback (offline 시에만 cache)
5. 정적 asset (`/assets/index-*.js` 등 hashed)만 cache-first 유지

### 3.3 변경 범위

- `public/sw.js` — CACHE_NAME bump + method/path 가드 + navigation strategy 분기
- **[v2 — Codex P1-4] 기존 spec 보존 + 갱신 의무**:
  - `tests/unit/sw.spec.ts` (image/font pass-through regression — v3.20 hotfix 보호)

### 5.2 결정

```ts
export function reportAsync<T>(label: string, p: Promise<T>): Promise<T | undefined> {
  return p.catch(err => {
    console.warn(`[reportAsync:${label}]`, err);
    // 토스트는 옵셔널 — 환경 mount 안된 상태 가능
    try { showToast(`${label} 로드 실패 — 새로고침 해주세요`); } catch { /* noop */ }
    return undefined;
  });
}
```

`src/main.ts`의 3개 dynamic import 모두 `reportAsync('welcome-garden', import(...).then(...))` 패턴으로 wrap.

### 5.3 변경 범위
