## 1. Background & Motivation

v3.2a-hotfix 배포(tip `e50562b`) 이후 일상 사용에서 다섯 가지 불편이 남았다:

1. **데스크탑 레이아웃이 모바일과 동일** — `.app-container` 데스크탑 max-width 960px, bottom-nav 그대로 (mobile viewport에 최적화). Hayden은 업무 중 1280–1440px 모니터에서 사용.
2. **답변 제출 버튼이 하단 네비게이션에 가림** — narrow viewport에서 `#submitBtn` 클릭이 nav로 landing. v3.2a Task 8에서 발견되어 Playwright는 CustomEvent로 우회했지만 실사용 UX는 남아있음(v3.2a spec §12 Follow-ups 참조).
3. **통계·인사이트·설정 탭 콘텐츠도 하단 nav에 가림** — `#homeTab`은 `padding-bottom: calc(--nav-height + --safe-bottom + 24px)`로 보호되지만 다른 탭들은 보호 없이 `.app-container` 공통 패딩에만 의존.
4. **브리핑 카드 중복** — 여러 관심사가 같은 RSS로 매핑(`handlers/home.ts:295-313`의 `interestToFeed`에서 `medium.com/feed/daangn` ×3, `lifehacker.co.kr/feed` ×4)되어 동일 기사가 카드 2~3개로 표시됨. 출처 식별도 불가능.
5. **히트맵 요일 정렬 버그** — `handlers/stats.ts:117-132`는 28일 단순 역순 렌더. 상단 요일 라벨은 [월~일] 고정인데 column 정렬은 `new Date()` 오늘 요일에 따라 우연히 맞거나 틀림.

v3.2b sub-group을 **ui**(이 세션, 매일 불편 해소)와 **features**(다음 세션, weekly 리포트 + 성장 분석 + Playwright SW coverage)로 분할. Notion 연동은 v3.2c로 별도 분리. 본 spec은 ui 단계만 다룬다.

## 5. Section B — 브리핑 dedup + source chip

### 5.1 `fetchFeed` 시그니처 변경 (services/rss.ts)

```ts
export interface FeedItem {
  title: string;
  link: string;
  description: string;
  pubDate: string;
}

export interface FeedResult {
  items: FeedItem[];
  sourceTitle: string;  // rss2json `feed.title` (e.g. "toss tech blog")
}

export async function fetchFeed(
  feedUrl: string,
  opts: { timeoutMs?: number } = {},
): Promise<FeedResult> {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), opts.timeoutMs ?? 5000);
  try {
    const url = `https://api.rss2json.com/v1/api.json?rss_url=${encodeURIComponent(feedUrl)}`;
    const r = await fetch(url, { signal: controller.signal });
    if (!r.ok) return { items: [], sourceTitle: '' };
    const data = (await r.json()) as {
      items?: FeedItem[];
      feed?: { title?: string };
    };
    return {
      items: Array.isArray(data.items) ? data.items : [],
      sourceTitle: data.feed?.title ?? '',
    };
  } catch {
    return { items: [], sourceTitle: '' };
  } finally {
    clearTimeout(timer);
  }
}
```

**호환 전략:** `fetchFeed`의 기존 호출부는 `handlers/home.ts:254`가 유일(grep 결과). 동일 PR에서 호출부를 함께 수정. 타입 체크가 drift를 잡는다.

### 5.2 dedup 알고리즘 (handlers/home.ts `refreshBriefings`)

```ts
async function refreshBriefings(): Promise<void> {
  const user = loadUser();
  if (!user || user.interests.length === 0) {
    showToast('관심 분야를 먼저 설정해 주세요');
    return;
  }
  // …loading placeholder unchanged…

  // 1) 관심사 3개를 각 feed URL로 변환 (중복 URL은 Set으로 제거)
  const picks = user.interests.slice(0, 3);
  const feedUrls = Array.from(
    new Set(picks.map(interestToFeed).filter((u): u is string => !!u)),
  );

  // 2) 각 feed를 한 번씩 fetch (병렬). 내부에서 items[0..n] 보관
  const fetched = await Promise.all(
    feedUrls.map((u) => fetchFeed(u, { timeoutMs: 5000 })),
  );

  // 3) dedup + 3장 보장:
  //    - 각 feed에서 items[0]부터 순회, 이미 seen 에 있는 link는 건너뜀
  //    - 3장 모이면 stop
  const seen = new Set<string>();
  const picked: Array<{ item: FeedItem; sourceTitle: string }> = [];
  const TARGET = 3;
  // round-robin: 각 feed의 i번째 아이템을 순차로 보면서 dedup
  const maxPerFeed = Math.max(...fetched.map((f) => f.items.length), 0);
  outer: for (let i = 0; i < maxPerFeed; i++) {
    for (const feed of fetched) {
      const item = feed.items[i];
      if (!item) continue;
      if (seen.has(item.link)) continue;
      seen.add(item.link);
      picked.push({ item, sourceTitle: feed.sourceTitle });
      if (picked.length >= TARGET) break outer;
    }
  }

  const today = getDateStr();
  const stored: Briefing[] = picked.map(({ item, sourceTitle }, i) => ({
    id: `b_${Date.now()}_${i}`,
    date: today,
    url: item.link,
    title: item.title,
    summary: stripTags(item.description).slice(0, 200),
    scrapped: false,
    read: false,
    memo: '',
    sourceTitle: sourceTitle || undefined,   // optional — 빈 문자열이면 저장 X
  }));
  saveBriefings(stored);
  hydrateBriefings();

  if (stored.length === 0) {
    // …기존 empty state 로직 그대로…
  }
}
```

**결정 근거:**

- **round-robin vs 직렬 drain**: 같은 feed(같은 interest 반복 매핑)만 있으면 직렬로 items[0], items[1], items[2]를 뽑아도 되지만, feed가 2개면 `[feedA[0], feedB[0], feedA[1]]`이 더 다양성 높음. 3장 보장용.
- **3장 미만 허용**: 모든 feed가 비어도 현재와 동일하게 empty state로 떨어짐. 일부만 채워지면 그대로 1~2장 표시(기존 동작 유지).
- **`seen: Set<string>`의 키는 link 기준**: 같은 글이 여러 feed에 실리는 경우(드뭄) 방지. title 기반 dedup은 미디엄 "Medium Daily Digest" 같은 뉴스레터성 아이템에서 오히려 오탐(같은 제목 다른 날짜).

```ts
function hydrateHeatmap(): void {
  const grid = document.getElementById('heatmapGrid');
  if (!grid) return;
  grid.replaceChildren();

  // labels (unchanged) …

  const answers = loadAnswers();
  const counts = new Map<string, number>();
  // …counts 계산 unchanged…

  const today = new Date();
  const DAYS = 28;

  // ISO weekday: 월=0, 화=1, …, 일=6 (라벨 배열 인덱스와 일치시킴)
  const isoIdx = (d: Date) => (d.getDay() + 6) % 7;   // Date.getDay: 일=0..토=6 → 월=0..일=6

  // firstDay = today - 27d
  const firstDay = new Date(today);
  firstDay.setDate(today.getDate() - (DAYS - 1));
  const leadingBlanks = isoIdx(firstDay);          // 0~6
  const todayIdx = isoIdx(today);
  const trailingBlanks = 6 - todayIdx;             // 0~6

  // 1) leading blanks
  for (let i = 0; i < leadingBlanks; i++) {
    const blank = document.createElement('button');
    blank.type = 'button';
    blank.className = 'heatmap-cell is-blank';
    blank.disabled = true;
    grid.append(blank);
  }

  // 2) 28 data cells (오래된 순)
  for (let i = 0; i < DAYS; i++) {
    const d = new Date(firstDay);
    d.setDate(firstDay.getDate() + i);
    const key = d.toISOString().slice(0, 10);
    const n = counts.get(key) ?? 0;
    const level = Math.min(3, n);
    const cell = document.createElement('button');
    cell.type = 'button';
    cell.className = `heatmap-cell level-${level}`;
    if (isoIdx(d) >= 5) cell.classList.add('is-weekend');   // 토=5, 일=6
    cell.dataset['date'] = key;
    cell.title = `${key}: ${n}개`;
    cell.addEventListener('click', () => showDayDetail(key));
    grid.append(cell);
  }

  // 3) trailing blanks
  for (let i = 0; i < trailingBlanks; i++) {
    const blank = document.createElement('button');
    blank.type = 'button';
    blank.className = 'heatmap-cell is-blank';
    blank.disabled = true;
    grid.append(blank);
  }

  // 셀 수 불변식: (leading) + 28 + (trailing) = 7의 배수
  // leading + 28 + trailing = leading + trailing + 28
  // leading = isoIdx(firstDay), trailing = 6 - isoIdx(today)
  // firstDay = today - 27d → isoIdx(firstDay) = (isoIdx(today) - 27) mod 7 = (isoIdx(today) + 1) mod 7
  // ⇒ leading + trailing = ((isoIdx(today)+1) + (6 - isoIdx(today))) mod 7 = 7 mod 7 = 0
  // ⇒ 총 cell 수 = 28 (정확히 4주). 단위 테스트가 이 불변식을 검증.
}
```

**주석으로 명시할 불변식:** `leadingBlanks + trailingBlanks ≡ 0 (mod 7)`, 따라서 항상 28개 cell = 4행.

## 10. Security / Accessibility

- 신규 문자열(briefing `sourceTitle`, 라벨 요일)은 모두 `textContent` 할당 → XSS 안전
- CSP/외부 호스트 변경 없음 → firebase.json 무변경
- sidebar(desktop) `.nav-item`에 `aria-current="page"`는 기존 모바일 nav와 동일하게 active state에서 부여(이미 구현되어 있으면 그대로, 아니면 범위 외). **Plan Discovery §11.5**에서 확인
- 주말 색 강조는 색상만으로 의미 전달하지 않음 — 라벨 텍스트(토/일) + cell hover title이 함께 정보 제공(WCAG 1.4.1 Use of Color 준수)
- blank cell `disabled` 속성 + `pointer-events: none`으로 키보드 포커스·클릭 모두 차단
