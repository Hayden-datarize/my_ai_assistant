## §1. 목표 · 범위 · Non-goals

### 1.1 목표 (Goals)

1. v3.12 즉시 보상 + 18 뱃지(에버그린 누적) + v3.13 Daily/Weekly/Monthly 미션(주기 자극) 위에 **분기 단위 macro horizon (분야별 식물 진화)** 레이어를 얹어 게임화 시리즈 3-tier 호흡 (초~일 / 일~월 / 월~분기) 완결.
2. 사용자 관심분야별 식물이 그 분야 활동(스크랩+메모 매칭)에 따라 진화 → "이번 분기 나는 어느 분야에 깊었나" 분야별 자기 회고 시각화.
3. v3.13 spec §1.1-4 의 약속 — *"v3.14 캐릭터 사이클이 미션 완수를 anchor로 삼을 수 있게 `cumulative.{period}Count` 카운터 인프라 마련"* — 정확 이행. 미션 완수 = 모든 식물에 양분 ("정원에 비").
4. v3.12 환영 모달 / detectEvents sweep / 토스트 / confetti 인프라 100% 재사용으로 **코드 일관 + 신규 LOC 최소화**.

### 1.2 In-scope (Q1~Q12 brainstorm 합의 → §9 요약 참조)

#### A. 식물 시스템 (Q1=B 정원 / Q2=A 분야별 1:1 매핑 / Q4=B 5 stage / Q5=B max만 분야별)

- **메타포**: 정원 — 사용자 관심분야별 식물 컬렉션 (분야별 1:1).
- **개수**: user.interests N개 (1~6 가변) = 식물 N개. 사용자 정의 분야는 fallback emoji 사용.
- **Stage**: 5단계 (씨앗 → 새싹 → 줄기 → 봉오리 → 꽃/만개) exponential 곡선.
- **시각**: emoji 기반 (v3.12 `icon: string` 컨벤션 follow).
  - Stage 1~4 = 분야 공통: 🌱 / 🌿 / 🌷 / 🌳
  - Stage 5 = 분야별 차별화: AI 🤖🌸 / 디자인 🎨🌹 / 경제 💰🌷 / 트렌드 🚀🌺 / 실무 📊🪴 / 성장 ⭐🌳 (정확 emoji는 plan 단계에서 OS 호환 검증 후 확정)

#### B. 진화 trigger source (Q3=C 분야 활동 + 미션 완수 보너스)

- **분야 활동** = 그 분야로 매칭된 신규 스크랩 (interestKeywords 매칭) + 매칭된 스크랩 중 메모 작성 (메모는 +1 추가). 답변은 분야 매핑 없으니 분야별 식물 진화 source에서 **제외**.
- **미션 완수 보너스** = 모든 식물에 동시 +N (v3.13 anchor 이행):
  - daily 1개 완수 → 모든 식물 +1
  - weekly 1개 완수 → 모든 식물 +5
  - monthly 1개 완수 → 모든 식물 +20
- 진화 threshold (cumulativeActivity 누적 boundary):
  - 1→2 = **8** (heavy 4일 / casual 1주)
  - 2→3 = **25** (heavy 2주 / casual 3주)
  - 3→4 = **70** (heavy 5주 / casual 2달)
  - 4→5 = **160** (heavy 2.5달 / casual 5달)

#### C. UI/UX (Q6=C hybrid / Q11=A 환영 모달 + backfill)

- **홈 탭 mini preview row** = greeting/streakBanner 아래 1줄 horizontal cells. 분야 N개, 각 ~50px (emoji + 짧은 라벨 + ✨ 영구 마크). 탭 시 stats 탭 navigate.
- **Stats 탭 full grid** = 기존 [streak/level/answers/scraps/뱃지] 아래 새 섹션 "내 정원". 3 col responsive (narrow = 1 col), 각 카드 ~120px × ~160px (emoji + 분야명 + stage 라벨 + cumulativeActivity 카운트 + ✨ 마크).
- **환영 모달** (첫 v3.15 진입 1회) = "🌱 정원이 새로 생겼어요" + backfill 결과 highlight + "정원 보러 가기" CTA → stats 탭 자동 scroll.
- **Stage 4→5 도달 effect** = 토스트 ".toast--bloom" + CSS confetti burst (v3.12 .toast--levelup 패턴 재사용) + 영구 ✨ 마크.

#### D. 부가 정책 (Q7=B wilting / Q8=B archive / Q10=B 트로피 + stay)

- **Wilting** = `lastEngagedAt` 7일+ 이전 → 식물 cell에 `.wilting` 클래스 (opacity 0.5 + grayscale 0.4 + 약간 기울기). 활동 1회 시 즉시 vivid 복귀. **stage는 절대 변하지 않음** (visual only).
- **Archive + 복원** = 분야 제거 시 `plantStateByInterest` entry 그대로 유지, grid에서만 숨김 (`user.interests.includes(id)` 로 visibility 결정). 분야 재추가 시 기존 entry 복원 (cumulativeActivity / stage 보존).
- **Max stage 후** = stage 5 stay (regression 0). 추가 활동 카운트는 cumulativeActivity 누적 계속 (visibility는 안 변함, stage 5 영구 유지). ✨ 영구 마크.

#### E. Backfill (Q11=A 패턴)

첫 v3.15 진입 시 1회 (`gardenBackfilled === false`):
- 사용자 관심분야 각각에 대해 `loadBriefings()` → scrapped + `interestKeywords` 매칭 카운트.
- 메모 작성된 매칭 스크랩은 +1 추가 (스크랩 1 + 메모 1 = 2 활동).
- threshold lookup으로 stage derive.
- `lastEngagedAt = 진입 시각 (오늘)` — 첫 인상 wilting 회피 (관대한 처리, §3.4 self-review fix).
- stage === 5 → `unlockedAt = 오늘` 셋.
- `gardenBackfilled = true` 셋, idempotent.

### 2.3 Schema v4 (User 확장)

```ts
interface PlantState {
  stage: 1 | 2 | 3 | 4 | 5;            // 식물 단계 (씨앗~만개)
  cumulativeActivity: number;           // 누적 분야 활동 카운트
  unlockedAt?: string;                  // stage 5 도달 ISO (영구 ✨ 마크용)
  lastEngagedAt?: string;               // 마지막 활동 ISO (wilting 판단)
}

interface User {
  // ... v3 fields 모두 유지
  schemaVersion: 4;                              // v3 → v4
  plantStateByInterest: Record<string, PlantState>;  // interestId → 식물
  gardenIntroduced: boolean;                     // 환영 모달 1회 보장 (v3.12 gamificationMigrated 패턴)
  gardenBackfilled: boolean;                     // backfill 1회 idempotent
}
```

**필드 설계 정당화** (Section 1 self-review fix 반영):

- `archived` 필드 제거: 분야 visibility는 `user.interests.includes(interestId)` 로 결정. `plantStateByInterest`는 user.interests와 독립적으로 유지 — entry 보존이 곧 archive, 재추가 시 자동 복원.
- `stage: 0` 제거: entry 자체가 없으면 식물 미생성. 식물 생성 즉시 stage 1 (씨앗)부터 시작.
- `unlockedAt` vs `lastEngagedAt` 분리: 영구 트로피 시각과 wilting 판단 시각은 의미가 다름 (합치면 ✨ 영구성 잃음).

### 2.4 진입점 / 데이터 흐름

```
[사용자 활동]                     [엔진 호출]                      [이벤트]
─────────────────────────────────────────────────────────────────────────
스크랩 toggle (briefings.ts)     → matchInterests(briefing)
                                 → forEach 매칭 분야:
                                     tickPlantActivity(user, id, +1)
                                 → saveUser → runSweep                → plant-stage-up?

답변 제출 (recordDailyAnswer)    → tickMissionProgress (기존)
                                 → 미션 완수 시 applyMissionBonus     → plant-stage-up?
                                 → saveUser → runSweep

분야 추가 (settings interests modal)  → ensurePlantsForInterests(user)
                                      → 새 ID에 stage 1 entry 즉시 생성 (S10 fix)
                                      → saveUser (interests modal save path 안에서 단일 호출)
분야 제거 (settings)                  → plant entry 유지 (visibility만 hidden)
분야 재추가                           → 기존 plant entry 그대로 visible 복원

매 진입 (home/stats render)      → checkWilting (read-only, UI hint)
첫 진입 (gardenBackfilled false) → backfillGarden() → saveUser
```

**핵심 invariant** (v3.12 graduated 패턴 정합):

- Stage transition 감지는 takeSnapshot/runSweep 패턴 확장 — `Snapshot.plantStages: Record<string, number>` 추가, `detectEvents`에서 `prev.plantStages[id] < curr.plantStages[id]` 시 `plant-stage-up { interestId, newStage }` event emit.
- saveUser throw 시 sweep 안 함 (false-fire 방지) — atomic single-write (v3.10 graduated, v3.13.1 T14 codex P1).
- in-memory mutate → saveUser → runSweep 순서 엄수.

## §3. Behavior (수치 + 알고리즘)

### 3.1 Threshold table (cumulativeActivity 누적)

| stage 전환 | 누적 활동 (placeholder) | 추가 필요 | 예상 기간 (heavy / casual, 미션 미반영) |
|---|---|---|---|
| 1→2 | 8 | 8 | 4일 / 1주 |
| 2→3 | 25 | 17 | 2주 / 3주 |
| 3→4 | 70 | 45 | 5주 / 2달 |
| 4→5 | 160 | 90 | 2.5달 / 5달 |

가정: heavy = 분야 활동 ~2회/일, casual = ~1회/일. 미션 완수 보너스 별도 합산.

**⚠️ 본 spec 수치는 placeholder** (S4 self-review fix). Q9 brainstorm 합의의 *본질 commitment*는 **시간 horizon — engaged user max ~3개월, casual user max ~5개월** 이며, 절대값(8/25/70/160)은 그 시간 horizon을 hit하는 추정치다. Plan 단계 §Threshold Sim 시트에서 다음을 검증 후 절대값 조정 가능:

- 실제 분야 매칭 briefings/day 분포 (interestKeywords + matchKeyword 시뮬레이션)
- 미션 보너스 effective multiplier (식물 수 N개 × 보너스 = N배 가속)
- 곡선 모양(exponential 8 → 25 → 70 → 160 ratio)은 보존, 절대값은 ±50% 또는 그 이상 조정 허용
- Plan retro 시점에 최종 수치 + 시뮬 결과 §Threshold Sim 명기

### 3.2 미션 완수 보너스 (모든 식물 동시 +N, v3.13 anchor 이행)

```
daily   완수 1개 = 모든 식물 cumulativeActivity +1   (placeholder)
weekly  완수 1개 = 모든 식물 cumulativeActivity +5   (placeholder)
monthly 완수 1개 = 모든 식물 cumulativeActivity +20  (placeholder)
```

호출 위치: `tickMissionProgress`에서 mission completed 전환 직후 (v3.13 cumulative.{period}Count++ 시점). 즉 미션 1개 완수 → applyMissionBonus(period) → 모든 식물 cumulativeActivity 동시 update → stage 재계산.

**⚠️ 본 spec 수치는 placeholder** (S4 self-review fix, §3.1과 같은 사유). 보너스 strength는 *식물 수(N개) × 효과* 로 effective multiplier가 작동하므로 power user (모든 미션 완수) 도달 시간이 Q9 합의(engaged ~3개월)와 deviation 가능. Plan 단계 §Mission Bonus Sim 시트에서 다음을 검증 후 조정 가능:

- daily/weekly/monthly 미션 *cap* 도입 여부 (예: daily 미션 N개 완수해도 일일 +1 cap)
- 보너스 절대값 ±50% 또는 그 이상 조정 허용 (Q9 commitment hit 우선)
- 완수 빈도 분포 (v3.13 데이터 기반 power user / mid user / casual user 시뮬)

### 3.3 Wilting threshold (visual only, stage 변화 없음)

```
lastEngagedAt 7일+ 이전 → 식물 cell에 .wilting 클래스 적용
  - opacity: 0.5
  - filter: grayscale(0.4)
  - transform: rotate(-2deg)
활동 1회 발생 → lastEngagedAt 갱신 → 즉시 vivid 복귀 (.wilting 제거)
```

**stage는 절대 변하지 않음** (Q7-B 합의). 시각적 cue로 자연스러운 재방문 유도만.

`checkWilting`은 read-only 함수 (User 변경 없음). render 시점마다 호출, 결과는 UI 클래스 적용.

### 3.4 Backfill 알고리즘 (첫 v3.15 진입 시 1회)

**Trigger 시점** (S3 spec self-review fix): `loadUserData` 호출 path에서 `migrateUserToV4` 직후 — 즉 lazy migrate v3→v4 실행되는 같은 진입점에서 곧바로 backfill 자동 실행. 별도 이벤트 / 별도 hook 없음. `gardenBackfilled === false`일 때만 1회 작동, 이후 idempotent.

```ts
function backfillGarden(user: User): void {
  if (user.gardenBackfilled) return;  // idempotent

  const briefings = loadBriefings();
  const today = new Date().toISOString();

  for (const interestId of user.interests) {
    const matched = briefings.filter(b =>
      b.scrapped &&
      interestKeywords(interestId).some(k =>
        matchKeyword(`${b.sourceTitle ?? ''} ${b.title} ${b.summary}`.toLowerCase(), k)
      )
    );
    const memoCount = matched.filter(b => b.memo.trim().length > 0).length;
    const cumulativeActivity = matched.length + memoCount;

    const stage = thresholdLookup(cumulativeActivity);  // 1~5

    user.plantStateByInterest[interestId] = {
      stage,
      cumulativeActivity,
      lastEngagedAt: today,                    // 첫 인상 wilting 회피 (Section 2 self-review fix)
      unlockedAt: stage === 5 ? today : undefined,
    };
  }

  user.gardenBackfilled = true;
  // S2 fix: backfill 자체는 takeSnapshot/runSweep 호출하지 않음 — false-fire 방지.
  // backfill로 stage 1→4 jump 또는 stage 5 즉시 도달 시 plant-stage-up event 다발 emit 위험.
  // 신규 사용자에게의 통지는 환영 모달 highlight로만 처리 (§4.3).
  // 호출자 (loadUserData path)도 backfill 직후엔 sweep 안 함 — 다음 정상 활동 시점부터 sweep 작동.
}
```

**Self-review fix 반영**:
- (C3 / Section 2) `lastEngagedAt = today` 셋 — 매칭 스크랩이 6개월 전이라도 첫 진입 시 wilting 표시되지 않도록 관대 처리. wilting timer는 v3.15 진입 시점부터 시작.
- (S2 / spec self-review) backfill 함수 내부 + 호출자(loadUserData path) 모두 sweep 우회 — backfill로 인한 stage transition은 환영 모달 highlight로만 통지, plant-stage-up event emit 없음.
- (S3 / spec self-review) trigger 시점 = `migrateUserToV4` 직후 명시.

### 3.5 Stage transition 이벤트 흐름 (v3.12 sweep 패턴 확장)

`Snapshot.plantStages: Record<string, number>` (식물 entry 미생성 시 key 부재 — undefined 표현).

```ts
// achievements.ts
takeSnapshot(): Snapshot {
  // ... 기존 필드
  return {
    // ...
    plantStages: Object.fromEntries(
      Object.entries(user.plantStateByInterest).map(([id, p]) => [id, p.stage])

}

detectEvents(prev: Snapshot, curr: Snapshot): GameEvent[] {
  // ... 기존 events
  for (const [id, currStage] of Object.entries(curr.plantStages)) {
    // S1 fix: prev에 entry 없음(분야 추가 직후 / backfill 직후 등) = transition 0으로 처리.
    // ?? 0 으로 fallback하면 0 < currStage → false plant-stage-up 다발 emit (잡음 + backfill highlight 중복).

    const prevStage = prev.plantStages[id] ?? currStage;
```
