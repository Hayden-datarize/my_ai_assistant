### 1.1 현재 archive 검색 한계

`src/ui/handlers/archive.ts:84`은 입력을 `trim().toLowerCase().normalize('NFC')` 후 단일 `currentQuery` 문자열로 보관하고, 4 filter spot (`answers` / `insights` / `all` / `byInterest`)에서 `text.normalize('NFC').toLowerCase().includes(currentQuery)`로 단일 substring 매칭한다.

- 다중 키워드 입력 시 (예: `"리액트 훅"`) 전체 문자열이 그대로 들어 있는 항목만 hit → 사용자 의도 (두 단어 모두 포함) 미충족.
- 한글 자모(초성) 입력 (예: `"ㅍㄹ"`) 매칭 미지원 → 모바일 IME 빠른 탐색 패턴 사용 불가.

### 1.2 본 사이클 목표

- 다중 토큰 AND + 한글 초성 매칭을 도입해 archive 검색 hit율을 사용자 의도에 맞춘다.
- `<mark>` highlight는 substring 토큰만 적용 (초성-only 토큰은 통과-only, syllable mark 미지원 — v3.32 out).
- 외부 라이브러리 미사용, bundle 추가 ≤ +500 B (GREEN ≤ +300 B).
- v3.30 carry polish 3건을 동시 청산해 v3.30~v3.31 carry queue를 정리한다.

## §2. Architecture

### 2.1 신규 helper — `src/utils/fuzzy.ts`

| Export | Signature | 책임 |
|---|---|---|
| `tokenizeQuery` | `(raw: string) => string[]` | raw → `normalize('NFC')` → `toLowerCase()` → `trim()` → `/\s+/` split → 빈 토큰 제거 |
| `getInitialConsonants` | `(s: string) => string` | 한글 음절 (`AC00~D7A3`)을 19자 자음 테이블로 매핑한 문자열 반환. 비음절은 그대로 통과 |
| `isInitialOnlyToken` | `(t: string) => boolean` | `/^[ㄱ-ㅎ]+$/`. 한글 자음(compatibility jamo)만 구성된 토큰 판정 |
| `matchesAllTokens` | `(text: string, tokens: string[]) => boolean` | 토큰 배열에 대해 AND fold. 토큰이 초성-only면 `getInitialConsonants(text).includes(token)`, 아니면 `text.normalize('NFC').toLowerCase().includes(token)`. 빈 배열은 vacuous true |

**정규화 순서 (NFC → lowercase → trim)**: NFC 먼저 — 한글 NFD 입력 시 lowercase 단계에서 syllable 형태가 달라지는 문제를 회피한다 (archive.ts:84 기존 패턴 정합).

**자음 테이블**: `"ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ"` 19자 (Hangul compatibility jamo). 음절의 초성 인덱스는 `Math.floor((codePoint - 0xAC00) / 588)`.

**초성 매칭 정책**:
- contiguous substring on extracted initials만 매칭 (`"ㅍㄹ"` matches `"프로젝트"` 초성 `"ㅍㄹㅈㅌ"`).
- 최소 길이 가드 없음 (1자 허용, substring 단일 자모와 균형).
- mixed-script 토큰 (예: `"ㅋproject"`)은 isInitialOnlyToken false → substring 처리.

### 2.2 `src/utils/highlight.ts` signature 변경

기존:
```ts
export function highlightHtml(text: string, query: string): string
```

변경 (clean break, archive.ts 단일 caller 확인):
```ts
export function highlightHtml(text: string, tokens: string[]): string
```

- 빈 배열 또는 초성-only 토큰만 있는 경우 → `escapeHtml(text)` 반환 (mark 없음).
- substring 토큰만 추려 길이 desc sort → escapeRegex alternation 단일 sweep regex (`/(t1|t2)/gi`).
- 기존 zero-width 방지 lastIndex 가드 / escapeHtml + `<mark>` only inject 보안 invariant 유지.

### 2.3 `src/ui/handlers/archive.ts` integration

| 변경 | 위치 |
|---|---|
| `currentTokens: string[]` 신설 (single source of truth) | module 상단 |
| `currentQuery: string` 유지 (raw input 보존, write-only) — read 경로 모두 `currentTokens` 경유 | 동상 |
| `applyQuery()` (line ~84): `currentQuery = raw.trim().toLowerCase().normalize('NFC')` 후 `currentTokens = tokenizeQuery(input?.value ?? '')` 추가 | 검색 input handler |
| Filter 4 spot — `text.normalize('NFC').toLowerCase().includes(currentQuery)` → `matchesAllTokens(text, currentTokens)` | `answers` / `insights` / `all (briefing)` / `byInterest` 모두 |
| `<mark>` 호출 2곳 — `highlightHtml(text, currentQuery)` → `highlightHtml(text, currentTokens)` | answer / insight render |
| 기존 `if (currentQuery)` 가드 — `if (currentTokens.length > 0)` 또는 vacuous true 활용 단일 처리 | filter spot |

archive 검색 6 케이스:
1. 단일 substring (예: `"리액트"`) — 기존 동작 회귀 없음
2. 다중 토큰 AND (예: `"리액트 훅"`) — 두 단어 모두 포함 항목만 표시
3. 초성 only (예: `"ㅍㄹ"`) — 초성 매칭, mark 없음
4. 초성 + substring 혼합 (예: `"ㅍㄹ react"`) — 두 조건 AND, react만 mark
5. 영문 substring (예: `"react"`) — 기존 회귀 없음
6. 빈 토큰만 입력 (공백 다수, 예: `"   "`) — `tokenizeQuery` → `[]` → 전체 표시 (UX 회귀 차단)
