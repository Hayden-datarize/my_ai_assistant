## §1. 목표 · 범위 · Non-goals

### 1.1 목표 (Goals)

1. v3.12에서 시각화한 즉시 보상 + 18 뱃지(에버그린 누적) 위에 **주기적 자극(Daily/Weekly/Monthly)** 레이어를 얹어 "오늘/이번 주/이번 달 무엇을 할까" cognitive map 제공
2. 미션 = 짧은 호흡(Daily 24h) + 중간 호흡(Weekly 7d) + 긴 호흡(Monthly 30d) 3-tier로 "한 번 답변 → 끝" 죽음 흐름 차단
3. v3.12 `detectEvents` sweep 패턴을 그대로 재사용하여 **단일 이벤트 진입점**에 `mission-complete` event 통합 (forward reference한 그대로)
4. v3.14 캐릭터 사이클이 미션 완수를 anchor로 삼을 수 있게 `cumulative.{period}Count` 카운터 인프라 마련

### 1.2 In-scope

#### A. 미션 시스템 (Q1=b+monthly, Q2=Balanced, Q3=하이브리드 채택)

- **Daily 3개** (풀 7개 후보에서 deterministic random 선택, 시드=date)
- **Weekly 2개** (고정)
- **Monthly 1개** (고정)
- 캘린더 기준 KST 리셋 (Daily 자정 / Weekly 월요일 / Monthly 1일)
- Lazy regeneration — 별도 cron 없이 진입 시점에 expired 미션 새로 생성

#### B. 미션 보상 (Q4=b 채택)

- 미션 완수 시 **XP 보너스** (Daily 각 +10 XP / Weekly 각 +50 XP / Monthly +200 XP)
- v3.12 +XP floating 자연 통합 (답변 XP + 미션 보너스 XP 합산 → 1회 floating)

- `mission-init` (데일리 1회) / `mission-master` (데일리 30회) / `weekly-champion` (위클리 8회) / `monthly-hero` (먼슬리 1회)
- v3.12 `badgeCatalog.ts` + silhouette grid 그대로 확장 (18 → 22 뱃지)

#### D. UI (Q5 = (a) 홈 탭 답변 카드 바로 아래 결정)

- 홈 탭 "답변 카드" 직후 미션 섹션

### 3.4 Sweep 통합 (v3.12 forward reference 그대로)

```
recordDailyAnswer / toggleScrap / saveMemo
  → getActiveMissions(now, user)            ← lazy regeneration (expired → new)
  → prev = takeSnapshot(user)               ← missionsActive/Cumulative 포함
  → tickMissionProgress(user, action)       ← progress++ → completed 전환 시 cumulative++ + xp += rewardXp
  → mutate user (answer/scrap/memo)
  → saveUser(user)                          ← C1 fix: try/catch (실패 시 sweep 차단)
  → curr = takeSnapshot(user)
  → runSweep(prev, curr)                    ← read-only 비교, mission-complete event emit
  → rewards.ts → 토스트 + +XP floating
```

**핵심 invariant:**
1. `tickMissionProgress`만 user mutate (xp 보너스 포함)
2. `runSweep`은 read-only — prev/curr 비교만, mutate 0
3. `saveUser` 1회만 호출 (race 회피)
4. `saveUser` 실패 시 sweep 차단 (v3.12 C1 fix 그대로 적용 — false-fire 방지)

## §4. 데이터 모델 (Schema v2 → v3)

### 4.1 User 스키마 확장

```ts
type UserDataV3 = UserDataV2 & {
  schemaVersion: 3;
  missions: {
    active: MissionInstance[];
    cumulative: {
      dailyCount: number;     // 미션 뱃지 trigger용 누적 (mission-init / mission-master)
      weeklyCount: number;    // weekly-champion (8회 = 4주 풀 활동)
      monthlyCount: number;   // monthly-hero
    };
    lastDailySeed: string;    // 'YYYY-MM-DD' (KST) — 같은 날 재진입 시 동일 미션 보장
    currentWeekIso: string;   // 'YYYY-Www' (ISO 8601, KST 월요일 시작)
    currentMonthIso: string;  // 'YYYY-MM' (KST)
  };
};

type MissionInstance = {
  defId: string;              // missionCatalog.ts entry id (예: 'daily-answer-1')
  period: 'daily' | 'weekly' | 'monthly';
  windowStart: number;        // 자정/월요일/1일 ms (KST 기준)
  progress: number;           // 0..target
  completed: boolean;
  progressDates?: string[];   // active-day trigger 미션 전용 ('YYYY-MM-DD' KST), §5.5 참조
};
```

### 4.2 왜 windowStart만 저장하고 target/reward는 catalog lookup인가

- **DRY** — 카탈로그(`missionCatalog.ts`)는 정적, 데이터 중복 회피
- **카탈로그 변경 시 즉시 반영** — XP 보상 조정 시 active 미션도 새 값 사용 (migration 불필요)
- **localStorage 용량 최소화** — 사용자 active 미션 6개 × ~80 bytes = ~500 bytes

### 4.3 Lazy migration v2 → v3 (`userData.ts`)

```ts
function migrateUserToV3(user: UserDataV2): UserDataV3 {
  return {
    ...user,
    schemaVersion: 3,
    missions: {
      active: [],
      cumulative: { dailyCount: 0, weeklyCount: 0, monthlyCount: 0 },
      lastDailySeed: '',
      currentWeekIso: '',
      currentMonthIso: '',
    },
  };
}

// loadUserData 안에서:
if ((user.schemaVersion ?? 1) < 3) user = migrateUserToV3(user);
```

- Idempotent — `schemaVersion < 3` 체크 한 번만
- Graceful — try/catch로 감싸 실패해도 앱 동작 (v3.12 patterns)
- 다음 `getActiveMissions` 호출 시 모든 주기 새로 생성 (마치 신규 사용자처럼)

### 4.4 getCachedUser shape guard v3 추가 (T1 동시 수행)

v3.12.1에서 도입한 v2 shape guard에 v3 필드 guard 추가:

```ts
// userData.ts getCachedUser
if (typeof u.missions?.cumulative?.dailyCount !== 'number') {
  u.missions.cumulative.dailyCount = 0;  // NaN/undefined 차단
}
// weeklyCount, monthlyCount 동일
if (typeof u.missions?.lastDailySeed !== 'string') {
  u.missions.lastDailySeed = '';
}
// currentWeekIso, currentMonthIso 동일
if (!Array.isArray(u.missions?.active)) {
  u.missions.active = [];
}
```

silent NaN으로 미션 진행률 깨지는 사고 방지.

### 4.5 Snapshot 확장 (`gameTypes.ts`)

```ts
type Snapshot = {
  // v3.12 기존 필드 (xp, level, streak, earnedBadges, …)

function takeSnapshot(user: UserDataV3): Snapshot {
  return {
    // ... 기존 필드 ...

    missionsCumulative: {
      daily: user.missions.cumulative.dailyCount,
      weekly: user.missions.cumulative.weeklyCount,
      monthly: user.missions.cumulative.monthlyCount,

}
```

### 5.4 MissionDef 형식

```ts
type MissionAction = 'answer' | 'scrap' | 'memo' | 'briefing-view' | 'cross-interest-view' | 'archive-revisit' | 'active-day';

type MissionDef = {
  id: string;                  // 고유 defId
  text: string;                // 한국어 raw text (v3.6 i18n Lite ≥2 빈도 graduation 기준 — 본 사이클 raw, 후속 graduation 후보)
  period: 'daily' | 'weekly' | 'monthly';
  target: number;              // ≥ 1
  rewardXp: number;            // > 0
  triggerOn: MissionAction;
  badgeTrigger?: string;       // 미션 자체가 trigger하는 뱃지 (현재 카탈로그엔 없음, 후속 hook only)
};
```

### 5.5 `triggerOn: 'active-day'` 특수 처리

- 다른 trigger와 달리 "오늘 첫 활동(answer/scrap/memo 어느 것이든)이 일어난 날" 단위로 +1
- `tickMissionProgress`에서 today KST date를 `weekly-active-5days` instance 외부 set에 저장 (예: `user.missions.weeklyActiveDates: string[]`)
- 매 reset마다 weeklyActiveDates 초기화

대안: weekly-active-5days instance에 `progressDates: string[]` 필드 추가 — 모델 더 명확. 본 spec은 후자 채택:

```ts
type MissionInstance = {
  defId: string;
  period: 'daily' | 'weekly' | 'monthly';
  windowStart: number;
  progress: number;
  completed: boolean;
  progressDates?: string[];    // active-day trigger 미션 전용 (KST date 'YYYY-MM-DD')
};
```

`tickMissionProgress`:
- `triggerOn === 'active-day'` 미션만:
  - 오늘 KST date가 `progressDates`에 없으면 push + `progress++`
  - 이미 있으면 no-op (idempotent)
- 다른 trigger는 단순 `progress++`

## §6. 미션 Lifecycle

### 6.1 Create — `getActiveMissions(now, user)`

호출 시점:
- 홈 탭 진입 (또는 home tab activate)
- `recordDailyAnswer` / `toggleScrap` / `saveMemo` 진입 직전 (tick 전)

로직:
```ts
function getActiveMissions(now: Date, user: UserDataV3): MissionInstance[] {
  const todayIso = getKSTDateIso(now);     // 'YYYY-MM-DD'
  const weekIso = getKSTWeekIso(now);      // 'YYYY-Www'
  const monthIso = getKSTMonthIso(now);    // 'YYYY-MM'

  let dirty = false;

  if (user.missions.lastDailySeed !== todayIso) {
    const newDaily = pickDailyMissions(todayIso, now);   // 3 instances
    user.missions.active = user.missions.active.filter(m => m.period !== 'daily').concat(newDaily);
    user.missions.lastDailySeed = todayIso;
    dirty = true;
  }
  if (user.missions.currentWeekIso !== weekIso) {
    const newWeekly = makeWeeklyMissions(now);            // 2 instances
    user.missions.active = user.missions.active.filter(m => m.period !== 'weekly').concat(newWeekly);
    user.missions.currentWeekIso = weekIso;
    dirty = true;
  }
  if (user.missions.currentMonthIso !== monthIso) {
    const newMonthly = makeMonthlyMissions(now);          // 1 instance
    user.missions.active = user.missions.active.filter(m => m.period !== 'monthly').concat(newMonthly);
    user.missions.currentMonthIso = monthIso;
    dirty = true;
  }

  // saveUser는 호출하지 않음 — caller invariant (§3.4)
  // dirty 정보가 필요하면 별도 반환값 추가 가능하나, 현재 caller는 항상 saveUser하므로 불필요
  return user.missions.active;
}
```

**Caller invariant:**
- 홈 탭 단독 진입 (액션 없음) — `getActiveMissions(now, user) → saveUser(user) → renderMissionsSection(user)` (saveUser 1회)
- 액션 동반 (answer/scrap/memo) — `getActiveMissions(now, user) → tick → mutate → saveUser(user) → sweep` (saveUser 1회, §3.4)

이로써 모든 진입점에서 saveUser는 정확히 1번 호출되어 race 회피.

### 6.2 Deterministic random (`pickDailyMissions`)

```ts
function pickDailyMissions(dateIso: string, now: Date): MissionInstance[] {
  const seed = hashStr(dateIso);                  // 32-bit hash
  const rng = mulberry32(seed);
  const pool = DAILY_POOL;                        // 7 entries
  const picked = sampleWithoutReplacement(rng, pool, 3);
  return picked.map(def => ({
    defId: def.id,
    period: 'daily',
    windowStart: getKSTWindowStart(now, 'daily'),
    progress: 0,
    completed: false,
    ...(def.triggerOn === 'active-day' ? { progressDates: [] } : {}),
  }));
}
```

- 같은 날 재진입 → 같은 미션 (디버깅 쉬움, 사용자 신뢰)
- 단일 사용자 SPA → userId seed 불필요

### 6.3 Tick — `tickMissionProgress(user, action)`

```ts
type MissionAction = 'answer' | 'scrap' | 'memo' | 'briefing-view' | 'cross-interest-view' | 'archive-revisit' | 'active-day';

function tickMissionProgress(user: UserDataV3, action: MissionAction, now: Date = new Date()): void {
  // active-day는 별도: answer/scrap/memo 호출 시 함께 tick
  for (const m of user.missions.active) {
    const def = getMissionDef(m.defId);
    if (m.completed) continue;
    if (def.triggerOn !== action && def.triggerOn !== 'active-day') continue;

    if (def.triggerOn === 'active-day') {
      const todayIso = getKSTDateIso(now);
      m.progressDates = m.progressDates ?? [];
      if (m.progressDates.includes(todayIso)) continue;       // idempotent
      m.progressDates.push(todayIso);
      m.progress = m.progressDates.length;
    } else {
      m.progress++;
    }

    if (m.progress >= def.target) {
      m.completed = true;
      user.xp += def.rewardXp;                                // XP 보너스 즉시 add
      user.missions.cumulative[`${m.period}Count` as const]++;
    }
  }
}
```

## §10. 에러 핸들링 / Edge case

### 10.1 saveUser 실패

- v3.12 C1 fix 그대로 — try/catch로 감싸 sweep 차단 (false-fire 방지)
- `tickMissionProgress`로 user 객체 mutate된 후 saveUser 실패 → 메모리상 user는 변경됨, 다음 액션에서 다시 시도. 사용자에게 보이는 정상 진행 (v3.7 saveUser 에러 UX 토스트 정책 따름)

### 10.2 시간대 변경 (사용자 KST → 해외 여행)

- 모든 reset 비교는 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })` 강제 → KST 기준 일관 (v3.3.4.2 heatmap TZ fix 패턴)

### 10.3 자정 직전/직후 답변 race

- `recordDailyAnswer` 진입 직후 `getActiveMissions(now, user)` 호출 → 자정 넘어갔으면 새 daily 미션 생성 (이전은 사라짐)
- 답변은 새 미션 progress 1로 카운트
- "자정 1초 전 답변 → 직후 미션 완수 토스트" 같은 race 없음 (sequential JS event loop)

### 10.4 사용자가 1주 비웠다 진입

- Daily: 어제 미완수 미션 모두 폐기, 오늘 새로 생성
- Weekly: lastWeekIso 다르면 새로 생성 (이전 주 진행 carry-over X)
- Monthly: lastMonthIso 다르면 새로 생성
- Cumulative 카운터: 영구 누적 (reset과 무관)

### 10.5 Schema migration 실패

- migrateUserToV3 자체는 순수 함수 (failure 없음)
- loadUserData try/catch graceful — migration 실패 시 default missions 객체로 fallback (v3.12 패턴)

### 10.6 active-day idempotency

- 하루 안에 답변 + 스크랩 + 메모 모두 trigger → `weekly-active-5days` progressDates에 오늘 1번만 push (idempotent)
- 같은 날 재진입에도 안전

### 10.7 카탈로그 변경 시 active 미션 동기화

- 사용자 active 미션 defId가 catalog에서 제거되면 (예: D7 삭제) → `getMissionDef(m.defId)` undefined → tick에서 skip, UI에서 unknown으로 표시될 위험
- 방어: `getActiveMissions` 진입 시 active 중 catalog에 없는 defId는 필터링 + dirty=true로 saveUser
- 단, v3.13 출시 시점 카탈로그 고정이라 본 사이클에서는 edge case (시리즈 후속 변경 시 적용)
