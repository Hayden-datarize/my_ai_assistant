## 5. P0 — #5 Heatmap level-2 opacity 상향

### 5.1 현상
- [main.css:826](src/styles/main.css#L826): `.heatmap-cell.level-2 { background: var(--primary-light); opacity: 0.6; }`
- `--primary-light: #818CF8` × opacity 0.6 → 시각적으로 level-1 (`--primary-ultra-light: #EEF2FF`)와 거의 구분 안 됨
- WCAG AA contrast (대비 3:1)를 자체 만족 안 함 (실제로는 통계 카운트 시각화라 텍스트 contrast 규정 적용은 아니나, level-1과 분리 안 되는 게 문제)

### 5.2 변경
```css
.heatmap-cell.level-2 {
  background: var(--primary-light);
  opacity: 0.85;  /* was 0.6 */
}
```

### 5.3 영향
- level-3은 `opacity: 0.8` ([main.css:827](src/styles/main.css#L827)) — 변경 없음. level-2(0.85)가 level-3(0.8)보다 옅어 보일 수 있는 inversion 우려 → primary vs primary-light 색 자체가 다름(짙음 vs 옅음)으로 자연 정렬됨. **Plan Discovery §16.1 시각 검증** 항목.
- 다크 모드: 다크 모드의 `--primary-light: #A5B4FC` ([main.css:36](src/styles/main.css#L36)) × 0.85도 검증.

## 6. P0 — #6 주말 셀 강조 강화

### 6.1 현상
- [main.css:830-832](src/styles/main.css#L830): `.heatmap-cell.level-0.is-weekend { background: var(--accent-light); }` — 활동 없는 주말만 amber tint
- level-1+ 주말은 일반 평일과 시각 차이 없음 → "주말에도 답변 했네"가 안 보임

### 6.2 변경
```css
/* 모든 주말 셀에 좌측 1px accent border 추가 (level과 무관) */
.heatmap-cell.is-weekend:not(.is-blank) {
  box-shadow: inset 2px 0 0 var(--accent);
}
/* level-0 주말 tint는 유지 (기존 line 830-832) — boxShadow와 background 함께 적용 */
```

### 6.3 영향
- **`box-shadow: inset` 선택 근거:** `box-sizing: border-box`가 전역 적용되어 있어 ([main.css:57](src/styles/main.css#L57)) `border-left` 추가해도 outer 크기는 불변 (grid 정렬 영향 없음). 하지만 `.heatmap-cell.is-blank`에 이미 `border: 1px dashed var(--border)` ([main.css:833-838](src/styles/main.css#L833))가 있어 `border-left` 추가 시 blank 셀에 4-side 혼합 border가 생김. `box-shadow: inset`은 border 속성과 독립 레이어라 blank 셀의 dashed border와 충돌 없음.
- 주말 셀 hover 시 `transform: scale(1.15)` ([main.css:824](src/styles/main.css#L824))는 box-shadow도 같이 확대됨 — 정상 거동 (2px → ~2.3px, 미미).
- blank 주말 셀(데이터 없는 미래 일자)에는 적용 안 함 (`:not(.is-blank)`).
- 단위 테스트 (`tests/unit/heatmap.spec.ts:870-877` "marks exactly 8 weekend data cells")는 `.is-weekend:not(.is-blank)` selector를 이미 사용 → 기존 테스트 그린 유지. CSS 클래스 assertion만 검증, 색 값 미검증.

## 8. P0 — #9 브리핑 카드 hover depth

### 8.1 현상
- [main.css:362-370](src/styles/main.css#L362) `.briefing-card`: hover = `translateY(-2px) + shadow-md`
- 클릭 가능한 카드인데 "click me" 신호가 약함
- 기존 4-side `border: 1px solid var(--border)` ([main.css:365](src/styles/main.css#L365))가 있어 `border-left` 추가는 layout shift 위험

### 8.2 변경
```css
.briefing-card {
  /* …existing border: 1px solid var(--border) 유지… */
  transition: transform 0.2s, box-shadow 0.2s;
}
.briefing-card:hover {
  transform: translateY(-2px);
  /* shadow-md + 좌측 primary 강조선 (inset shadow로 layout shift 없이 추가) */
  box-shadow: var(--shadow-md), inset 3px 0 0 var(--primary);
}
```

### 8.3 영향
- **`box-shadow: inset` 선택 근거:** 기존 `border: 1px solid var(--border)`는 4-side. 만약 `border-left: 3px solid transparent` 추가 후 `border-left-color` 토글 방식을 쓰면 left가 1px(`solid var(--border)`) → 3px transparent로 cascade 덮어쓰기되어 카드가 좌측 2px shift 발생. inset shadow는 border 속성과 별개 layer라 충돌·shift 모두 없음.
- `box-shadow` 다중 값(콤마 분리): 첫번째가 outer drop shadow (`shadow-md`), 두번째가 inset 좌측 라인. 하나의 shorthand로 atomic 적용.
- `.briefing-card.read` ([main.css:781-784](src/styles/main.css#L781))는 `border-color: var(--primary-light)` 4-side 적용 → border와 box-shadow는 독립이므로 read 상태 카드도 hover 시 inset primary 라인이 추가로 보임 (정상 거동, 읽음 카드도 시각 신호).
- `.briefing-source` chip과 충돌 없음 (chip은 카드 내부 inline element).

## 12. P1 — #10 btn disabled pointer-events

### 12.1 현상
- [main.css:284](src/styles/main.css#L284) `.btn:disabled { opacity: 0.5; cursor: not-allowed; }` — 클릭 이벤트가 capture phase에서 leak 가능 (예: `e.stopPropagation()` 없으면 부모 핸들러 트리거)

### 12.2 변경
```css
.btn:disabled {
  opacity: 0.5;
  cursor: not-allowed;
  pointer-events: none;  /* NEW */
}
```

### 12.3 영향
- `<button disabled>`은 HTML 명세상 클릭 이벤트 자체가 발생하지 않음 — `pointer-events: none`은 이중 안전망 (`aria-disabled="true"`만 쓰는 custom 컴포넌트나 부모 클릭 핸들러로의 leak 대비).
- **focus는 차단되지 않음** — `pointer-events: none`은 마우스 이벤트만 차단, 키보드 focus는 그대로 가능. 단, `<button disabled>`은 disabled 속성 자체가 focus를 막음 (HTML 표준). 즉, focus 차단 효과는 disabled 속성에서 오고 pointer-events는 기여 없음.
- 마우스 hover tooltip 영향: disabled 버튼에 `title` 속성으로 tooltip 띄우는 패턴이 있다면 `pointer-events: none`이 hover를 막아 tooltip도 안 뜸. **Plan Discovery §16.7**에서 grep으로 확인 후 결정.

import { test, expect } from '@playwright/test';

test.use({ serviceWorkers: 'block' });

async function seedUser(page: import('@playwright/test').Page): Promise<void> {
  await page.addInitScript(() => {
    localStorage.setItem('user', JSON.stringify({
      name: 'Polish', interests: ['pm'],
      onboardedAt: '2026-04-01', streak: 0, lastActiveDate: '', xp: 0, level: 1,
    }));

}

test('briefing card hover applies inset primary box-shadow (existence check)', async ({ page }) => {
  await seedUser(page);
  await page.route('**/api.rss2json.com/**', (route) =>
    route.fulfill({
      status: 200, contentType: 'application/json',
      body: JSON.stringify({
        feed: { title: 'src' },
        items: [{ title: 'T', link: 'https://example.com/1', description: 'd', pubDate: '' }],
      }),

  );
  await page.goto('/');
  await expect(page.locator('#homeTab')).toBeVisible();
  await page.locator('#refreshBriefing').click();
  const card = page.locator('.briefing-card').first();
  await expect(card).toBeVisible({ timeout: 10_000 });

  const beforeHover = await card.evaluate((el) => getComputedStyle(el).boxShadow);
  await card.hover();
  const afterHover = await card.evaluate((el) => getComputedStyle(el).boxShadow);

  // hover 전후 box-shadow가 달라졌고, after는 'none'이 아니어야 함 (값 자체는 검증 안 함)
  expect(afterHover).not.toBe(beforeHover);
  expect(afterHover).not.toBe('none');
  // hover box-shadow는 두 그림자 콤마 분리: outer drop + inset 좌측 라인
  expect(afterHover).toContain('inset');
});

test('onboarding chip selected has non-default transform (scale)', async ({ page }) => {
  await page.addInitScript(() => { localStorage.removeItem('user'); });
  await page.goto('/');
  const chip = page.locator('.onboarding-chip').first();
  await expect(chip).toBeVisible({ timeout: 5_000 });
  const before = await chip.evaluate((el) => getComputedStyle(el).transform);
  await chip.click();
  const after = await chip.evaluate((el) => getComputedStyle(el).transform);

  expect(after).not.toBe(before);
  expect(after).not.toBe('none');  // selected 상태는 transform 적용 (matrix or scale)
});

test('focus-visible on first focusable shows visible outline (keyboard tab)', async ({ page }) => {
  await seedUser(page);
  await page.goto('/');
  await page.keyboard.press('Tab');
  const focused = await page.evaluate(() => {
    const el = document.activeElement as HTMLElement | null;
    if (!el || el === document.body) return null;
    const cs = getComputedStyle(el);
    return { tag: el.tagName, outlineStyle: cs.outlineStyle, outlineWidth: cs.outlineWidth };
  });
  expect(focused).not.toBeNull();
  expect(focused!.outlineStyle).not.toBe('none');
  // outlineWidth가 '0px'이 아니어야 함 (값 비교는 토큰 자유)
  expect(focused!.outlineWidth).not.toBe('0px');
});

test('disabled button has pointer-events: none', async ({ page }) => {
  await seedUser(page);
  await page.goto('/');

    if (!btn) return null;
    btn.setAttribute('disabled', '');

  });
