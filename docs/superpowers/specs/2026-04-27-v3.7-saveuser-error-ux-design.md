## §1 Background

v3.6 T1 (`interests.ts` dedup) 완료 시점에 의도적으로 남긴 부채:

> `state/user.ts:saveUser`는 `localStorage.setItem`이 throw할 경우 caller로 그대로 propagate. 현재 4 callers 중 어디도 try/catch 없음 → 사용자는 실패를 인지하지 못함 (silent fail), unhandled promise rejection 가능성.

또한 v3.6 T6에서 `settings-interests-section.spec.ts` flake를 `vi.waitFor` 폴링으로 fix했으나, 동일 패턴이 다른 spec(특히 `vi.resetModules` + 동적 import 사용처)에 잠복할 가능성 — 진단 필요.

본 사이클은:
- **B (메인)** — `saveUser` 에러 UX 일관 정책: throw → caller try/catch + 분기 토스트
- **C (보조)** — vitest test isolation 진단 (실패 발견 시만 수정) + 가이드라인 문서화

## §5 Tasks

### T1 — `state/user.ts` JSDoc + `getSaveErrorMessage` 추가

**Files**: `src/state/user.ts`

**Changes**:
- `saveUser` JSDoc: `@throws {DOMException} QuotaExceededError when localStorage quota exceeded; other DOMException for SecurityError etc.`
- `recordActivity` / `checkAndUpdateStreak` JSDoc: `@throws {DOMException} propagated from saveUser`
- 신규 export:
  ```ts
  /**
   * saveUser 실패 시 사용자 가시 메시지 결정.
   * QuotaExceededError → SAVE_QUOTA_EXCEEDED (액션 가이드 포함)
   * 그 외 → SAVE_FAILED (fallback)
   */
  export function getSaveErrorMessage(err: unknown): string {
    if (err instanceof DOMException && err.name === 'QuotaExceededError') {
      return MSG.SAVE_QUOTA_EXCEEDED;
    }
    return MSG.SAVE_FAILED;
  }
  ```
- `MSG` import 추가 (`from '../i18n/messages'`)

**Tests**: `tests/unit/state-user.spec.ts`
- `saveUser propagates QuotaExceededError when localStorage rejects` — `Storage.prototype.setItem` mock으로 `DOMException('quota', 'QuotaExceededError')` throw 시뮬, `expect(() => saveUser(u)).toThrow(DOMException)`
- `getSaveErrorMessage returns SAVE_QUOTA_EXCEEDED for QuotaExceededError` — args 매칭
- `getSaveErrorMessage returns SAVE_FAILED for generic Error / unknown` — fallback 검증

**LoC**: +9 (JSDoc 3개) +14 (helper) +6 (테스트 3 it-block) = **+29**

### T3 — `interests.ts` try/catch 추가

**Files**: `src/ui/modals/interests.ts`

**Changes** (line 64~70 근처):
```ts
// before:
saveUser({ ...user, interests: newInterests });
showToast(MSG.INTERESTS_UPDATED);

// after:
try {
  saveUser({ ...user, interests: newInterests });
  showToast(MSG.INTERESTS_UPDATED);
} catch (e) {
  showToast(getSaveErrorMessage(e));
  return; // modal 닫지 않고 사용자에게 재시도 기회
}
```

**Decision — 실패 시 modal 동작**:
- 옵션 (a): modal 유지 — 사용자가 같은 input으로 재시도 가능
- 옵션 (b): modal 닫음 — 입력 손실
- **(a) 채택**: 입력 보존 + 재시도 흐름 자연스러움. `return`으로 후속 modal 닫기 로직 (`closeModal()` 등) skip

**Tests**: `tests/unit/modals-interests.spec.ts`
- `shows quota toast when saveUser throws QuotaExceededError` — `state/user.ts:saveUser` mock으로 throw, showToast spy
- `shows fallback toast when saveUser throws generic Error` — 같은 패턴
- `keeps modal open when save fails` — modal DOM이 그대로인지 검증 (closeModal/cleanup 미호출)

**LoC**: +6 (코드) +9 (테스트 3 it-block) = **+15**

**Decision — 실패 시 답변 저장 후속 흐름**:
- 옵션 (a): `return` — 후속 (chat bubble, briefing 갱신, recordActivity) 모두 skip
- 옵션 (b): 토스트만 띄우고 후속 진행 — 메모리 상태는 일관, persist만 실패
- **(b) 채택**: chat bubble은 메모리 기반이므로 가시적 답변은 보존 → UX 손실 최소화. 단, 새로고침 시 사라진다는 사실은 토스트가 안내. `recordActivity`는 본 사이클 데드이므로 호출 라인 없음 (있다면 throw 시 같은 try/catch에 포함되어야 하나 본 사이클 무관)

→ 최종 코드:
```ts
try {
  saveUser(user);
} catch (e) {
  showToast(getSaveErrorMessage(e));
  // 답변은 메모리/UI에는 반영됨 — persist만 실패. 후속 흐름은 그대로 진행.
}
```

**Tests**: `tests/unit/home-answer-save-error.spec.ts` (신규)

- `shows fallback toast for generic save error` — 같은 패턴

**LoC**: -3 (USER_STORAGE) -3 (로컬 saveUser) +6 (try/catch) +1 (import) +12 (테스트 3 it-block) = **+13**

### §A.3 카피 미리보기

성공 경로 (변경 없음):
- 관심 분야 수정 → `MSG.INTERESTS_UPDATED` ("관심 분야가 업데이트되었어요.")

- Quota 초과 → `MSG.SAVE_QUOTA_EXCEEDED` ("❌ 저장 공간이 가득 찼어요. 설정에서 번역 캐시를 초기화해 주세요.")
