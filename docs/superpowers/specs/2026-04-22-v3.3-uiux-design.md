## 4. Architecture — 파일 구조 & `@layer` 전략

### 4.1 새 디렉토리 구조 (v3.3.0 실구현 반영, 2026-04-22 amendment)

```
src/styles/
├── main.css              # entry — @layer 정의 + @import 만 (~19 lines)
├── tokens.css            # design tokens 전체 (+ 768px :root override)
├── base.css              # reset, html/body, 기본 typography, focus-visible
├── layout.css            # app-container, header, bottom-nav, tab 컨테이너 padding
├── utilities.css         # .hidden, .text-center, .mt-*, .mb-*, .fade-in (진짜 유틸만)
├── components/           # 재사용 design-system primitives
│   ├── splash.css        # .splash-* (신규 — 초기 계획 외 세분화)
│   ├── onboarding.css    # .onboarding*, .onboard-*, .interest-*, .api-key-*
│   ├── buttons.css       # .btn + variants
│   ├── cards.css         # .briefing-*, .streak-*, .xp-badge, .card-memo*, .card-action-btn
│   ├── forms.css         # .settings-* (v3.3.1에서 일반 form primitives 추가 예정)
│   ├── heatmap.css       # .heatmap-*
│   └── shared.css        # 공용 UI primitives (toast/modal/empty-state/skeleton/scroll-indicator/banners/action-card)
└── pages/                # 페이지별 compositions (탭-scoped UI flows)
    ├── home.css          # question/answer/hint/submit/chat + 768px #homeTab grid
    ├── archive.css       # .archive-*, .filter-chip
    └── stats.css         # .stat-*, .level-*, .xp-progress*, .badges-*, .badge-*
```

**`components/` vs `pages/` 경계**:

- `components/`: 여러 페이지에서 재사용되거나 재사용 가능한 UI primitive (buttons, cards, forms, heatmap, shared UI 조각 등)
- `pages/`: 특정 탭 하나에만 존재하는 composition (home tab의 question+chat flow, archive tab 전용 UI 등)
- 두 디렉토리 모두 `@layer components`에 로드됨 — 구분은 조직적(organizational) 목적, 런타임 specificity 구분 아님
- v3.3.1/v3.3.2 구현 시 참조: 재사용성이 기준. 새 UI가 한 페이지 전용이면 `pages/`, 두 곳 이상에서 쓰이거나 쓰일 예정이면 `components/`

### 4.2 `main.css` 구조 (v3.3.0 실구현 반영)

```css
/* 1. Layer 선언 — 모든 @import보다 앞 (순서가 우선순위 결정) */
@layer tokens, base, layout, components, utilities;

/* 2. Layer별 import (same-layer 내에서는 source order가 tiebreaker) */
@import './tokens.css' layer(tokens);
@import './base.css' layer(base);
@import './layout.css' layer(layout);
@import './components/splash.css' layer(components);
@import './components/onboarding.css' layer(components);
@import './components/buttons.css' layer(components);
@import './components/cards.css' layer(components);
@import './components/forms.css' layer(components);
@import './components/heatmap.css' layer(components);
@import './components/shared.css' layer(components);
@import './pages/home.css' layer(components);
@import './pages/archive.css' layer(components);
@import './pages/stats.css' layer(components);
@import './utilities.css' layer(utilities);
```

**`components/* → pages/*` import 순서는 의도적**: CSS Cascade Layers 규칙상 같은 레이어 내에서는 뒤에 import된 파일이 tiebreaker에서 승리한다. 페이지 composition이 reusable component primitive를 오버라이드하는 방향이 자연스러우므로, `pages/*`는 항상 `components/*` 뒤에 import 한다.

**할루시네이션 가능성 경고**: CSS Cascade Layers(`@layer`) 브라우저 지원 = Chrome 99+, Safari 15.4+, Firefox 97+ (확인된 출처: MDN). **iOS 15.3 이하 사용자는 지원 안 됨**. 배포 전 타깃 브라우저 Hayden 확정 필요.

### 5.3 다크 모드 정책

- **기존 `[data-theme="dark"]` 구조 유지** — toggle 구현 방식은 현 코드 존중, 변경 없음
- theme-invariant 토큰: spacing / typography / radius / z-index / motion / focus-ring / border
- 다크 모드 재매핑 대상: color, shadow, heatmap palette
- Shadow 다크 모드 강화: `--shadow-md: 0 4px 12px rgba(0, 0, 0, 0.35);` (기본 0.08 대비 강함)

**현 구현 점검 항목** (구현 전 확인):
- [ ] 다크 모드 toggle이 `prefers-color-scheme` 자동 반영인지 user-button 방식인지
- [ ] localStorage key 이름 (기존 존중)
- [ ] html 요소의 `data-theme` 속성 토글 로직 위치

### 5.4 Reduce-motion 대응

### 6.4 JS 모듈 (신규 `src/ui/sidebar.ts`)

책임:
- 햄버거 클릭 핸들러 → toggle
- ESC 키 전역 리스너 → close (open 상태에서만 활성)
- Backdrop 클릭 → close
- 탭 아이템 클릭 → close + 기존 tab switching 호출
- `aria-expanded`, `aria-hidden`, `data-open` 동기화
- `localStorage['dg-sidebar-last-state']` 읽기/쓰기
- Focus management: open 시 drawer 첫 focusable로 focus, close 시 햄버거 버튼으로 복귀

### 6.5 Focus Trap Utility (신규 `src/ui/utils/focus-trap.ts`)

책임:
- 주어진 컨테이너의 focusable elements 조회 (`button, a, input, select, textarea, [tabindex]:not([tabindex="-1"])`)
- Tab forward: 마지막 요소에서 Tab → 첫 요소로
- Shift+Tab backward: 첫 요소에서 Shift+Tab → 마지막 요소로
- `activate(container)` / `deactivate()` API
- ~60줄 예상, 외부 라이브러리 불필요

### 6.6 모바일/데스크탑 탭 active state 동기화

현재 tab switching 함수 위치 확인 필요 (추정: [src/ui/app.ts](src/ui/app.ts) 또는 별도 tab router).

구현:
- active 탭 변경 시 `.bottom-nav .nav-item[data-tab="X"]`와 `.sidebar-drawer .nav-item[data-tab="X"]` 둘 다 `.is-active` 갱신
- 단일 utility 함수로 통일 (`setActiveTab(tabId)`)

### 6.7 상태 영속

```
localStorage['dg-sidebar-last-state']: 'open' | 'closed'
기본값: 'closed' (초기 설치/clear 시)
```

- 페이지 로드 시 저장값 읽어 초기 상태 복원
- toggle 동작마다 저장

## 13. Risks & Assumptions

### 13.1 브라우저 호환성

- **CSS Cascade Layers** (`@layer`): Baseline 2022. iOS 15.3 이하 미지원.
  - **할루시네이션 가능성 경고**: 정확한 iOS 버전은 caniuse/MDN 재확인 필요.
  - **대응**: Hayden 타깃 사용자 버전 확인. iOS 15 포함이면 `@layer` 생략 + 선택자 특이성 관리로 대체.
- **`color-mix()`**: iOS 16.4+. 따라서 heatmap에는 pre-computed hex 사용 (§5.2).
- **`:focus-visible`**: 모든 최신 브라우저 지원. iOS 15.4+.

### 13.2 빌드 사이즈

- tokens.css + 분할 파일은 합산 시 기존 main.css와 거의 동일 (@layer 메타만 ~수백 바이트 추가)
- 신규 JS 모듈(`sidebar.ts`, `focus-trap.ts`) gzip +~1.5KB 예상
- heatmap 새 render 로직으로 `stats.ts` +~1KB 예상
- 총 예상 gzip 증가: 2~3KB. **수용 범위**.

### 13.3 기존 코드와 wiring 리스크 ([feedback_dg_wiring_lesson])

- 마크업 이식 ≠ 기능 작동. 다음 항목 반드시 plan 단계에서 실제 DOM 확인:
  - 탭 switching 함수 위치와 시그니처
  - 다크 모드 toggle 핸들러 위치
  - settings 폼 action / 이벤트 바인딩
  - bottom-nav 탭 아이템의 `data-tab` 속성 네이밍
  - heatmap `hydrateHeatmap` 함수가 생성하는 DOM 구조와 클래스명

### 13.4 디자인 변경이 기존 사용자 체감에 미치는 영향

- v3.3.0은 시각 변화 없음 → 리스크 낮음
- v3.3.1 sidebar 변경은 큰 체감 → Hayden 본인이 유일 사용자이므로 배포 후 즉시 피드백 가능
- v3.3.2 heatmap 변경은 통계 탭 한정 → 격리됨

### 13.5 테스트 커버리지 보강 필요

- 외부 호스트 건드는 PR 아님 ([feedback_test_coverage_cors_csp] 해당 없음)
- 단, sidebar toggle state + layout 회귀 가드는 시각 회귀 스냅샷보다 기능 assertion 중심이어야 (마크업 이식 lesson)
