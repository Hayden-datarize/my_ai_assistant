**Goal:** `saveUser` 실패가 사용자에게 명시적으로 전달되도록 throw → caller try/catch + 분기 토스트 정책 적용. v3.6 T1 dedup 마무리(home.ts 로컬 `saveUser` 삭제). vitest test isolation 잠복 진단.

```ts
/**
 * Maps a `saveUser`-thrown error to the user-visible toast message.
 * Single source of truth for save error copy — used by both interests modal
 * and home answer save callers.
 *
 * - `QuotaExceededError` → `MSG.SAVE_QUOTA_EXCEEDED` (액션 가이드 포함)
 * - 그 외 (generic Error, unknown) → `MSG.SAVE_FAILED` (fallback)
 */
export function getSaveErrorMessage(err: unknown): string {
  if (err instanceof DOMException && err.name === 'QuotaExceededError') {
    return MSG.SAVE_QUOTA_EXCEEDED;
  }
  return MSG.SAVE_FAILED;
}
```

```markdown
## 2. 비동기 폴링 — `setTimeout` 금지

비동기 effect를 기다릴 때 `setTimeout(resolve, N)`로 sleep하지 마세요. **`vi.waitFor`** 또는 Playwright의 **`expect.poll`**을 사용하세요.

\`\`\`ts
// ❌ 금지 — flaky
await new Promise((r) => setTimeout(r, 100));

// ✅ vitest
await vi.waitFor(() => expect(document.querySelector('.dg-toast')).not.toBeNull());

// ✅ Playwright
await expect.poll(() => page.locator('.dg-toast').count()).toBeGreaterThan(0);
\`\`\`

예외: `vi.useFakeTimers()` + `vi.advanceTimersByTime(N)`로 의도적 timer 검증은 OK.

## 3. Module-level Mock — Hoisting 주의

`vi.mock()`는 spec 상단에서 hoisting됩니다. 순서 의존이 있을 때 `vi.unmock()` 또는 `vi.doMock()` (no hoisting) 사용을 고려하세요.

## 4. DOM 테스트 Cleanup

jsdom 기반 spec에서 DOM mutation은 spec 간 leak됩니다. `afterEach`에 cleanup 강제:

\`\`\`ts
afterEach(() => {
  document.body.innerHTML = '';
  localStorage.clear();
});
\`\`\`

## 5. N=5 연속 Pass DoD

신규/수정 spec은 5회 연속 pass 확인을 권장합니다:

\`\`\`bash
for i in {1..5}; do npx vitest run tests/unit/your-spec.ts || break; done
\`\`\`

전체 테스트 안정성 확인:

\`\`\`bash

\`\`\`

## 6. localStorage 모킹

`Storage.prototype.setItem`을 spy해서 throw 시뮬:

\`\`\`ts
vi.spyOn(Storage.prototype, 'setItem').mockImplementation(() => {
  throw new DOMException('quota', 'QuotaExceededError');
});
\`\`\`

`mockImplementationOnce`는 1회만, `mockImplementation`은 매번 throw. 후자 사용 시 spec 끝에 `vi.restoreAllMocks()` 필수.
```
