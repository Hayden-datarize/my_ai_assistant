### 1.4 리팩토링 패턴 권고 (C7 옵션 A — Codex 결정용)

**핵심 제약**: archive의 `dg:insights:added/removed/updated`는 home에서 dispatch — **archive 탭 미진입 시에도 listen 필요**. 단순 lazy mount 시 누락.

**옵션 A — 분리 (register vs mount)**:
- `register*Listeners()` 신설 — `on()` / `addEventListener` 등록만, boot 시점 호출 (cross-tab 의존성 보존)
- `mount*Handlers()` — DOM-touching init (button wiring, 초기 render), tab-changed 시점 lazy
- `main.ts`: boot 시점 4 handler 모두 `register*Listeners()` 호출 + `home`만 `mount*Handlers()` eager / 나머지는 nav.ts switchTab 시점 first-mount

**옵션 B — listener를 별도 module로 추출**:
- `src/ui/listeners/{home,archive,stats,missions}-listeners.ts` 신설
- handlers 본문은 그대로, listener만 분리
- `main.ts`에서 listeners 모듈만 boot 시점 import + register
- handlers는 nav.ts에서 lazy

**옵션 C — 격하 / 부분 적용**:
- archive listener만 분리 (`dg:insights:*` 의존성 가장 명확)
- home/stats/missions는 그대로

**Codex 권고**: 옵션 A가 가장 컨벤션 친화 (기존 `mount*Handlers` 이름 보존 + 분리). 옵션 B는 file 증식.

## §2. C4-sidebar — Drawer Close 동기 보호

### 2.1 현재 코드 (`src/ui/sidebar.ts:46-53`)

```typescript
btn.addEventListener('click', () => {
  // v3.29 T3 review fix (I2): silent dynamic-import failure 차단 — chunk
  // load fail 시 console.warn으로 진단 가능화 (post-deploy stale SW 등).
  switchTab(t.id).catch((err) => {
    console.warn('[sidebar] switchTab failed', t.id, err);
  });
  close();
});
```

### 2.2 문제

`switchTab()`은 dynamic import (5+ second chunk load 가능) 비동기. `close()`가 동기 호출이므로 drawer는 즉시 닫힘 — UX OK. **단순 async/await 마이그 시**:

```typescript
btn.addEventListener('click', async () => {
  try {
    await switchTab(t.id);   // ← chunk load 동안 await blocks
  } catch (err) {
    console.warn('[sidebar] switchTab failed', t.id, err);
  }
  close();  // ← chunk load 완료 후 drawer 닫힘 — "stuck" UX
});
```

### 2.3 권고 패턴

```typescript
btn.addEventListener('click', () => {
  close();   // ← 동기 즉시 close (현재와 동일)
  void switchTab(t.id).catch((err) => {
    console.warn('[sidebar] switchTab failed', t.id, err);
  });
});
```

또는 `try/finally`:

```typescript
btn.addEventListener('click', async () => {
  close();  // 동기 우선
  try {
    await switchTab(t.id);
  } catch (err) {
    console.warn('[sidebar] switchTab failed', t.id, err);
  }
});
```

**핵심**: `close()` 호출이 `await switchTab()` **전**에 와야 UX 유지. async/await는 의미 transparency 향상 가능성은 있지만 `void` + `.catch()` 패턴이 더 명료.

## §3. C5 — Mark Token Consolidation 분석

### 3.1 현재 정의 (`src/styles/tokens.css:10/43/113-114/126-127`)

```css
/* :root (light) */
--accent-light: #FEF3C7;   /* amber-100 */
--mark-bg: #FEF3C7;        /* amber-100 — same as --accent-light (light) */
--mark-fg: var(--text-primary);

/* :root.dark (dark) */
--accent-light: #422006;   /* dark amber 4 */
--mark-bg: #78350F;        /* amber-900 — readable dim, not too bright */
--mark-fg: #FDE68A;        /* amber-200 — high contrast on dark amber */
```

### 3.2 Consolidation 가능성

- **Light variant 동일**: `--mark-bg` = `--accent-light` = `#FEF3C7`
- **Dark variant 다름**: `--accent-light` = `#422006` (거의 검정), `--mark-bg` = `#78350F` (가독성 위해 더 밝음)

→ **semantic 분리 정당**. 통합 시 dark mode `<mark>` 가독성 손실. **v3.30 retro의 P3 backlog 격하 권고 유지**.

### 3.3 WCAG AA 재검증 (T6 carry concern)

- light: `--mark-bg #FEF3C7` (amber-100) + `--mark-fg var(--text-primary) #1E293B` (slate-800)
- contrast ratio 계산: ≈ **10.5:1** (AAA 충분, AA 4.5:1 한참 상회)
- dark: `--mark-bg #78350F` + `--mark-fg #FDE68A` → contrast ≈ **7.2:1** (AAA)

→ **재검증 OK, P3 backlog 종결 가능**.

## §4. T2 P2-2 — Array.isArray 전역 graduate 분석

### 4.1 현재 corruption 위험 호출처 (실측)

| 파일 | 라인 | 호출 |
|---|---|---|
| `src/ui/tabs/archive.ts` | 39 | `loadAnswers()` |
| `src/ui/tabs/stats.ts` | 16 | `loadAnswers().length` |
| `src/ui/modals/welcome-gamification.ts` | 19 | `loadAnswers()` |
| `src/ui/handlers/stats.ts` | 103/104/142/390/418/433 | `loadAnswers()` / `loadBriefings()` × 6 |
| `src/ui/handlers/archive.ts` | 49/55/56/104/111/198/227/244/267/296/317 | `loadAnswers()` / `loadBriefings()` × 11 |

**총 ~20곳**. 모두 직접 `.length` / `.filter` / `.find` 호출.

### 4.2 권고 패턴

**옵션 1 — persistence 진입점에서 guard** (가장 안전):

```typescript
// src/state/persistence.ts
export function loadAnswers(): Answer[] {
  const raw = /* localStorage parse */;
  return Array.isArray(raw) ? raw : [];
}
```

→ 단일 fix point, 호출처 ~20곳 변경 0.

**옵션 2 — 호출처별 guard**:

```typescript
const answers = loadAnswers();
if (!Array.isArray(answers)) return /* fallback */;
```

→ 20곳 수정 필요. DRY violation.

**Codex 권고**: 옵션 1. persistence 모듈이 이미 single source-of-truth이므로 자연스러움.

### 4.3 회귀 spec 권고

- `tests/state/persistence-array-guard.spec.ts` 신설:
  - corrupted storage (string / object / null) → `[]` fallback 보장
  - valid array → 그대로 반환 (idempotent)
